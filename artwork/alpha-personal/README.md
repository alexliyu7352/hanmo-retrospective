## 来源与核验

每张图的完整提示词存放于同名 `.prompt.txt`；原始工具文件路径、尺寸、文件字节数、SHA256、提示词 SHA256 和透明像素统计见 `manifest.json`。隔离副本与工具原件的 SHA256 相同。未使用商业游戏图片作为生成输入，没有程序绘制、裁切、去背或透明度后处理。

生成前查看了本工程 `game/assets/art/f05/city.webp`、`guard.png` 及 `manifest.json`，以温润黄土、墨绿、木褐和手绘轮廓协调色感。逐张检查了生成画面：背景没有 UI、字、人物、网格或范围圈；人物的身体与完整武器均在画内，单独成图。

人物画布四角及主体外部具有 alpha=0。主体 alpha 主要为 252–253，接近不透明；少量边缘为半透明，已保留原始结果。不能仅凭有 alpha 就认定所有尺寸下边缘和轮廓已通过实机检查。

## 主工程接入边界

- 仅把所需资源复制到主工程，并通过 `game/data/presentation.json` 注册；不要在界面另加资源 ID 白名单。此目录未擅自注册新资源。
- 两背景为近似斜俯视绘景，没有权威碰撞、移动成本或浅滩通行信息。场地内容应显式定义边界、障碍、浅滩和接触点，并把可见边缘树石与实际几何对齐；规则不得由背景资源 ID 推断。
- 演武场中部适合基础距离与方向练习；河滩提供不同边界和浅水条件。是否阻挡、是否减速由同一规则数据决定，不能看到水面就由 UI 私自判断。
- 人物是一个朝向的静态立姿，非八方向动画或已完成战斗反馈；目前未生成行走、挥击、受击和倒地帧。需要独立地面锚点和朝向指示；左右翻转只能作表现选择，不能代替真实规则朝向。
- 三人物服装与武器可辨，实际缩小到 90–120 像素后的字号、轮廓、脚点、队伍色、目标圈与遮挡尚待 Godot 运行检查。不得让人物按包含长枪的整幅外框统一缩放而造成长兵人物身体明显偏小。
- 范围、命中、伤害、状态、胜负、退出与保存均由工程真实运行生成，不能从这些素材推定实现或验收完成。

本任务没有调用 CLI/API 后备方式，没有接入主工程，没有运行引擎；主 Agent 负责内容与资源清单接入、场地复用及真实输入和截图复验。
