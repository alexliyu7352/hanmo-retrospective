## 0.2 固定产品方向与不变范围

保留人物身份、自由旅行、城市生活、交游、主命与晋升、多职业、技艺与卡片、修业小游戏、个人战、野战/攻城、动态人物和条件化事件。职业不是互斥技能树，统一天下不是唯一结局。

推荐技术继续为单机2D、Godot与GDScript、Compatibility、Web从工程探针同步验证。没有强制账号、服务器结算、抽卡付费、运行时大模型、多人联机、云存档、跨世代经营或庞大编辑平台。也不把其他项目的Android TV规范搬进本游戏。

| P2 人生与战争扩展 | 治理、高位/君主、攻城、豪侠与水上组织、更多区域与平台 | 复用规则及独立机制明确写出，不计入P1已交付 |

## 0.3 哪些选择本轮已经具体化

时间按半日、交付按完成时刻判期限；交易确认时完成钱货交割、再推进半日；角色和部队占用与权限严格分离；主命允许包干留余，不把经费游戏化空间删掉；价格按逐件边际成本并保留双向价差。

个人战采用同时规划与确定性冲突解析，野战按部队顺序行动；所有战斗只提交一次结果，军需只在世界半日结算点消费。小游戏自动结果可通主线，手动成长奖励最多为正常值120%。

局内状态与全局图鉴分开；长行动、随机流、事件选择与结算标记保存；网页等待IndexedDB事务完成并读回校验才显示保存成功。正式平台兼容与性能只能以构建实测认定。

## 0.4 参数、事实与完成状态

公式与参数是首轮平衡基线，不是已试玩验证的最佳解。历史日期/人物的真实部署需要内容资料审校，本文不把C01等功能槽或原创事件当成史实。Godot和浏览器技术约束在08附有核对来源；未来引擎升级需要重验。

本轮完成的是规则级详细设计、访谈记录、内容规格和文档/算例核验。**没有游戏工程、游戏构建、正式UI原画、80人物史料快照、全部对白、实机测试或部署成果。** 100个T编号是后续验收场景，不是100个已通过的游戏测试。

所有核心系统均有设计落点；但设计不是“永远无需试玩修改”。战斗节奏、市场利润、成长速度和NPC扩张率必须在可玩版本中验证。用户可以整体审阅和修改代拟决策，实施前再把这些规则拆成执行计划，不需要重复同一轮访谈。

# 01｜Superpowers自问自答访谈与决策记录

**日期：2026-09-09。方式：设计者自问自答；不是虚构的用户采访实录。**

用户授权采用自问自答完成详细设计。因此对范围内问题比较候选并选择推荐方案，不逐题打断用户。所有“选”均为本轮代拟设计决策，用户仍可修改；不把它们写成用户亲口同意的原话。

本轮属于新项目系统详细设计。上位目标来自既有总体方案，不修改“人物立志、多人生、跨平台和网页”的方向；实施代码、远端推送与实际发布不在本轮。

## I01｜这轮可以代用户决定到什么程度？

**候选：** A 每题询问用户；B 自问自答形成可评审决策；C 同时直接写游戏。

**自答与决策：** 选B。用户已授权自问自答完成详细设计。 范围内选出推荐解并写理由；授权不等于用户逐条确认参数，也不等于授权部署或游戏实施。

**落点与验证：** 文件/章节 全部；T100。

## I02｜应先把P1做成极简按钮游戏，还是保住完整玩法结构？

**候选：** A 删修业/战斗以换小体量；B 减地图和内容但保核心；C 第一版塞满全国八职业。

**自答与决策：** 选B，保留既定P1预算和完整后续目标。 A偏离参照玩法，C使每条路线过浅；后期路线规则仍在07写明，不假装已可玩。

**落点与验证：** 文件/章节 00、07、09；T85、T86、T95。

## I03｜世界用真实时间、日结算还是半日？

**候选：** A 实时；B 一日；C 半日行动驱动。

**自答与决策：** 选C。菜单阅读不走时间，行动消耗半日。 保留旅行与日程取舍，不加入现实倒计时；统一由02时钟推进。

**落点与验证：** 文件/章节 02；T01、T02。

## I04｜跨平台是同一规则还是网页另写一套？

**候选：** A Godot客户端＋另一网页逻辑；B 一个Godot/GDScript核心；C 先桌面最后移植。

**自答与决策：** 选B，Linux/Web从工程探针开始同时验证。 不让存档和规则长期分叉；具体引擎构建在实际导出探针后锁定。

**落点与验证：** 文件/章节 08；T73、T81。

## I05｜任务到城就算按期，还是交付完成才算？

**候选：** A 到城；B 点交付按钮；C 交付行动完成。

**自答与决策：** 选C，finish_tick不晚于deadline即按期。 到达、会面、交付有不同时间成本；截止边界先应用有效完成再检查逾期。

**落点与验证：** 文件/章节 02、04；T03、T34。

## I06｜所有行动统一在最后生效，还是明确分开始与结束？

**候选：** A 全部最后生效；B 全部立刻生效；C 按动作规定起始/完成效果。

**自答与决策：** 选C。交易先钱货交换再消耗半日，交付完成时判断期限。 具体差异进入合同，不由UI临时决定；保存必须记录起始效果已执行。

**落点与验证：** 文件/章节 02、04；T05、T88。

## I07｜查看预测结果会不会改变随机数？

**候选：** A 预览也掷骰；B 预览无副作用，提交才抽；C 全游戏取消随机。

**自答与决策：** 选B。装饰随机与玩法随机分开。 保留遭遇与命中不确定性，但阅读行为不改变世界未来。

**落点与验证：** 文件/章节 02、08；T01、T74。

## I08｜旅行中途取消能否回到出发前？

**候选：** A 全额撤销；B 不可取消；C 保留已走进度，在安全边界处理返回。

**自答与决策：** 选C。只释放未执行计划。 有代价而非锁死；破产滞留有耗时恢复路径，不免费瞬移。

**落点与验证：** 文件/章节 02；T04、T07。

## I09｜地图先做精确全国地理还是有意义区域交通？

**候选：** A 全国大量空点；B 区域拓扑先形成选择，再核验历史映射；C 单线闯关。

**自答与决策：** 选B，12据点、18边，保留替代路线。 功能拓扑不是正式190年行政图；发布前必须完成历史地理资料。

**落点与验证：** 文件/章节 02、09；T10、T97。

## I10｜人物能否同日出征、开店、教书？

**候选：** A 全部后台同时做；B 一个人只能一项主要行动；C 除职业外全禁。

**自答与决策：** 选B，店员与代教可以实际接班。 限制人物本人时间与地点，而不是禁掉兼修；任职与行动占用分离。

**落点与验证：** 文件/章节 02、07；T06、T66、T67。

## I11｜角色差异靠无限属性成长还是本领与经历？

**候选：** A 所有属性可无限练满；B 有限属性成长＋技能经验＋经历；C 属性全固定。

**自答与决策：** 选B，P1每属性永久成长最多5。 保留开局特点，训练重点放技能；标准自建统一预算。

**落点与验证：** 文件/章节 03；T11、T12。

## I12｜职业应该是互斥技能树吗？

**候选：** A 职业外技能禁用；B 任职职责排他、技艺可以兼修；C 可同时任职敌对组织。

**自答与决策：** 选B。主要任职只占一个槽。 避免武将不能学医、辞官一切清零，也避免同人同时接受冲突指挥权。

**落点与验证：** 文件/章节 03、04、07；T19、T32、T64。

## I13｜关系一个好感值够不够？

**候选：** A 一个值；B 亲近与信任＋事实；C 十多条心理数值。

**自答与决策：** 选B，关系是有方向的边。 足以表达喜欢但不托付、不同立场仍有私交，又避免过度数值化人格。

**落点与验证：** 文件/章节 03；T14、T15。

## I14｜送礼能不能解决所有人际门槛？

**候选：** A 能；B 彻底取消送礼；C 有效果但递减且不覆盖权限。

**自答与决策：** 选C，礼物主要增亲近，信任来自承诺。 保留熟悉的交游活动，不把友谊变成购买军事权限。

**落点与验证：** 文件/章节 03；T14、T15。

## I15｜请求结果随机还是可解释？

**候选：** A 每次打开都掷骰；B 条件/评分＋一次协商；C 达好感即同意。

**自答与决策：** 选B，硬条件先过滤。 玩家能找到改善路径，又不能靠反复点按钮让敌将无条件开城。

**落点与验证：** 文件/章节 03；T15、T56。

## I16｜技能成长按等级卡还是经验？

**候选：** A 每级固定一张卡；B 累计经验派生等级，特殊本领另得；C 只做加点树。

**自答与决策：** 选B，0—4级门槛固定。 技能与卡片不是同一概念；实践、修业、师承各有作用。

**落点与验证：** 文件/章节 03；T12、T18。

## I17｜某个师傅死了会不会堵死主线？

**候选：** A 接受永久堵死；B 自动复活；C 提供合格替代教师/实践考试。

**自答与决策：** 选C，专属剧情可以失效，基础成长仍可达。 不破坏世界事实，也不让自动小游戏或偶然事件锁掉职业。

**落点与验证：** 文件/章节 03、06；T13、T16、T55。

## I18｜小游戏能否跳过？

**候选：** A 必须手动；B 纯动画无影响；C 自动正常结算，手动小幅更好。

**自答与决策：** 选C，养成收益差最多20%。 主线资格不能以实时反应为唯一条件；自动仍考虑角色能力。

**落点与验证：** 文件/章节 03；T17、T89。

## I19｜市场需要完整全国封闭经济吗？

**候选：** A 全人口钱包闭合；B 小型开放经济，有真实资源转移及明确产消；C 固定价无限库存。

**自答与决策：** 选B。 足够支持价差、战争和经营，不先建宏观经济研究项目；不能缺钱时偷偷补AI。

**落点与验证：** 文件/章节 04、06；T21、T52。

## I20｜大额交易按第一件价格算吗？

**候选：** A 单价乘数量；B 每件沿库存刻度定价；C 随机涨价。

**自答与决策：** 选B，双向价差与最高优惠有清楚边界。 买光市场必须付真实边际成本，原样回卖没有系统漏洞利润。

**落点与验证：** 文件/章节 04；T21、T22。

**落点与验证：** 文件/章节 04；T25、T27。

**落点与验证：** 文件/章节 04；T03、T34。

**落点与验证：** 文件/章节 04、06；T28、T62。

## I24｜商铺进钱都算利润吗？

## I25｜卡片是抽牌战斗吗？

# 02｜世界时间、地图与行动详细设计

**基线：总体设计 v0.1 第4—5、16、21章。决策：I03—I10、I32。适用：P1起。**

本文件定义规则，不是已经运行的程序。文中钱、日、容量均为游戏单位；所有数值标为首轮平衡参数，不是历史度量。

## 2.1 全局不变量

| 编号 | 必须始终成立 |
|---|---|
| INV01 | 一个人物只有一个合法位置和一个占用其本人的主要行动。组织任职与行动占用分开。 |
| INV02 | 同一个世界半日只结算一次；界面帧、动画、浏览器可见性不驱动世界时间。 |
| INV03 | 数量与金额为整数且不为负；同一份货物不能同时被两个任务预留。 |
| INV04 | 规则结果先形成，表现层只播放；跳过动画不改变任何结果。 |
| INV05 | 查询和预览不改变世界、随机流、关系或任务进度。 |
| INV06 | 行动、交易、任务结算各有实例ID；重复提交旧实例不重复执行。 |
| INV07 | 跨模块判断使用稳定ID和明确时刻，不用显示名称、真实时钟或节点路径。 |
| INV08 | 读档恢复已提交事实，不再次执行进入场景时的奖励脚本。 |

## 2.2 时间表示与截止口径

`tick`为从剧本起点开始的非负整数；0代表开局日上半日。`day_index = tick div 2`；每月30日，每年360日。时间标签是游戏化历法，不声称对应精确汉历。日期换算只在显示层进行，逻辑不解析中文日期。

任务以**交付行动完成时刻**判定及时性：`delivery_finish_tick <= deadline_tick`为按期。在`t=10`开始一个耗时1半日的交付，于11完成；截止11则按期，截止10则不能称按期。接令和路线预览同时提示“预计交付完成时刻”，不只显示到城时间。

截止检查位于本半日所有正常完成效果之后。于截止边界完成的交付先完成，再检查未完成的任务。任务是否允许逾期部分交付由任务配置决定。过期不自动消失，清算规则见04。

时间可免费查看，不能免费刷收益。相同会面中的问候、打听和请求组成一个会面行动；额外开始一次实质交往才再耗时。免费取消未确认的草案，不产生关系或经验。

## 2.3 权威状态与行动状态机

`WorldState`保存`tick, revision, next_instance_id, actors, locations, routes, organizations, markets, tasks, events, battles, long_actions, rng, history`。`revision`在每次逻辑提交后加1，和时间不是同一概念；零时长的事件选择也能改变revision。

`ActionDraft → Validated → Committed → Running → Completed`。

可选支路：`Draft/Validated → Cancelled`（无代价）；`Running → Suspended → Running`；`Running/Suspended → Aborted`（保留已经实际消耗的资源和时间）；`Running → Failed`（目标失效等结果）。Completed、Aborted、Failed都是终态，不允许同ID重新启动。

| ActionInstance字段 | 类型与规则 |
|---|---|
| id / actor_id / kind | 稳定字符串；kind来自封闭枚举 |
| created_tick / start_tick / expected_finish_tick | 非负整数；预计时刻不是不可变化的承诺 |
| participants | 本次实际参与且被占用的人物ID；服务型市场不锁全城商人 |
| status / remaining_ticks | 上述状态；剩余时间不得为负 |
| start_effects_applied | 布尔，防止恢复时重复扣预付款 |
| reserved_resources | 资源ID、数量、owner与用途；只记录真实预留 |
| progress / pause_reason | 按行动类型定义；不使用任意脚本对象 |
| result_id / completion_applied | 结果引用与终态结算标记 |
| validated_revision | 防止过时预览提交；不作为联网防作弊机制 |

`validate`返回可执行性、原因码、显示费用、耗时和涉及实体版本。`commit`重验；失败必须零副作用。已经接受的行动写入实例并占用人物，只有该动作定义的起始效果立即发生。行动服务是写入入口，UI不能直接加钱或移动人物。

### 起始效果和完成效果的统一口径

短交易在确认后立即交换钱货，再推进半日，交易单据记录确认时刻；买卖行为不会因随后出现的道路消息被撤销。交付任务的数量在开始时预留，**完成时**转交并判定期限。修业在开始时缴费，逐半日获得学习效果；取消后不退已完成部分。旅行逐半日付费与推进，不预扣整段行程。

这些差异写在行动配置，不由各页面自行决定。每个逻辑提交使用临时状态副本；不变量检查通过后替换当前权威状态。P1小世界先使用普通状态副本与局部结果对象，不先建事件溯源数据库。程序异常时丢弃未提交副本，保留最近稳定世界，不能默默吞错误继续算。

### 稳定边界

允许保存：行动已接受且起始效果明确写入后、一个半日完成后、一个事件选择完成后、战斗等待下一轮输入时。保存包含正在进行的行动；加载不能把Committed再当成新动作。结算函数内部和移动动画中途不是保存边界。

## 2.4 一个半日的固定顺序

进入时读取起始快照`S(t)`并生成本轮消费、行动与占用清单。`advance_one_tick`不可重入；本次只能推进`t → t+1`。

| 阶段 | 操作 | 冲突规则 |
|---|---|---|
| T1 | 检查现有行动可继续性；确定本半日参与者、行程和军队口粮 | 只准备，不向UI展示半成品 |
| T2 | 按行动ID顺序推进旅行、工作、学习、NPC已有行动；收集完成效果 | 不启动本半日尚未开始的新长行动 |
| T3 | 应用本轮战术结算、到达、交货、治疗与任务客观进度 | 同一物资冲突先预留者有效；无预留的竞用按行动ID |
| T4 | 消耗本半日事先确定的旅行费用、口粮，更新疲劳、伤病计数 | 一个费用键只能出现一次；军需规则见05 |
| T5 | 令时间到`t+1`；跨日时做市场生产消费、店铺营业和恢复；跨月时做薪给与常规议事 | 已终止组织不付款；单个结算记录明确日期键 |
| T6 | 完成有效任务的奖励清算；再检查逾期、主体灭亡、合同失效 | 截止边界完成优先于逾期 |
| T7 | NPC挑选下一行动；势力在到期节点更新计划 | 新行动最早从`t+1`开始，不偷走本半日 |
| T8 | 检查事件候选与通知，写经历、验证不变量、生成稳定快照 | 重大选择排队；不在半日中途递归打开弹窗 |

T2—T6是一个逻辑事务。遇到需要玩家选择的道路事件，先停在对应真实路段边界，完成本半日其他结算，再展示选择。选择引发的新行动从下一半日开始。日结算或月结算不会因为一次旅行跨了多日而只执行一次。

部队战每完成一轮调用一次上述流程；个人战包含在触发它的行动半日内，轮数不另加世界时间。没有任何战斗动画直接调用时钟。

## 2.5 行动表与取消处理

| 行动 | 时间 | 起始效果 | 完成效果 | 中断 |
|---|---:|---|---|---|
| 实质会面 | 1 | 占用双方；收礼物时转移礼物 | 关系、消息、请求结果 | 普通会面不被半日内新事件打断 |
| 一批交易 | 1 | 一次钱货交换；生成账单 | 技能经验；结束市场占用 | 不撤销已成交账单 |
| 任务交付 | 1 | 预留交付资源、记录报告地点 | 转交、质量、期限、奖励 | 发令主体消失转合法清算 |
| 短工 | 1 | 无押金 | 个人收入80钱、疲劳+8 | 受伤严重也有低强度版本，收入40 |
| 普通休息 | 1 | 支付已展示费用 | 体力+35、疲劳−30 | 可在半日后停止 |
| 修业 | 2—6 | 支付本课程费用 | 每半日经验，最后检查卡片资格 | 未开始半日退款；已提供教学不退 |
| 城际旅行 | 路线计算 | 首段路线、运力和同伴合法性校验 | 每半日行程和费用；最终到达 | 可于边界转向或等待 |
| 野战一轮 | 1 | 冻结参战单位与供给清单 | 本轮损失、任务、世界推进 | 轮内不随意退出；可保存于轮间 |
| 个人战 | 0额外 | 从原行动接管局部交互 | 胜负返回原行动 | 依战斗目标撤离，不重复收费 |

“短工80”不是所有NPC无限被动收入，只有占用人物劳动半日的实际服务；世界经济中记作民间服务收入来源。主要用于恢复基本行动能力，不用复杂市民资产数据库来证明每个铜钱流向。

## 2.6 路网数据与行程

据点定义`id, type, facility_ids, owner_org, map_xy, market_id, garrison_id`。路段定义`id, from, to, base_steps, modes, risk_bp, capacity_limit, blocked_reason, known_at`。全部逻辑路径使用节点和有向边，双向路显式提供反向通行条件。

P1逻辑拓扑采用以下12节点与18条双向连线，**这是功能测试拓扑，不是已审校的190年历史地理名单**。C01—C08为城市，V01/V02为乡里，F01为渡口，M01为营寨。正式地名、人物快照是内容制作交付，不在系统设计中编造历史事实。

| 边 | 标准步行半日数 | 用途 |
|---|---:|---|
| C01—C02 | 2 | 常用商道 |
| C02—C03 | 2 | 城际主路 |
| C03—C04 | 3 | 长途路段 |
| C01—V01 | 1 | 新手恢复地点 |
| V01—C03 | 4 | 主路受阻的替代路径 |
| C02—M01 | 1 | 官军任务 |
| M01—C04 | 3 | 较短但高风险路径 |
| C04—F01 | 2 | 水陆衔接 |
| F01—C05 | 2 | 渡运费用节点 |
| C05—C06 | 2 | 交易循环 |
| C06—C07 | 3 | 区域远行 |
| C07—C08 | 2 | 城际主路 |
| C08—C05 | 4 | 第二商旅环 |
| C06—V02 | 1 | 地方支线 |
| V02—C08 | 3 | 备用道路 |

| C04—C07 | 6 | 战争改道 |

路线用Dijkstra求“当前已知的最短时耗”；另提供低风险候选，计算权重`time + floor(risk_bp/500)`，仅作选择建议，不伪装真实概率最优。相同权重按路段ID字典序固定。允许玩家手选途经点。

旅行进度使用整数`progress_points`。道路长度`base_steps×100`；步行每半日100点、轻装骑乘150点、车队100点；雨天乘80%，运输熟练按第03章增益，最终至少1点。没有“半个tick到达并多做一件事”，到达在边界发生，溢出进度不跨下一条边。距离与速度修正是平衡参数。

同伴共享队伍位置，队伍速度取最慢的成员/运输方式；轻骑不能一边跑得快一边让步行货车瞬移跟随。载重按真实携带及任务货物计算。超载时禁止启程，提供分批、租车、存仓；途中运力损失则暂停，允许存放、托运或明确放弃货物。

每半日基本行旅费：个人8钱，车队附加4钱，护卫每人6钱。道路额外费用只在进入指定边时收一次，路段实例记录。费用只能使用合同允许的钱包。余额不足时不负债穿越；在边界触发“滞留”：就地求助送回最近已过据点，耗2半日、货物最多损失非任务个人货物10%，无个人货物则无货损。返回不瞬移免费重置，可在该据点做短工。

风险在进入每个路段时抽一次`event`随机流，保存`encounter_resolved`；停留与读档不重抽同一段。普通/危险道路基线300/1200基点；护卫与最新情报最多减少500基点，最低100基点。风险是遭遇概率，不直接等于死亡概率。选择绕行使用真实替代路线，无替代路才等待或返回。

人物位置采用互斥联合类型：`Settlement(id)`、`OnRoute(edge_id, progress, origin)`、`Battle(id)`、`Captive(holder, settlement)`、`Dead(last_place)`。不同时存两个可独立修改的“当前位置”。地图标记由此派生。

## 2.7 人物消息与访问

玩家知识条目保存`subject_id, last_known_place, observed_tick, source, confidence`。已知消息不会每次开图更新为真实世界。亲自见到、可靠报告、旅人传闻分别标为确认/报告/传闻；过期仍展示日期，不直接删除。

宅邸访问预览免费告诉玩家公开可知的可用性：在家、受命在外、未知。实际打听消耗1半日，获得合法消息并可能建立联系。人物被占用时不能双重开始师承；可约下一个可用时段，超过约期显示原因，不无声消失。

## 2.8 规则契约与错误

| 契约 | 输入 | 输出 | 主要错误 |
|---|---|---|---|
| 预览行动 | actor_id、kind、参数、当前revision | 可行性、时间、成本、原因 | 未知主体、不可达、权限不足 |
| 提交行动 | draft、预览版本、request_id | ActionInstance、起始结果 | 版本过时、人物占用、资源不足 |
| 推进半日 | 当前WorldState、驱动原因 | 新状态、结果、通知 | 重入、内部不变量失败 |
| 暂停/取消 | action_id、具体选择 | 已消耗与释放资源 | 不可取消阶段、实例已结束 |
| 查看路线 | 起终点、模式、知识 | 路线候选及消息时间 | 无已知可达路线 |

开发时具名类、函数和方法都要写明职责、输入输出和重要副作用；不能以“函数名很清楚”替代维护说明。这里只规定可观察契约，不为凑详细程度编造数百个内部函数。

## 2.9 本模块验收

T01：阅读20个面板，tick、revision、随机状态不变。T02：连续旅行5半日，恰结算5次时钟，跨日消费次数正确。T03：截止11、交付完成11，成功；完成12按逾期规则。T04：路上返回不清零原耗时和费用。T05：加载Committed交易不再扣款。T06：同一人物已在行军，不能同时拜师。T07：道路遇险读档不重抽。T08：野战一轮恰为1半日，个人战10轮不额外变成5天。T09：NPC新任务最早下一半日有进度。T10：12节点全连通且任一主商道路段受阻仍有可解释的替代/等待路线。

# 03｜人物、关系、成长、卡片与小游戏详细设计

**基线：总体设计第6—7、11—14、18章。决策：I11—I18、I25—I27。**

## 3.1 人物结构与属性

人物定义与局内状态分离。定义包含稳定ID、显示文本键、历史/原创标签、头像资源、初始属性、性格和剧本出处；局内状态保存属性成长、技能经验、体力疲劳、位置、职务、钱包/物品、关系、行动、卡片及经历。改名不改变ID。历史标签需要出处字段，原创角色不能包装成真实人物。

五属性为统率、武力、智谋、政务、魅力，基础1—100。P1不通过普通重复修业无限增加属性；每属性一生最多+5点永久成长，来自五个不同的对应里程碑，每个+1。修业主要增长技艺。装备和伤病的临时修正单列，实际值`clamp(基础+成长+临时,1,110)`，不改写基础。

标准自建人物：五项从40开始，额外100点，最终总和300；单项20—85，降低属性按1:1返还点数；10项技能共4级初始点，单项不超过2。选择专长不能再免费叠加点数。P1自建年龄18—60，生日只影响年龄与叙事；出生年份由剧本锚点和年龄换算，不制造未核验历史人物。

自由创建允许单机自行调参，记录`creation_mode=free`，不禁用主要玩法，不加入服务器验证。跨局图鉴区分自由解锁标记，但不处罚玩家。

## 3.2 技能等级与经验

累计经验门槛：0级0、1级100、2级300、3级650、4级1200。等级按最高已达到门槛派生，经验上限1200；不另外维护可与经验矛盾的可写等级。一次奖励超过门槛可连续升级；同一奖励实例只生效一次。

| P1技能 | 属性辅助 | 起作用的地方 |
|---|---|---|
| 步战 | 统率 | 步兵攻防与训练 |
| 骑战 | 统率 | 骑兵机动、战法资格 |
| 弓弩 | 武力/统率按战斗类型 | 个人弓术、弓弩兵训练 |
| 武艺 | 武力 | 个人战、切磋、秘技 |
| 兵法 | 智谋 | 指挥资源、阵法、军阵小游戏 |
| 辩说 | 智谋 | 礼议与交涉论据 |
| 交涉 | 魅力 | 请求、议价与委托条件 |
| 礼学 | 政务 | 举荐、正式拜访、礼议 |
| 商术 | 政务 | 价格理解、商铺经营、订单 |
| 运输 | 智谋 | 行旅速度、容量组织、货损控制 |

每半日定向修业基础20经验。先计算`normal_xp=floor(base×condition_bp/10000)`，再计算`xp=floor(normal_xp×performance_bp/10000)`；condition_bp为6000—10000，取疲劳效率和伤势效率的较小值，伤势0/1/2/3对应10000/9000/7500/6000；performance_bp正常10000、手动优秀最多12000。先取正常结果再乘加成，确保整数取整之后手动收益仍不超过正常的120%。实践奖励由模板给10—40经验，按任务实际贡献分配到最多两项技能，不能十项都涨。

普通定向课程费用每半日`20+10×目标技能级`钱，目标级为下一技能等级，课程2—6半日；试炼费按任务另列，不重复收课程费。师承要求教师技能严格高于学员，双方在同一据点且可用；普通技能至2级可在公共设施学习，3—4级需要合格教师或明确实践考核。P1每项技能必须至少有一条不依赖唯一会死亡NPC的成长途径：设施至2级，加两名候选教师或技能实践考核至4级。自动小游戏不阻断这些途径。

运输等级每级提高行旅进度2%，最多8%；随身基础运力20，运输每级+2；车队另加80而非乘算所有货物。提升运力改变组织效率，是游戏抽象。

## 3.3 体力、疲劳与伤病

体力0—100，疲劳0—100，伤势等级0—3；疾病为具名状态，含严重度与剩余疗程，不输出现实诊断或药方。体力=0通常表示失去继续个人战能力，不自动死亡。

疲劳0—39效率100%，40—69为90%，70—89为75%，90—100为60%。战斗数值在开战快照读取修正；不因播放速度改变疲劳。旅行每半日疲劳+5，短工+8，修业+6；休息体力+35、疲劳−30。普通休息费用20，野外休息免费但恢复分别+15/−15且处于路段风险规则内，不可重复抽遇险。

轻伤需要累计4个恢复半日，中伤8、重伤12；合格医馆治疗每半日完成2个恢复点，安全住宿每半日1点。重伤禁止主动发起切磋和重体力训练，但保留阅读、轻工、求助和治疗。伤势影响实际体力上限为90/75/50，不永久扣基础属性。

没钱且严重受伤时，乡里救助行动耗2半日、免费用、给予4恢复点，14日内同人一次；其后轻工能恢复路费。救助不会复制可交易药品。玩家不会因缺钱无法做工、又因无法做工永远不能恢复。

P1默认不以自然疾病随机杀死玩家。完整寿命规则见07，死亡仅在已明确告知的终局或高风险事件生效。

## 3.4 关系结构与单向性

`RelationEdge(from,to)`保存亲近0—100、信任0—100、事实标签、最后互动tick、礼物类别计数、已兑现承诺。A信任B与B信任A不必相等；同一共同事件可以明确修改两个方向，不能默认为自动对称。

事实：同僚、师徒、恩义、仇怨、结义、婚姻。师徒和婚姻等互相引用的事实通过一次原子操作建立；被俘不自动删除关系，转仕不把私人好感清零。公开声望0—1000与恶名0—1000分开。

| 行为 | 初始结果 | 防机械刷取 |
|---|---|---|
| 有内容的会面 | 亲近+2；首次共同话题额外+2 | 同一对象同日只计一次基础会面收益 |
| 兑现普通承诺 | 信任+4、亲近+1 | 依任务/承诺实例一次结算 |
| 重要共患难 | 信任+8、亲近+6 | 依事件实例，不依打开对话次数 |
| 普通合意礼物 | 亲近+6 | 同类礼物30日内第2件50%、第3件25%、之后0 |
| 珍贵且合意礼物 | 亲近+10 | 信任最多+1，同样递减；不越过职责硬条件 |
| 有因延期且获准 | 信任0或−1 | 与无故失约区别 |
| 侵占公物/恶意毁约 | 信任−15、对应组织恶名+10 | 只影响相关主体及实际传播范围 |

礼物转移先确认，价值来自真实物品；对方不收则不消耗礼物，但若已经开始实质会面仍消耗该会面时间。信任不通过普通问候增长。

### 请求判定

先检查硬条件：主体存活、能接触、本人可用、技能/身份资格、权限与不可违反的承诺。硬条件失败不抽随机。可协商请求再计算：

`score = floor(亲近×20/100)+floor(信任×35/100)+floor(辅助属性×15/100)+5×相关技能+利益修正(−20…20)−请求难度(0…60)`。

score≥40直接接受，≤10拒绝；中间允许一次礼议协商，最终成绩转换为−5…+5分后再与门槛30比较。P1不再额外掷随机骰决定对方突然反悔。这样拒绝原因可以解释，关系和能力真实有效。相同处境被拒后重新打开不改变判断；硬条件或关系发生实质变化才重新评估。

举荐采用礼学/魅力，授艺采用对应技能与信任，借用物资采用交涉及信任。借用只能授予借出者有权支配的资源。友好不能覆盖敌对军事禁令；一次议价优胜不能替无权者签订势力同盟。

## 3.5 卡片数据与跨局语义

`CardDef`字段：id、category、name_key、description_key、prerequisites、acquire_condition、effect_kind、effect_params、hint_key、icon_id、repeat_policy。效果从封闭枚举选择：解锁人物、解锁行动、修正单个参数、赋予秘技/战法、称号资格、记录见闻。文本不能执行脚本。

局内`learned_card_ids`赋予实际能力；全局`discovered_card_ids`记录曾获得；人物卡另维护`unlocked_actor_ids`。新周目不复制钱财、装备或本领。重复获得仅更新发现记录，不重复叠加被动效果或奖励。

## 3.6 小游戏统一协议

`ChallengeSpec(id,type,difficulty,actor_snapshot,context,seed,state)`。进入前确认手动或自动；这时才生成并保存题面种子。结果只含0—100成绩与选项记录，不直接加钱或经验，由所属行动结算。中途退出按自动基础成绩结算，不能反复重开更换题面；允许读旧档自由重玩，不做联网反作弊。

自动基础成绩：`clamp(45 + 8×相关技能 + floor(辅助属性/10) − 8×难度级(0—3), 30, 90)`。手动成绩取原始操作成绩与“自动成绩−10”的较大值，保证动作障碍不造成巨大惩罚；教学支持不限时、步骤提示。经验乘数`10000 + max(0,score−auto_score)×200`，封顶12000。手动优势最多20%，不适用于凭空提高交付数量或越权请求。

### 议价筹算

固定3轮，无现实时间倒计时。界面给出目标预算、数量和对方可接受条件。每轮从数量调整、分批、付款条件三个公开提议中选一；不包含信用借款系统的P1只允许“现款、小量、合并购买”。提议适配当前供需+20分、满足对方已知条件+10、不相关0；基础20分，封顶100。自动使用人物成绩。折扣`min(800, 相关关系优惠 + floor(score×5))`基点，所有来源合计不超过800。确定结果生成正式报价，之后不能靠反复议价叠加同一交易折扣。

### 军阵操练

5×4演练板，3个编组，4个地形任务。玩家每步选择编组与目标格，一共4步，可撤销未确认步骤。保护粮点、占住通路、远程有前卫、骑兵不入劣地各25分。题面由有限已校验模板生成，始终存在合法解；不由随机地图生成不可解题。成绩调整训练效果与经验，训练人数仍来自真实获授权士卒。

### 礼议应答

3个话题节点，每节点显示对象已知立场和3条论据。根据当前话题利益、先前回应一致性评分：基础25，三轮各最多25，封顶100。正确与否依游戏已提供的信息，不要求玩家背历史。结果可将请求score调整`clamp(floor((成绩−60)/8),−5,5)`。某个硬性政治禁令不能靠100分越过。

# 04｜主命、经济、仕途与商铺详细设计

**基线：总体设计第8—10章；关联02时间、03人物、05战斗。决策：I19—I24、I28—I31。**

## 4.1 所有权、使用权与预留

钱包实体`Wallet(id,owner_kind,owner_id,balance)`；owner_kind限个人、组织、商铺、任务托管、民间经济池。物品批次`ItemLot(id,item_id,quantity,owner,container_id,reserved_by)`；同种同归属且无不同预留的物品可合并，不能混淆公粮与私粮。

权限分开判断：属于谁、由谁携带、谁可使用、是否已被预留。玩家可以携带属于组织的粮食，但不能因此默认在个人市场卖出。任务预算只授权合同列出的货品、路费和服务；没有跨货币复杂财务系统。

每次转移同时扣一方加另一方，不能“先加玩家钱再等动画扣公库”。生产、民间消费、税收、工资等合法来源/去向有分类记录，但不模拟全国每个农民的钱包；经济采用开放资源模型，不冒充完全闭合经济。

批量交易行最多500单位，批量总价与运力仍须校验；大量军需通过仓储/运输任务完成。一个容器内每批货物的预留总量不得超过数量；合同间转让预留需先解除或明确改约。

## 4.2 市场报价公式

城市每商品记录`stock, target_stock, capacity, base_price, elasticity_bp, event_bp, market_revision`。另有市场现金余额。初始`target_stock=100, capacity=300, elasticity_bp=5000, event_bp=0`，可逐城市覆盖。8个P1商品如下，均为虚构游戏计价，不作历史换算。

| 商品 | 基价 | 单位载重 | 日生产/日民用消耗基线 |
|---|---:|---:|---:|
| 粮 | 40 | 1 | 12/10 |
| 布 | 120 | 2 | 5/4 |
| 木材 | 60 | 2 | 6/5 |
| 铁料 | 100 | 3 | 4/3 |
| 盐 | 80 | 1 | 5/4 |
| 药材 | 150 | 1 | 3/2 |
| 马具 | 300 | 5 | 1/1 |
| 普通兵器 | 500 | 5 | 1/1 |

单个库存刻度s对应基础边际价：

`M(s) = clamp(B + floor(B×E×(T−s)/(10000×T)) + floor(B×W/10000), ceil(B/2), 2×B)`。

B基价、T目标库存、E弹性基点、W事件基点。负数除法使用向负无穷取整，不使用语言默认截断。该定义是本项目算法；未声称适用于真实金融市场。

从库存S买q单位，第i件（i从0开始）价格：`ask_i = ceil(M(S−i−1)×(11500−d)/10000)`。

向库存S卖q单位，第i件价格：`bid_i = floor(M(S+i)×(8500+b)/10000)`。

d、b均为0—800基点，包含关系、小游戏与特殊优惠的总和。全价为逐件求和，不能用第一件报价乘数量。立即买卖逆序对应同一组库存刻度，最低买价系数10700仍大于最高卖价9300，因此同城原样回卖不能因库存恢复产生无中生有利润。跨日事件与跨城价差可以真实获利。

卖出还检查市场现金和仓容，不能市场明明没钱仍付全款。库存不足、钱不够、容量不够都给出最大可成交数量；不静默减少数量后假装完成委托。

### 报价提交与时效

预览报价包含商品、数量、买卖方向、逐件总价、两边钱包、载重、折扣来源、市场revision、有效tick与关联行动ID。**有效期是当前游戏tick且市场版本未变化**，不是玩家阅读界面30秒就涨价。

确认时重验实际库存、钱和所有权，原子转移钱货并递增市场revision，生成唯一账单，然后让人物消耗1半日。点击两次相同request_id返回同一账单，不再扣钱；旧revision的新请求要求重新确认。价格预览和小游戏不在市场端预扣库存，P1单机不需要复杂挂单撮合系统。

多商品同一批交易先检查所有行；全部可成交才一次提交，任一行失败则全单不执行。买卖同商品在一批中互斥，避免难理解的自我抵消。

### 日更新

日末先加入生产`min(capacity−stock,production)`，再从可用库存消耗`min(stock,demand)`。民用消耗按照当前中间价给市场增加民间消费收入，记录开放经济来源；战争征调则必须扣组织钱包或按公开征发事件处理，不重复把一批粮既卖给民间又交给军队。补货不瞬间恢复至目标库存。事件加价有起止tick，只在日更新或事件明示时改变W。

## 4.3 购粮算例：同一任务的两种正常解法

任务需10粮，包干预算650，固定成功报酬80；本地B=40，外城B=25，库存/目标均100、E=5000。无议价折扣。外城往返各2半日，带车队每半日12钱；出发前运力足够。为单独验算报价，两地本测试粮产/民耗都设10且关闭NPC交易和事件，故旅行期间未购入的市场库存保持100；正式剧本仍执行动态市场，不保证此固定金额。

| 路线 | 操作序列 | 数量与费用口径 |
|---|---|---|
| 本地采购 | 买粮1半日→交付1半日 | 逐件购入总价依公式；无城际路费；2半日完成 |
| 外城采购 | 去程2→买粮1→回程2→交付1 | 外城逐件购入总价＋48路费；6半日完成 |

两路线都可能合格，前者节省时间，后者留用结余更多。本例逐件价格、总成本、结余和报酬由交付包中的规则样例核算报告列出，不把未经计算的金额手抄成规则。

任务开始前显示期限。若截止距离只有4半日，外城方案不应显示“可按时交付”；更优秀的战斗能力也不能让不够的路程自动消失。

## 4.4 主命实体与状态机

`TaskDef`：id、模板、可用组织/地点/人物槽、接受条件、目标列表、期限半日数、资金模式、预算、基础报酬、基础功绩、可部分完成、延期条款、失败清算、事件关联。

`TaskInstance`：id、def_id、issuer_entity、assignee、issued_tick、accepted_tick、deadline_tick、状态、实际预算钱包、目标进度、货物预留、extension_count、objective_completed_tick、settlement_id、结果质量、参与者映射。

状态：`Offered → Active → ReadyToReport → SettledSuccess/SettledPartial`。Active/ReadyToReport可以进入Overdue或Cancelled；逾期/取消仍须`Liquidating → SettledFailure/SettledCancelled`清算公款与货物。发令主体已消失进入Orphaned再走相同清算，不永远占一个任务槽。

ReadyToReport只代表客观条件已满足，不代表已收到奖励。玩家未报告时可以继续生活；期限仍按合同执行。目标完成后离开地点不自动把已完成事实清除；需要“交付实物”的目标另检查交付时所持数量。

### 目标类型

| 类型 | 必要字段 | 进度来源 |
|---|---|---|
| deliver_item | item_id、count、receiver、allow_partial | 已授权实物转移账单 |
| deliver_message | letter_id、receiver | 成功会面事件；不读取背包外的虚构信件 |
| visit/report | 地点列表、所需证据类型 | 真实到访与报告 |
| recruit | 来源据点、人数、费用上限 | 志愿兵员池转移到获授权部队 |
| train | unit_id、训练增量/达标值 | 合法操练结果 |
| negotiate | 对象、条款类型、底线 | 真实请求/协商结果 |
| escort | 护送目标、起终点、最大损失 | 同行状态与到达/战斗结果 |
| recover | 指定货物/债务事实、允许方式 | 交涉或已定义遭遇结果 |

多个必须目标逻辑为AND；配置可定义可替代目标组OR，但不用任意嵌套脚本。进度由领域事实驱动，UI不能直接调用“任务完成”。同一账单不能向两个排他的交货目标计量。

## 4.5 奖励与资金清算

成功质量基线100；明确的超额指标最多给20%额外功绩，但不能多生出合同没有规定的钱。按期完成固定报酬全额；可接受部分交付阈值默认50%，报酬`floor(base_reward×完成比例)`，功绩再乘50%。逾期最多允许2半日补交时，报酬与功绩再乘50%；超过则失败清算。不同模板可禁止部分完成，如送信、护卫对象生还。

| 模式 | 接令 | 成功 | 失败/取消 |
|---|---|---|---|
| 包干 | 预算从组织转任务钱包 | 先完成目标；剩余预算全归个人；固定报酬按合同从组织支出 | 返还未花预算及未交任务物品；合法且已发生的行旅费用不虚构追回；不享结余 |
| 实报 | 预算托管，支出限白名单 | 剩余预算返组织；个人只有报酬 | 同样回收余额和公物；按原因给评价 |
| 自营 | 不领取公款 | 货物收益属于自己的钱包/店铺 | 自担风险，除明确违约不扣公职功绩 |

个人愿意垫款时，确认上限后建立`personal_advance`，按合同先归还垫款再处理结余；没有事先授权不自动抽干个人钱包。合同预算不足给“申请补款/自愿垫付/改约/放弃”，不能使余额变负。

公物侵占只在玩家明确选择的行为后生效：转移所有权、创建损失记录、关闭相应完成路径并计算失信。普通界面误操作不是默认犯罪。P1不加司法审计、联网防盗与复杂债务系统。

发令人物死亡但组织存在，由组织合法继任者接管；组织也灭亡则清算至其资产接管方。无人接管的任务钱包和实物转为`unclaimed`保管，不直接赠予玩家；经过30日无接管并经明确事件可以解除保管。人物可继续在野，不被永久锁在旧合同。

结算使用唯一`settlement_id`，同一事务记录结果、货物转移、预算归还、报酬、功绩、关系和卡片。载入已有settlement时只展示回顾。领取动画被跳过不影响结果。

## 4.7 仕途与议事

P1职位代码`unaffiliated, junior, team_leader`。后续`city_head, regional_head, ruler`已定义但不出现在P1可操作职位菜单。正式官号由剧本映射，不声称一套代码就是汉代统一官制。

入仕可从公开招募或举荐进入。公开招募要求完成一项地方事务、目标组织恶名<30，并通过对应基础能力考核；举荐要求推荐者信任≥35且有引荐资格。不能因某唯一推荐人死亡彻底断路。

领队资格：功绩≥300、组织评价≥40、至少完成3种任务类型，其中至少一次训练/运输/护送；兵法或运输≥1，统率≥40。通过一个独立执行考核后获得授权。文职人物可完成补给领队考核，不强制赢个人单挑。岗位有空缺则正式任命；暂时无空缺提供真实临时领队任务，完成可得“具备领队资格”的阶段回顾，但不凭空挤掉现有部将。

组织评价0—100，不与所有上级私交混为一谈；普通合格主命+3、重要成功+5、无故失败−5，合法延期−1，出差豁免不扣。功绩和资格页面显示已达标与未满足类别。

常规议事在每月首日上半日启动，通知提前至少6半日；在外执行已批准任务的成员豁免到场。议事耗1半日，依次汇报旧任务、说明目标、派发/请领新任务。紧急召集必须附召集缘由与到达窗口；不能强迫玩家瞬移回城。

辞职先显示未结任务、公物与后果：办清交接即解除任职；技能、私产、人际边保留。恶意离职走对应违约清算，不一律成为所有势力追杀目标。主要任职只能1份，商铺持有与技艺不等于第二份主要任职，但实际远程经营需可用店员。

## 4.8 首间商铺

开设条件：至少3个不同客户履约、商术≥2、个人资产可支付900钱开设费与300钱初始店金、当地无通缉、合法铺位存在。标准每座P1商业城市至少1个可用铺位，不能全被NPC永久抢光；铺位属于公开市场供给，不是完成条件后无因突然出现建筑。

店铺状态`Preparing → Open → Suspended → Closed`。成立时资金从个人钱包分离进入店铺钱包；解散时先清算租金、已有订单，再返还私有库存和余额，不额外生成出售价值。店铺库容200载重单位，P1至多1店、1名负责营业的店员，不建设无限商队。

本店每日先支付应付日费：月租60按每日2钱，店员月报酬90按每日3钱；钱不足则Suspended，停止接新订单，现有订单可由本人处理。不会产生无限负债。玩家可存款、补货、调整加价率、亲自营业、委任合法雇员。

初期零售统一依当地市场需求，每日最多出售3单位。零售标价`floor(当地中间价×(10000+markup)/10000)`，markup选0/500/1000；高加价会使日需求上限分别3/2/1。没有货就没有营业收入。客人消费记作民间经济来源，店铺卖货扣实际库存。

成本批次保留实际购入均价与运输分摊；经营净收益=零售/订单收入−对应已售货成本−实际租金/人工/运输。投入个人本金不是营业收入，卖完旧库存不是凭空利润。P1阶段结局要求开业累计10个实际营业日、履行2个店铺订单、累计净收益≥200；达到后可以继续经营，不硬停游戏。

店员不能既随玩家出征又在店里营业。请假、受伤、被俘使店铺暂停或由玩家接班，经营报告标明原因。不在P1扩张为员工招聘平台。

# 05｜个人战、野战与攻城详细设计

**基线：总体设计第14—15章。决策：I33—I39。个人战与野战为P1，攻城为P2。**

本章规定一个可实现的初始规则集，未经过实际试玩调平。程序不能在动画中重掷结果；个人秘技与部队战法使用不同类型。

## 5.1 共用原则

战斗实例保存地图、目标、参战实体、原世界行动引用、回合、阶段、行动队列、随机流状态、已生成结果和结算标记。局部生命/兵力是战斗期间的权威状态，世界对象被占用；战后只按唯一结算ID回写一次。

战斗读档在输入边界继续，或从已确定结果直接完成表现，不会把同一轮伤害计算两次。默认允许手动保存于稳定轮次；不设置必须联网证明的铁人档。

坐标均为整数，原点左上。个人移动使用上下左右四邻接，每步1，禁止穿越墙、敌我占格及地图边界。射线采用“线段与闭合格方形相交”的supercover定义：穿越角点时两侧格都视为被穿越，有任一实墙即阻挡。检查使用整数交叉乘法，不依赖物理引擎浮点碰撞。目标格不自挡，普通单位挡弓箭，枪/剑不穿墙。

## 5.2 个人战实体与回合

场地9×9。P1单挑1对1，护送遭遇最多己方3人对5敌人；护送对象可以占用己方名额且具独立胜负条件。

`DuelUnit`：actor_id、side、格坐标、四向朝向、体力0—100、有效属性、武艺/弓弩级、武器、护具、防御态、气势0—100、状态持续回合、已提交意图。初始气势30，伤者按03的体力上限入场。

| 武器 | 威力 | 移动力 | 速度基值 | 攻击范围 |
|---|---:|---:|---:|---|
| 刀剑 | 8 | 3 | 4 | 切比雪夫距离1，目标在面向前半平面 |
| 长兵 | 12 | 2 | 3 | 距离1—2，同一朝向直线；特殊扫击另有定义 |
| 弓 | 10 | 3 | 2 | 切比雪夫距离2—5，需射界；贴身不能正常射击 |

护具初始防御6，重护具防御10且移动−1，最低移动1。不同品质先用小范围参数变化，不增加随机词条系统。

**一个回合：** 读取起始快照并由AI确定意图 → 玩家规划 → 校验双方合法性 → 防御声明 → 分步移动 → 生成攻击与秘技结果 → 同时应用伤害/状态 → 气势恢复与持续状态 → 目标判定 → 新一轮。

AI在玩家本轮指令提交前生成并保存意图；改变预览不能使AI重新读取玩家打算。若玩家保存于规划期，保存已确定AI意图与随机状态。敌意图可显示模糊姿态，不默认公开全部精确落点。

### 行动类型

移动攻击可选择合法路径、最终朝向及一个目标实体；原地防御可改变朝向但不移动；秘技由卡定义是否可移动；等待恢复气势；撤离需满足实际出口条件。玩家选路径时只是预览，确认才提交。

移动力只限制路径长度，攻击不另外扣移动点。普通攻击或秘技只能选择一次。目标移动后脱离范围则攻击落空，不能自动追踪换目标。普通落空不耗气势；进攻秘技只有到攻击阶段仍具备目标条件才扣预留气势；防御型秘技在准备阶段就消耗，未受攻击也不退款。

## 5.3 同时移动冲突算法

行动速度`initiative=武器速度基值+floor(武力/10)+武艺级`。同值比较回合轮转后的参与者稳定ID排序；回合r将有序名单轮转`r mod 人数`，避免永远同一个ID占优；不抽随机数。

每个移动子步同时读取当前占位，所有仍可移动者提出下一格。先拒绝地形/边界不合法提案；同一目标格只保留优先级最高者，其余人物停在原格并结束本轮移动。然后构建“目标格当前占用者”的依赖关系：

- 链最终通向空格且链上每个占用者都有有效离开提案，整条链同时移动。
- 交换两格、三人及以上循环换位全部拒绝，敌我都一致处理。
- 链通向不移动者或被拒提案者，整条链拒绝。

失败者本轮不再重算路径、不再次尝试抢同格。下一子步只处理已经成功且仍有路径的人物。移动完后才按意图设置朝向；被阻挡者仍可按所选朝向转身，但不能额外补走。

算法应输出逐步轨迹供动画播放，不让动画物体相撞后临时选择谁退让。用例包含：同格竞争、跟随进入空格、两人对穿、三人环换、被静止目标堵住、地图角落。

## 5.4 攻击与伤害

个人弓使用弓弩技能，其他武器使用武艺。本节公式中的武力取`max(1,floor(人物当前武力×condition_bp/10000))`，condition_bp为03定义的疲劳/伤势较小效率，在入战时固定；不永久修改人物基础属性。命中基点：

`hit_bp=clamp(7500+200×(攻击技能−防御武艺)+20×(攻击武力−防御武力)+秘技命中修正,1500,9500)`。

有效攻击按攻击者ID、目标ID顺序从duel随机流取得整数0—9999，值小于hit_bp命中。攻击不合法则不取随机数。预览可显示估计概率，但不消费实际随机流。

`A=12+floor(武力/4)+4×攻击技能+武器威力`；`D=floor(防御武力/8)+护具防御`；基础伤害`max(1,A−D)`。

朝向系数看防御者朝向与其到攻击者的向量点积：正值正面10000、零侧面11000、负值背面12500。防御行动对正面乘7000，其余方向不减；秘技防御独立乘算且整体减伤最低保留30%。最终伤害为基础伤害×位置×防御×秘技倍率，统一以基点乘积后向下取整，最低1；不在每个中间浮点操作时取整。

所有攻击基于移动后的同一个快照生成。该轮已经合法出手的人物即使被同轮攻击打到0体力，其攻击仍生效。因此可以出现同时倒地。不是按数组顺序先扣一个人的血、再取消他的已提交攻击。

DU04反击在本轮首次近身命中后产生一次附加伤害，40%普通基础伤害；不再引发反反击，不触发第二次反击。只对事先声明反击的人生效，即便双方本轮同时倒地。DU05牵制/DU09压弦造成的移动减益从**下一轮**开始，避免先后应用改变已经走完的路线。

气势：防御+10、等待+15、普通命中+5、受到伤害+3，本轮总恢复最多20；发动进攻秘技不因命中再领取普通攻击的+5。上限100。持续状态按定义的剩余“未来有效轮数”递减，新施加的1轮减益不在同轮末立刻过期。

## 5.5 个人战AI与目标

AI候选集限制为合法终点×普通攻击/已学秘技/防御/撤离，不搜索未来玩家输入。评价：完成场景目标+100、预计保护对象减少风险+40、有效伤害+伤害值、预期受伤−伤害值、浪费气势−消耗/4。低体力优先撤离或防御。相同分数按稳定行动编码排序，保留调试原因。

胜负优先级：保护对象死亡/被擒等关键失败 → 敌方消灭/护送到达等成功 → 同时倒地的场景平局规则 → 无法继续/超过回合上限。单挑上限30轮，届时体力百分比高者获评胜，差<10个百分点算平局；护送上限20轮，按保护对象是否到达出口判断，未到达则可以停战/撤离失败，不反复无限刷气势。

撤离需人物到达标记出口，连续一轮未受近战命中；护送撤离必须包含被保护者，不能主角一跑就任务成功。切磋失败不杀人，不丢所有装备；普通遭遇败北最多损失个人现钱10%、轻/中伤与2半日延误。任务货物损失按场景最多20%且必须回到任务清算。被俘属于明确场景结果，不使用普通失败隐含永久软锁。

## 5.6 野战实体、地图与权限

18×12以内方格，每方最多5部。单位`ArmyUnit`保存id、commander_id、所属、当前有效兵员、伤员、兵种、训练0—100、疲劳0—100、士气0—100、指挥资源0—100、粮草引用、位置/朝向、行动状态。每部P1规模50—500，属于小规模野战抽象。

玩家控制集由授权与本场角色计算。部将只控制自己的获授权单位；统帅控制所辖部队，可委任。P1正常仕途至领队，不让玩家提前获得君主权限；统帅接口通过独立测试夹具验证，不能以此宣称P1已开放高官路线。

每轮开始按`floor(统率/10)+兵种速度基值`降序排队，同值按轮转稳定ID。步兵速度1、弓弩0、骑兵3。每部一次行动；可移动后攻击/战法，或防御/等待/撤退。已经行动、溃退、被俘或消灭的单位不再行动。

**轮内任一阵营达成即时终止条件时，仍结算当前已开始轮次的一次半日，而不是根据谁先行动获得免费时间。** 其余未行动部队不补攻击，只生成回合结束结果。世界事件与援军在轮次边界进入，不在某支箭动画中途改阵营。

## 5.7 兵种、地形与控制区

| 兵种 | 移动点 | 射程 | 基础特征 |
|---|---:|---|---|
| 步兵 | 3 | 1格 | 复杂地形稳定，可固守和协防 |
| 弓弩 | 2 | 2—4格 | 需射界，贴身仅50%强度近战，不可用远程战法 |
| 骑兵 | 5 | 1格 | 开阔地侧击，林地/泥地成本高 |

平地/道路移动成本1；林地步兵1、弓弩2、骑兵3；丘陵所有2且弓弩射程+1（不超过5）；泥地步/弓2、骑4；水域P1不可通行。敌军上下左右邻格构成控制区，进入后结束移动；起点已在敌控制区可后撤1格但本轮不得攻击，佯退另行解除限制。

移动不能穿过敌军；可经过友军但不能停在友军格，途中若友军已变为障碍需重新给合法预览，已确认行动不得穿墙。单轮顺序结算，不复用个人战同时抢格算法。

侧后攻击以目标最近确认朝向判断，侧面伤害110%，背后120%；BA04满足骑兵、本轮移动至少2格、目标侧后时再乘125%。骑兵不获得无条件对弓弩的额外相克系数。林地被射击伤害×80%，丘陵防守近战×90%，固守×80%；最终所有伤害修正限制在基础的40%—180%。

## 5.8 野战伤害、士气与战法

`攻势=35+floor(统率/2)+5×对应兵种技能+floor(训练/5)`；`守势=35+floor(防御统率/2)+5×防御兵种技能+floor(防御训练/5)`。

`基础减员=max(1,floor(攻击有效兵员×攻势/(6×(100+守势))))`。

最终减员=基础减员×地形/朝向/士气/战法系数后取整，最多为目标当前有效兵员。士气系数`5000+50×攻击士气`（50%—100%），单位疲劳效率沿用03的四档，在本轮攻击时读取并乘算；正常行军每半日部队疲劳+3，合格驻地休整每半日−10。P1野战普通伤害不再叠随机暴击，便于判断；战法中需要概率的状态单独从battle随机流抽取，配置明示。

损失中伤员`floor(减员×60/100)`，死亡为余数；从有效兵员扣全部减员，再分别加伤员池与死亡累计，不能战后把伤员与活跃兵都全恢复。目标士气减少`min(20,2+floor(减员×100/攻击前目标有效兵员))`。统帅被击退另使同侧未溃退单位士气−10，一场只发生一次。

士气0立即进入Routed，下一次自身行动自动向本方出口移动，不能继续攻击。被包围且无可达出口、连续2轮不能撤离则被俘；剩余有效兵员进入俘虏池，不变成无故死亡。击溃敌军可以获胜，不必杀光。

指挥资源初始40，上限100；每轮自身行动开始恢复`5+兵法级`；战法消耗见03。同一轮每部只能一个主动战法。协防转移的是原始伤害中的20%，两部合计减员不能超过原本总数；不递归触发另一协防。所有修正按基点一次取整。

## 5.9 战争目标、补给与恢复

目标类型：击退、守住位置N轮、护送实体到出口、突破指定部队、掩护指定友军撤离。创建时冻结参与者与目标，事件可以在边界改变条件并明确通知。护送目标失败优先于“最后一击杀死敌统帅”；双方同时失去关键目标按场景平局/撤退处理，不强行给玩家成功。

每半日有效军队口粮为`ceil(半日起始有效兵员/100)`粮。**唯一扣粮位置是02的T4**；战斗只提交本轮供给清单，世界系统使用`consumption_key=(tick_end,unit_id,'rations')`确保扣一次。军队在T3释放战斗占用后，仍按起始供给清单扣该轮粮，不又按日常驻军扣第二次。

粮不足扣到0，单位士气−10、当轮结束后产生缺粮状态；连续缺粮2半日每半日再逃散`ceil(有效兵员×2/100)`。逃散记入离队，不伪记死亡。行动确认前显示库存可支持的半日数。

战后双方分别处理占用、位置、伤员、俘虏、公物和任务结果。安全据点且有供给时每日恢复`min(伤员,ceil(伤员初始池/4))`，每批伤员在4个合格恢复日内返回；中途行军或断供暂停。不按当前伤员百分比无限逼近0。

远方战斗使用同一攻击/防守参数与补给规则，以固定中性地形和自动策略逐轮计算，不走UI；正式阶段再做聚合提速。无需另造不可比较的“战力一乘就必胜”公式。结果校验只要求同条件下表现方向与损失量级合理，不保证与玩家战术逐步相同。

## 5.10 P2攻城详细规则

不计入P1。复用单位、时间、供给、朝向和战法，只增加城防节点与器械动作。最小完整城防图包含接近区A、主门G、侧道S、城墙W、内城I、守方补给口D。连线A—G—I、A—S—I、W—G/W—S、I—D，节点由场景定义映射到已有战场格，而非新3D引擎。

主门耐久300，側道障碍180，城墙防护使相连守军远射伤害×120%；攻门行动占一次攻击，造成`20+5×筑城级+floor(部队有效兵员/50)`耐久损失。简易攻具消耗木材10、铁料2及4半日制造/准备，每次攻门额外20；必须由合法资产提供，不能到城门自动生成。

城門/側道耐久0后允许进入内城；控制内城连续2轮且守方统帅已退出/溃退则占领。破门不直接让所有敌人消失。守方可轮换部队、修复未交战节点（每轮消耗木料2恢复20）、突围或等待援军。攻方可压制、分路、围困和谈判。

围困需封锁所有当前有效补给边，并实际占用至少两部维持；否则不认定完全断粮。守方粮耗仍每半日由T4扣；库存为0且连续6半日无法补给、士气均值<30时进入投降协商窗口。投降条款允许保命离城/整编/等待援军，须有负责人权限和真实人物意愿判定；不是固定日期自动交城。

占领转移据点公共库存与守备权，私人物品和商铺不默认清零；设置占领整合期20半日，期间税收50%、征募冻结，复用06治理规则。P1只能发生已定义的政治归附/投降事件，不以扣城墙或未实现围困伪装已经完成攻城。

## 5.11 战斗验收

T35：抢同格最终只有一人，跟随链可进入空格、交换与环换失败。T36：个人战AI不随玩家未提交草案变化。T37：同时致命攻击双方均生效。T38：目标移出范围不自动追击，未发动进攻秘技退预留气势。T39：防御朝向确实改变减伤，背面不享正面防御。T40：墙角射线不能穿过被阻挡格。T41：护卫对象被擒但主角存活仍判失败。T42：每部一轮只行动一次，部将不能控制友部。T43：弓贴身减效、骑兵泥地受限、控制区有效。T44：协防总损失守恒且不递归。T45：兵力/伤员/死亡/俘虏/离队合计正确。T46：战斗轮结束只扣一次粮，提前胜利仍耗1半日。T47：退出动画/读档不重新掷伤害。T48：P2破门仅开放道路，不直接判占领。T49：围困未封锁补给口不触发断粮投降。T50：远方自动战有真实损失与消耗，不瞬移出兵。

# 06｜世界AI、事件、外交与治理详细设计

**基线：总体设计第9、16—18章。决策：I32、I40—I45。P1运行区域AI与事件；完整治理和攻城外交按P2开放。**

## 6.1 NPC行动，而不是装饰性日程

每个具名人物具备`role, personality_tags, goals, needs, knowledge, main_action_id, home, affiliation`。需要与目标取有限枚举，不先构建通用规划语言。20名重点人物增加专属事件和目标；其余60名也有真实所在地、工作和资格。

调度：人物已有行动继续执行，只有空闲、行动失败/结束或重要处境变化时选择下一行动；每半日最多一次决策。行动候选包括执行职责、休息、旅行、交易、学习、访问、等待。不可用动作在评分前排除，不通过高评分突破资源/位置限制。

初始效用`U=职责紧迫度(0—50)+个人目标收益(0—25)+关系动机(0—15)+性格契合(0—10)−时间成本(每半日2)−资源负担(0—20)−风险(0—20)`；最高分且>0才执行，否则休息/等待。同分按行动编码，必要的少量性格扰动在进入决策时取world流一次并保存，界面刷新不重选。

出征、被俘、受伤和主要任职职责具有硬限制；师傅已接受课程便不能又自动去另一城购物。NPC听到的情报与玩家一样有来源时间，不能直接读敌方未来命令。调试记录保留“被排除原因、前三候选、选中原因”，不把整段内部评分强塞给玩家。

### 经济与职业生活

NPC交易使用同一个市场接口与真实个人/授权组织钱包；缺钱可以工作，不能无限生成自己想买的装备。组织公款、日常民間工资与供给等合法来源显式标记，P1不维护全体平民实例。NPC岗位服务不要求每位摊贩都有完整历史人物AI，公共市场可由设施服务实体承担。

在野人物优先满足休息和生计，然后按专长访学、交游或求职；士卒/官员优先履职但保留期限内自由时段；商旅人物在有正预期净收益且足够运力时选择贸易。行商只使用其已知行情，不能总是精确追着玩家刚制造的价差瞬移。

## 6.2 区域势力决策

组织状态包含负责人、据点、主要成员、现金/粮草、编制、外交态度、守备底线、已批准行动、下一决策tick。每6半日评估一次；战争结束、负责人更替、据点归属变化时提前一次评估。常规月议事另外处理成员主命。

决策顺序：处理负责人/组织有效性 → 满足现有军队口粮 → 保持据点守备 → 恢复/招募 → 指派民政与采购 → 决定军事行动。P1每组织最多2支外出军队，不能把所有人征空。军事发起需要预计可支持至少6半日供给、出发后每控制城市守军≥100、已知可达道路和获授权将领。

出击目标评价：明确争议或防卫需求+50、预计局部优势≥1.4倍+20、道路价值+10、供给不足直接禁止。优势比较用05统一战斗参数，不凭空读取隐藏敌军；未知兵力采用已知报告和保守估算。失败后至少6半日整补，不每个tick重生一支全新军队。

P1支持真实行军、野战、护送、巡防、道路封锁、协商停战和政治归附；**不把未制作的攻城变成自动城墙伤害**。普通野战胜利改变部队、道路和谈判处境，不直接改城市归属。归属变化通过符合条件的政治事件发生；P2接入05的攻城后才提供完整军事征服。

这是对区域切片边界的明确化，不是取消完整产品的动态战争、灭国和统一目标。P1中“统一区域”只可来自实际归附结果，并且仍称区域结果。

## 6.3 世界资源更新

据点公库与民间市场分开。P1世界AI最低字段为公共现金、粮、可招募人数、守军、治安/民心；不开放玩家城郡治理界面。月度收入与补充从`production_profile`产生，记录公共生产/税收，而非按AI缺多少就补多少。

征募一次最多20人，必须从可招募池扣，每人招募费40钱；训练、装备和口粮另有真实来源。每月可招募池恢复为当期人口允许的上限，未到月末不因为重开面板恢复。P1回补上限依据据点配置；P2切换人口模型后按人口与治安计算，不并行运行两套补兵规则。

普通难度不隐藏增加AI资金或偷看玩家计划。后续高难度若增加资源，只用明示倍率，记入难度设置并可在报告中查出。

## 6.4 事件数据契约

`EventDef`至少含id、scope、priority、window_start/window_end、conditions、participant_slots、location_constraints、choices、effects、cooldown_ticks、once_policy、fallback、text_keys。scope为world/actor/task/organization之一，一次性标记以`def_id + scope_instance_id`建立，不使一次粮商失约封死以后所有角色的同类事件。

条件只允许比较数值、检查存在/状态/标签/归属、AND/OR组合；效果只允许调用已定义的资源转移、关系变化、启动任务/行动、赋予卡片、改变事件标记、设置到期修正。禁止在内容中塞可执行脚本，主要是保持可校验性和存档可信度，不建立庞大内容脚本平台。

参与者槽分`fixed_actor`和`eligible_group`。专属人物事件不可把死者自动替换成陌生人；普通职务委托可以在同职责、地点、资格条件下换合法负责人。选择结果不得创造本不存在的货物账本。

## 6.5 事件生命周期与冲突

`Dormant → Eligible → Queued → Presented → ChoiceCommitted → Resolved`；条件失效可走Cancelled或预设Fallback，后续连锁事件重新按自己的ID进入队列。

入队和展示前各检查条件。普通同一tick最多展示3个非关键事件，其余保留；紧急战斗/人身危险/任务即刻失效优先，不丢弃。排序为优先级降序、进入时间升序、事件ID升序。选择触发的新事件最早下一次稳定边界展示，禁止同一调用栈无限自触发。

事件展示期间世界时间停住，不需要现实线程锁；参与人物有当前交互占用，不能被同一条选择重复启动另一项互斥会面。选择需要1半日就创建明确行动，先显示时间与费用，不在对话文本中偷偷推进。

提交选择先重验费用与硬条件，原子执行结果并写入choice_id/settlement_id。若主体已无效，显示原因和配置好的退化内容；不能移花接木使用原来的按钮位置执行另一选项。

以下是原创事件设计，不声称为史料事件；地点用02功能节点。正式对白、人物名称和美术属于后续内容制作，规则入口与结果在此确定。每个事件至少有接受/拒绝或两种有效处理，不用随机加减钱代替系统行为。

| E11 渡运中断 | F01路线在用、阶段气候/事故条件成立 | 陆路绕行/等待4半日/返回 | 封锁指定边4半日并影响所有人，不对玩家单独生效 |
| E12 路遇索财 | 路段遭遇抽中、队伍尚在该路段 | 支付最多30钱/交涉/个人战/可用回撤 | 扣合法个人钱；公款不擅自支付；战斗仍属于该路段半日 |
| E13 商铺断货 | 店铺已开、连续2日缺主要货 | 自采/改商品/暂停营业 | 建采购/交易计划，按实际库存恢复，不凭空补货 |
| E14 粮价与乡里 | 地方粮库存<目标25%，持续2日 | 卖粮/完成救助运输/不介入 | 从真实货物供应，民心与声望按贡献更新，价修正有期限 |
| E15 被俘出路 | 玩家Captive状态 | 自付赎金/组织交涉/等待释放 | 赎金上限个人钱20%，不足可等10半日；释放到安全据点，重伤先救助 |
| E16 旧主不在 | 任职组织灭亡或发令主体永久失效 | 交接/转交接管者/保管公物 | 调用04清算、解除无效权限，私产保留 |
| E17 地方归附 | 地方负责人可决定归属、与原主关系破裂、另一方供给/保护提议有效 | 留守/谈判归附/拒绝 | 使用外交权限和组织意愿判定；更换真实归属并整合，不无故复活势力 |
| E18 行历回顾 | 12据点见闻且6次有意义交往，未触发本阶段回顾 | 观看继续/退休 | 记录TI06、生成回顾；继续保留世界，退休有独立确认 |

三条短链为E01—03、E04—06、E07—09。链中断要有取消说明，不为了凑完成率强行生成缺失参与者。E15由多次等待行动推进世界而非跳过所有其他人活动；标准模式保证10半日内存在无钱释放路径，代价是时间与有限损失。

## 6.7 历史倾向与沙盒

历史倾向仅提高符合真实前提的已审校事件权重，不能改写既有死亡、俘虏和归属事实。自由沙盒关闭强方向性权重，保留相同日常任务、经济和人物规则。

正式史实事件额外带`source_refs, historical_assertions, adaptation_notes`。未完成出处审查的事件不能作为历史事件发布，仍可明确标为虚构支线。190年只是总体设计的剧本锚点；本详细设计不编造同一天80人的真实部署。

## 6.8 P2治理：可执行规则而非权限名称

玩家成为城郡负责人后开放预算与委任，不让基层开局直接操作。`CityState`增加人口、生产劳力、可征募池、治安、民心、田地/工事级、税率政策、整合剩余tick、岗位任命和公共仓储。

月初总粮产`floor(生产劳力×田地产率×季节_bp/10000)`；先满足配置的民用留粮，再按政策分公共征收和民間市场供给。**采用人口模型时替代P1对应生产补充，不重复添加**。货币税基由城市配置的民間税源×政策倍率计算，不从玩家私人钱包扣。

税政三档：宽免=基准70%收入、民心+3；常赋=100%、民心不变；加征=125%、民心−5、下月税基−3%。税基连续调整设50%—150%界限，恢复依安民与常赋而非保存加载重置。未稳定占领期收入50%、禁止征募，持续20半日。

| 委任 | 耗时 | 费用 | 前提与效果 |
|---|---:|---|---|
| 农政 | 10半日 | 公钱300 | 农政≥1，完成后田地产率+2%，同田级累计上限10% |
| 安民 | 6半日 | 公钱120、粮10 | 民心+`3+礼学级`，不超过100 |
| 巡防 | 6半日 | 公钱100、授权步卒20 | 治安+`3+兵法级`，部队和领队被占用 |
| 修缮 | 8半日 | 钱200、木10、铁2 | 筑城≥1，恢复城防100，最高为已建容量 |
| 征募 | 4半日 | 每人40 | 扣可征募池，生产劳力随出征人数下降 |
| 训练 | 4半日 | 钱150、真实口粮 | 训练+`3+对应技能级`，上限100 |

每项委任复用TaskInstance、人员占用、进度与取消清算；玩家可亲做但不额外获得免费时间。委任者离职/死亡触发改派或按已完成比例结束，不复制工程成果。

区域统辖者设各城预算上限与目标，不能跨授权动用主君直属仓库；君主确定全势力方针与任免。预算改变影响下一次执行，不能中途把已实际付出的工程费收回来又重复花。

## 6.9 外交与势力存亡

外交提议`DiplomaticOffer(id,issuer_org,target_org,envoy,terms,expires_tick,required_authority)`。条款限停战、通行、援助、物资合作、归附；使者必须实际到达，报价/条款在到达后复核。下属可提出建议和执行主命，不能本人替国家签同盟。

目标接受分=对方收益0—40＋履约可信0—30＋共同威胁0—20＋使者交涉0—10−风险0—40。分≥50接受，30—49提出一份明确反报价，<30拒绝。人物亲近仅影响接触与最多5点可信辅助，不能压倒敌对的硬条件。停战初始期限60半日，到期前发通知，违约产生组织间明确的关系与声望后果。

组织失去全部合法据点并无有效流亡存在条件时进入Defeated；依次冻结新任命/开销、处理公库接管、把军队和人物分为归附/被俘/在野、解除旧任务、迁移有效事件。私人关系保留。人物死亡只可由战斗/剧情/寿终规则产生，不随组织对象被删除而整批死亡。

## 6.10 世界与事件验收

T51：80个具名人物状态合法且不存在同人多地。T52：NPC购物扣实际钱包与库存。T53：无6半日口粮或出征会掏空守军时不发动军队。T54：三条事件链可达且每步使用真实人物/资产。T55：专属参与者死亡不自动用别的人顶替。T56：选项成本变化时要求重验，已失效选择不偷偷改意。T57：同tick连锁事件不能无限递归或丢掉紧急事件。T58：P1野战不通过未实现攻城自动占城。T59：被俘10半日内有无钱出路，世界照常推进。T60：P2治理替代旧生产器，无重复税粮；占领整合期生效。T61：使者行动与签约权限都真实存在。T62：灭国不清空私产、不复活死者、不留下永久无主任务。T63：批量无人干预模拟检查资源、世界塌缩分布与卡死；这些是未来游戏测试，当前未执行。

# 07｜完整人生道路与结局详细设计

**基线：总体设计第7、18章。决策：I01—I02、I12、I41、I46。**

仕途与商铺见04，军事高位与治理见05—06。本章补齐豪侠、水上人生以及四条求道路线的规则，不把后续目标删成一句“以后再说”。**豪侠/水上主要在P2开放，求道独立后期在P3完成；P1不以基础服务冒充这些职业已经可玩。**

## 7.1 共用职业合同

主要组织任职占一个槽：政治势力、商旅组织、豪侠组织、水上组织相互排他。自由贸易、私人铺位和求道活动不是额外任职。加入新组织前展示旧任务、物资、保密/恩义承诺和解除方式。

`CareerState`记录职业代码、阶段、资格成就集合、组织/私人事业ID、已完成里程碑；阶段从客观成就派生，不能单靠重复点击“申请晋升”改变。求道事业采用`Institution`：所有者、据点、类型、等级、公共/私人资源、职员/学生、课程或订单、开支、开放状态。复用店铺库存、任务与时间，不为每个职业开发独立经营引擎。

从一条路线离开，不删除已学技能、合法私产和人脉；公开背弃仍影响相关关系。只有当前正在执行的行动与地点约束限制兼修，职业不是禁止其他生活的技能锁。

## 7.2 豪侠组织

组织层级：受托者 → 可信成员 → 领事 → 组织首领。进入需完成一项地方护送/救援、组织信任≥30；领事需履约5次且覆盖护送、探听、救援三类，信任≥50、相关技能至少2；首领需组织支持≥60并完成一次组织危机事件，而非花钱买头衔。

任务使用信息、人员、交通和合同：探听只产生消息条目，不直接改变敌方位置；救援可以交涉赎回、护送脱险或在明确战场中突破。成功条件为实际人或物安全抵达，杀敌不是唯一答案。人员占用与公私物资仍用共用规则。

探听行动耗2半日，费用40；线索充分度由消息来源与任务条件计算。成功分`30+10×谍报级+floor(智谋/5)+关系辅助0—15−防备0—40`，≥55获得可靠位置报告，35—54只得旧位置/时间，<35未获有效情报。暴露风险独立：明确的高警戒区域基线20%，谍报每级减3百分点，最低5%；非敌对公开询问不制造随机通缉。暴露后取消隐藏接触并影响具体组织关系，不让全世界同时知道。

领事最多同时安排3个小组，每组有实际领队、参与者、目标、预算和路线。首领安排成员职责与承诺优先级；拒绝伤害无关人物的委托可以保留信誉但放弃报酬，不用一个全局善恶值抹平雇主差异。

阶段结局“乡里所托”：10项有效履约、至少3次和平完成高风险任务、两处据点关系良好。组织结局“众人相从”：组织成员≥8、无未清重大违约、完成危机事件，可继续作为首领活动。数值为试玩起点。

## 7.3 水上组织与船队

入行 → 独立掌船 → 船队领事 → 舟师/航路首领。必须区别于陆上商人的改名：水路可达性、船位、载重、停靠许可、船员、季节通行和船体状况决定行动。

`Ship`字段：id、owner、所在港/route、容量、船体0—100、船员当前/最低、速度、assignment_id、维护状态。初始两船型：小舟容量60/船员5/速度100，大货舟容量180/船员15/速度80。抽象单位，不提供真实造船教程。船体<30禁止远航；每完成10半日航行损耗5，停靠维修耗2半日、木材3、钱80恢复20。

同一船只只能属于一个有效航行任务；货物+人员占用不得超过容量。船员不足不出航，风浪使速度下降而不是无提示把玩家直接击杀。航线受阻可改港、等待或原路返航；油漆水面的陆路图不算水上玩法完成。

船队任务包括运输、护航、救助、封锁和军用调拨。商业与军用合同明确所有权与支配权；船员、船舶、货物使用同一世界位置。小舟可走浅航道，大船需要深航道；跨港运输必须实际消耗时间和费用。

水战复用05部队战并增加水格、航向转弯成本和船体：每部关联船组，水战技能替代步骑技能；普通舰载攻击先造成船体压制/人员损失，船体0且不能撤离时触发被俘/弃船结果。首次完整水战只需一套水域地形与两类船，不制作海洋物理模拟。船体攻击基础`10+3×水战级`，转向90度消耗1移动点，逆流成本+1；火攻不在首个水战扩展中增加未经定义的真实燃烧模拟。

阶段结局“往来无阻”：完成5次跨港合同，至少2种通行条件，合法自有一船。后期结局“江上之主”：掌握3条实际航线、船队连续30日收支非负、完成一次护航或军事危机。航线掌握来自停靠许可与组织关系，不是购买地图上的一根线。

## 7.4 武学：师承、挑战与传授

完整流程：入门学习 → 掌握一系 → 接受挑战 → 开馆/授徒 → 形成传承。技能等级不等于武学事业阶段，获得所有攻击卡也不会自动成为宗师。

入门可在公共设施；精进需要至少两位不同教学来源或两类实践考核，避免唯一NPC死亡锁死路线。掌握一系需相关技能3、三张同系本领、三次不同对手/规则的挑战。对手技能和流派影响考核，不要求真实历史名将一定在场。

开馆条件：武艺3、声望≥150、合法场所、钱800及100运营金。每半日传授最多2名学生，教师被占用，学生每半日得20基础经验，不能点击收徒立刻复制全部技能。收费每生每课20，场所日费3，收益来自实际课程。教师不在时暂停高级课程，合格代教最多教到自身等级。

挑战类型：位置考核、限制秘技、保护对象、不同武器对局，均用05规则。不提供独立动作引擎。连续切磋同一个低等级对手不会累加“不同挑战”成就，但仍可练习。

结局“自成一家”：主技能4、至少五项同系本领、三名学生各达技能2、完成一项理念选择事件。结局不要求杀死其他流派人物，也不授予无条件最高伤害。之后可继续授徒、旅行或任职。

## 7.5 名士与学问：讲学而不做知识问答考试

访学 → 能立论 → 开席讲学 → 门生与地方影响。核心材料是游戏提供的文献和事件，不要求玩家预先背诵三国史。技能以礼学、辩说为主，研究文本有稳定文献ID和所提供的游戏论据标签。

研究一篇需4半日，消耗纸墨类抽象费用40；完成获得该文本见闻与一条论据，不能刷同一本重复增加文献数量。论据在礼议中提供上下文选项，不直接把所有请求变为成功。

讲学开设条件：礼学3、辩说2、三类不同文献记录、钱600场所费。每半日一场，最多3名学生/听众组；每场给实际参与者经验，人物位置与时间真实占用。地方调解作为事件任务，须考虑各方承诺；偏袒会改变相关关系，不用万能“魅力判定”洗掉利益冲突。

结局“桃李成荫”：至少三名学生礼学2、完成三项地方争议/教化事务、讲学累计20场。被征辟可以接受或拒绝；拒绝出仕不封锁结局。不引入全国教育经营或书院联网排行榜。

## 7.6 医者：纯游戏化医案与医馆

学习 → 普通医案 → 疑难医案 → 医馆/救助 → 传授。全部医案是虚构标签与资源匹配，文本不得输出真实诊断建议、真实处方剂量或现实操作步骤。

`Case`包含patient_id、fictional_pattern、severity1—3、已知线索、护理/用材选项、疗程、费用承担、结果上限。游戏线索可为“奔波疲惫”“伤后虚弱”等叙事状态，具体药材仅作为抽象道具编号。结果通过医术和信息完整度决定，不由玩家在互联网上查真实医术才能破解。

观察耗1半日给线索；选择支持、调理、专门疗程三类抽象方案。适配分`40+10×医术级+线索完整度0—30−严重度×10`；≥60按全疗程完成恢复，40—59延长2半日，<40需转诊/补充观察。不会把错误选择变成现实药方教学。高危剧情另明确风险，普通低级病例不随机杀人。

开医馆需医术3、五项不同合格医案、钱800场所费与200运营金。床位3，每个病人实际占位和时间；每日消耗护理物资，资金来自收费、赞助或玩家自付。无钱病人可减免费用，影响医馆收支与声望；不能同时把减免金额算作收入。

结局“济人有术”：三类严重度医案各合格、完成一次区域救助、至少一名学生医术2。救助物资要真实从市场/组织转入，病患结果更新真实人物状态。医术技能早期作为学习/服务出现，不代表P1已完成上述经营。

## 7.7 匠师：材料、订单与可控质量

入门工艺 → 稳定作品 → 作坊 → 名作/传承。制造只采用游戏材料与品质数值，不提供真实武器制造工艺。

`RecipeDef`：id、产品、抽象材料列表、最低锻造级、基础工时、设备等级、品质上限、可选工艺标签。`CraftJob`：任务ID、材料所有权、已消耗材料、已完成半日、熟练度快照、质量结果、订单引用。

开工时预留全部材料，第一半日消耗基础材料；取消后返还未投入材料，已投入部分转成回收材料（50%向下取整），不把完整原料和成品同时发回。成品仅在工时满足后生成一次。

基础品质`40+8×锻造级+5×设备等级+材料适配0—15+操作成绩修正0—10−赶工罚分0—20`，限制在配方允许区间。普通、良、精三档为<60、60—79、≥80；达到“名作”还需特定配方/经历且品质≥90，不能用重复随机按钮无条件赌出。赶工时间×75%但品质−15，确认前说明。

开作坊：锻造3、完成5个不同订单、钱1000与合法设施；P3初始1工作台，可通过投入700扩为2台，每台仍需实际人员。军用与民用订单共用库存和工时；人员不足时不能两台同时以同一师傅效率运行。

结局“器以传名”：完成三类不同用途高质量订单、制作一件满足条件名作、培养一名锻造2学生。不是积累最大的战斗伤害就算匠师通关。

## 7.8 阶段结局与终局

`Milestone(id,conditions,claimed_tick,world_summary_refs)`。满足后排队展示一次回顾，奖励与图鉴记录原子提交；选择继续不改变世界，观看第二次不再领奖。

| 结局类型 | 时机 | 后续 |
|---|---|---|
| P1仕途 | 领队资格/独立考核达标 | 可继续已有任务，超出职位明确版本边界 |

完整版本自然寿终年度风险基点`min(8000,300×(年龄−69))`，70岁以下为0，仅在游戏年界检查一次，属于寿命玩法参数，不是人口史学模型。P1不启用自然寿终随机终止。便利设置可关闭主角自然寿终，不影响一般成就；历史人物专属终局事件仍需明示且满足状态，不按历史日期强制复活或杀死。

婚姻与结义通过双方意愿、合法身份和事件建立关系事实；婚姻对象都为成年人；不做配偶装备数值系统。第一轮完整产品不加入生育养成、跨世代继承或家族树经营。回顾来自实际经历记录，运行时不调用大模型编造人生。

# 08｜程序架构、数据、存档与跨平台详细设计

**基线：总体设计第21—23章。决策：I04、I47—I52。**

## 8.1 已核对的技术约束与选择

2026-09-09核对Godot官方文档：Godot 4网页导出使用WebAssembly、WebGL 2.0及Compatibility路径，C#项目不能按该官方路线导出Web；单线程导出可避免把跨源隔离作为本项目初始部署前提。[R1] 因而沿用GDScript和单线程网页基线，不引入第二套Phaser规则实现。

具体Godot小版本不在未执行工程探针前冒定。工程首个验收要求一人物、一次旅行、一次交易、一次保存，Linux与Web分别运行；通过后构建清单记录准确引擎版本、提交标识、模板标识和导出设置。这里不宣称已找到“最好最新版本”，也不把未锁定构建混同于未定义游戏规则。

规则对象可使用RefCounted等GDScript对象但不依赖SceneTree节点；不声称因此完全不依赖Godot。原生文件与网页文件分别实现适配层，核心不写浏览器API。

## 8.2 模块依赖与职责

| 模块 | 写入职责 | 对外契约 | 不允许依赖 |
|---|---|---|---|
| ContentCatalog | 已校验静态定义索引 | 按ID读、列资格、内容版本 | UI节点、玩家存档副作用 |
| WorldKernel | tick/revision、提交顺序、不变量 | preview/submit/advance、稳定状态 | 文件选择器、音乐动画 |
| PersonRules | 属性、经验、关系、任职 | 资格/请求/成长结果 | 全军越权调度 |
| EconomyRules | 报价、所有权、账单、店务 | quote/trade/transfer/day_close | UI按钮、绘图 |
| TaskRules | 目标事实、期限、清算 | accept/report/settle | 自行推进时钟 |
| EventRules | 候选、绑定、选项效果 | enqueue/present/choose | 任意脚本求值 |
| DuelRules/ArmyRules | 回合、命令、伤害/损失 | plan/resolve/result | 物理动画决定胜负 |
| WorldAI | 根据已知信息选合法行动 | proposals、决策理由 | 绕过WorldKernel写资源 |

规则模块返回效果，由Kernel按固定阶段合并提交。没有微服务、HTTP游戏后端、消息队列、ECS总框架、数据库服务器或运行时大模型。浏览器IndexedDB是本地存储适配，不是引入联网游戏后台。

### 请求、结果与幂等

`Command`含kind、actor_id、参数、expected_revision、request_seq。每个操作主体的已接受request_seq单调增加；相同序号已执行则返回缓存结果，缓存淘汰后返回AlreadyApplied，不再执行。序号更旧同样不重新执行；新序号但版本过时返回StalePreview。实例ID由世界计数器产生，存档恢复计数器。

`ActionResult`含result_id、from_revision/to_revision、start/end_tick、实体变化、领域事实、显示消息键及参数、需交互事项。结果发生一次；不把它做成无限历史重放系统。保留最近64个请求结果便于重复点击反馈，长期事实由任务/卡片/账单自身的终态保存。普通明细账保留最近360游戏日，重要人生记录最多2000条；更早非关键记录汇总到累计统计。未清任务关联、一次性标记、解锁条件计数与现有资源不随日志清理删除，不能靠剪日志重新领取成就。

读旧手动档后另走一条人生是允许的单机行为。不同周目不能合并局内财物，因而不需要防止玩家主动读档的服务器审计。

## 8.3 数据表示与校验

静态内容采用UTF-8 JSON，以稳定ID关联；显示文本通过text_key引用；资产清单记录asset_id、路径、角色关联、来源/许可和正式/临时状态。实际制作可用表格辅助，再转成同一份规范内容，不让运行时依赖Excel或外部服务器。

| 记录 | 必填核心字段 | 参照完整性 |
|---|---|---|
| ActorDef | id、origin_tag、attributes、skills、initial_place、text_keys | 地点/组织/资源存在；属性范围合法 |
| SettlementDef | id、type、facilities、market、owner、map_xy | 8城2乡1渡1营数量；合法可达 |
| RouteDef | id、端点、长度、模式、风险、费用 | 端点存在，长度正整数 |
| ItemDef | id、price、weight、stack_limit、category | 重量>0，价格>0 |
| CardDef | id、type、condition、effect、hint、icon | 效果类型合法，跨战斗引用不允许 |
| TaskDef | id、模板、目标、期限、资金、清算、文本 | 10类目标字段齐全，预算不为负 |
| EventDef | id、条件、人物槽、选择、效果、失效支路 | 专属/替代人物条件清晰，循环可终止 |
| ScenarioDef | id、epoch、人物/组织/据点初始状态、enabled_features | 不把P2系统放进P1正常入口 |

正式加载前批量检查所有引用、重复ID、负数、无出口事件、无法完成的必需任务、无人可教的必需技能。报告指明文件和记录ID。缺少必需内容则停止开启该剧本，不用空白头像或无作用卡片默默顶替正式交付；内部测试夹具可明确标测试资源。

核心金额、数量、tick、基点均为有界整数。P1单个数字绝对值最大2^31−1，乘法中间值须控制在有符号64位内；批量价格逐件累加前检查溢出。超过上限报数据错误/交易过大，不能环绕成负数。

## 8.4 随机流和可复现边界

使用封装的Godot RandomNumberGenerator实例，world/event/duel/battle/minigame五个独立流；UI、音效和装饰随机不得调用这五个实例。官方文档说明其底层算法是实现细节，支持保存恢复state，但不应假设以后引擎版本永远保持同一序列。[R2]

因此保证目标仅为**相同已锁定引擎构建＋相同ruleset/content＋相同快照＋相同动作序列**跨平台规则一致。跨引擎升级必须跑固定序列回归和存档迁移，不能只改版本号就称兼容。

种子生成只在开局：对UTF-8的`用户种子文本+冒号+固定流名`求SHA-256，取前8字节按大端无符号整数解释，再与0x7fffffffffffffff相与，得到该流seed；保存seed和原始state的十进制字符串以及rng_backend构建标识。加载先设seed再恢复曾保存的state，不再次randomize。不会任意伪造state值。所有随机判断只用整数区间；遍历字典先按稳定ID排序，不让容器迭代顺序改变取随机数顺序。

需要比较跨平台结果时使用规范化状态摘要，排除真实保存时间、存档路径、动画时长和UI设置；保留全部玩法字段。只比较随机seed不够，还要比较已经消费后的state。

## 8.5 存档封装与安全边界

文件扩展名`.hmsave`，UTF-8 JSON封装：magic=HM-SAVE、format_version、ruleset_id、content_version、engine_build、rng_backend、save_id、generation、payload_length、payload_sha256、payload_json。`payload_json`是核心生成的确定字节文本，再作为字符串装进外层；避免各浏览器对重新格式化JSON产生不同摘要。

payload含WorldState、正在进行的行动/事件/战斗、已完成清算、重要历史及本局图鉴。外层保存时间只用于显示。64位seed/state都为字符串；游戏数值在安全整数上限内，JSON解析后必须校验整数性，不能把3.5个士卒或非数值塞回规则层。

全局档案独立保存设置、图鉴和人物解锁。导入局内档不清空现有全局档案；仅在明确“合并图鉴”操作时合并发现集合，不能并入上一周目的财物。本局取得的新发现携带待投递记录，即使全局档案写失败，重新加载本局也能按集合补记，而不会重新发一次物质奖励。

导入上限64MiB、嵌套深度32、单文本字段16384字符；检查未知必要版本、重复键/ID、非法引用、资源上界、校验值。校验摘要用于识别损坏与版本混淆，**不是签名、加密或防单机修改系统**。不把文件内容交给eval、ResourceLoader脚本或任意构造器。

未来内容版本迁移采用显式映射：旧ID→新ID、字段默认与规则变更。原始文件保留，迁移到新槽。不支持的更新版本拒绝并说明需要哪个版本，不能随机猜字段；已删除关键人物/任务不能静默丢弃后称迁移成功。

## 8.6 稳定保存流程

保存状态：`Idle → SnapshotReady → Writing → ReadbackVerify → Saved`；任一步失败进入Failed，保留当前内存世界和旧有效档。**规则提交成功**与**文件保存成功**是两件事，UI分别提示。存储失败不回滚已经玩的行动，也不禁用文件导出。

3个轮换自动槽、10个手动槽；每槽保存当前和前一代有效快照。创建/读取只在安全边界，战斗输入期、长行程路段进度都可保存。写盘异步期间可继续读信息；新的自动保存请求合并为最新安全快照，但不能让较旧写操作在较新之后覆盖它。每槽同一时刻一条写流水线。

### 原生适配

为每槽保留A/B两代。将下一代写入非当前代的临时文件，flush并关闭，读回检查长度/摘要/格式，再替换该备用代文件；前一代有效文件保留。读取时检查两代，选择最高有效generation；不依赖一份容易损坏的“当前指针”才能找到存档。目录元数据可重建。

手动覆盖先说明将替换哪个槽；坏文件不要就地修复，允许原样导出故障副本。此策略提高异常恢复能力，不承诺所有文件系统在突然断电时绝对零丢失。桌面P1不支持多个原生进程同时写同一用户档案目录。

### 网页适配

选择一层小型JavaScriptBridge接入IndexedDB，核心传递同样的完整快照文本。Godot提供JavaScript对象调用和回调机制，回调引用需保留到操作结束。[R3] 不把引擎虚拟文件系统的写入返回直接当成浏览器持久化已确认。

存储使用snapshots（各代快照）、slots（当前/上一代引用与generation）、profile三个object store。摘要和编码在事务前计算；一个readwrite事务读取预期generation、写入新快照并更新槽引用。事务内不穿插无关await，避免事务因事件循环而失活。[R4]

以事务complete而非单次put成功回调判定提交，再用新只读事务读回并校验，才显示“已保存”。事务abort、容量不足、权限拒绝、意外关闭分别返回可读错误。浏览器事务完成也不是对断电永久性或系统永不清理的承诺；MDN明确讨论了事务完成与真实磁盘刷写的边界。[R4]

同一槽多标签页采用事务内generation比较：标签A已从g写到g+1后，仍持g的标签B写入被拒；B可另存独立槽/导出，不能覆盖A。没有引入协同编辑协议。数据库升级阻塞时提示关闭旧标签或导出当前局，不删库重建。[R4]

浏览器配额、隐私浏览和用户清理可能影响本地存储，因此保留导入/导出与风险提示；`persist()`申请不能描述为永久保险。[R5] 退出页面时仅提示未完成保存，不把最后一次保存寄托于unload。

## 8.7 文件导入导出与往返

原生由文件选择对话框操作，网页由用户点击触发浏览器文件选择/下载，移动端测试实际文件行为。Godot JavaScriptBridge支持导出生成缓冲区；这不等于每个平台的下载体验已测试。[R3]

标准往返测试：网页快照A→Linux加载→执行固定10条命令→导出B→网页加载B→与Linux的规范化玩法状态比较；再继续相同命令序列比较关键结果与随机状态。跨局图鉴另测，不能用“标题显示同一人物名”代替互通。

## 8.8 发布与缓存

HTTPS静态部署；`.wasm`为`application/wasm`，脚本使用适当JavaScript类型，资源包为二进制；压缩声明与实际文件一致。版本目录固定一组引擎、代码、数据、美术，不在运行时从latest路径随机取新素材。

首屏提供用户点击进入、资源加载进度、能力不支持/加载失败信息。声音、全屏等在允许的用户操作流程中发起；网页后台暂停表现但不以真实时间追赶世界。[R1]

PWA作为增强能力：新版本先完整缓存和验证清单，等待当前游玩安全保存/退出后再切换；不在活跃游戏中强制skipWaiting换脚本。保留可启动旧版本，缓存缺失就显示需联网补齐。只有经断网启动测试通过才显示“可离线使用”。资源缓存与存档分开，删除旧资源不能清掉IndexedDB快照。

域名、仓库、部署账号由用户指定，本设计不部署到tvfan.app或其他已有站点，不复用其他项目的Android最低版本或TV遥控器要求。

## 8.9 平台与性能验证口径

P1必须：Linux真实运行、Chrome/Chromium及Firefox桌面网页核心路径、触摸输入路径。Windows尽早构建/启动，但未实测不称正式通过。macOS、Android原生、iOS、移动浏览器分别测试。iOS导出有macOS和Xcode环境要求，需在对应环境验证。[R6]

沿用总体预算：完整P1压缩首传≤80MB，含字体音频；桌面半日模拟p95≤100ms、移动≤300ms；桌面界面目标60fps、受限移动30fps。新增验收方法：预热50步，连续模拟1000步，记录全部耗时和最大值，不只选一个快速截图。报告设备、OS、浏览器、引擎模板、内容数量和内存峰值，不能在无设备时宣称满足。

地图/立绘按当前场景加载，图集以2048×2048为初始上限；字号放大需重新布局。长模拟每完成安全tick可让出一帧，显示进度并允许停止；不能在一个逻辑事务中途让用户发第二条游戏命令。先优化资源和查询，再考虑改规模；不以删掉卡片或NPC假装性能达标。

## 8.10 技术验收

# 09｜界面状态、内容交付与验收追踪

**基线：总体设计第19—20、24—26章。决策：I02、I27、I51—I52。**

## 9.1 界面不是规则的替代物

界面显示规则预览、提交命令、播放已经产生的结果；不能另写交易、奖励或伤害公式。游戏画面采用2D绘景与人物立绘，文字和数值叠层简明，不能把城市生活改成管理后台。下面是交互契约，不是已绘制的26张正式美术图。

布局基线桌面1280×720逻辑空间，侧栏可收起；宽屏增加地图空间而非无限拉伸按钮。手机横屏以单主场景＋底部行动栏＋抽屉信息为主；竖屏提供旋转说明和可访问的存档/退出，不挤压成不可玩界面。桌面常规正文18—20逻辑像素；触屏操作目标按实际显示尺度至少44像素作为设计起点，实机验证，不声称已经达某认证。

所有依赖悬停的信息有点按入口；右键取消有屏幕按钮；键盘只提供便利而不是唯一操作。字号100/125/150%重新排版，不能只放大后裁切。状态同时用图标/文字，不只用颜色；静音仍能识别战斗危险与任务截止。

## 9.3 输入与面板生命周期

世界只允许一个当前模态交互：事件、战斗确认、交易确认或系统文件对话。打开新的模态前关闭/暂停前者，不让同一点击穿透到下层地图。Esc取消草案或关闭最上层，不默认放弃整个主命；移动端返回键遵循相同语义。

场景切换先解除旧信号订阅，再绑定新视图；结果ID已经显示也不再发动作。字号/窗口改变只重排视图，不重建WorldState。拖动地图超过8显示像素判为拖拽，不同时触发目的地确认；该阈值按输入设备可配置。

保存失败提示保留最近“已确认保存”的游戏日期，同时显示当前局有未保存进展，不用绿色图标混淆两种状态。用户主动导出为明确按钮，不能自动在每半日弹下载框。

## 10.1 逐系统交叉审查

检查重点不是有没有写“未来可扩展”，而是同一人物、同一批物资、同一个半日、同一次奖励在不同模块中是否具有相同含义。审查后已将以下约定写回相关系统文件。

| 问题 | 确定的处理 | 落点 |
|---|---|---|
| 到城、点击交付、交付完成混用，导致截止边界不明确 | 按交付完成时刻判定；完成时刻等于截止时刻也按期；先应用该边界的合法完成，再检查逾期 | 02、04 |
| 交易扣钱与播放动画绑定，读档可能重复扣款 | 区分起始效果与完成效果；交易钱货一次性交割，半日占用另记；保存起始效果标记和动作序号 | 02、04、08 |
| 手动经验直接在原始值上乘1.2，最终整数可能超过正常奖励的120% | 先计算并取整正常经验，再计算表现加成；检查8400组整数输入 | 03、verification |
| 采购算例跨日时库存可能更新，固定价格示例前提不成立 | 算例明确将对应市场日产与民耗均设为10，关闭NPC交易及事件；实际游戏不冻结市场 | 04、verification |
| 技能、伤病与疲劳分别影响效率，但没有统一取值顺序 | 状态效率取疲劳与伤病系数的较低者，再进行奖励或个人有效属性计算 | 03、05 |
| 操练任务与部队疲劳只有名称，没有具体结算 | 固定操练时长、训练增长、士气、疲劳、支出与授权；行军和休整有独立规则 | 04、05 |
| 秘技与战法只写风味名，无法判断攻击范围或持续时间 | 逐卡给出触发和效果；补明DU05射程/移动约束及BA07风险持续到下次本部行动 | 03、05 |
| 同时移动争格、交换位置或环形移动可能产生多重占位 | 先目标格竞争，再检查依赖链；通向空格的合法链同时移动，交换和环形依赖拒绝 | 05 |
| 两名角色同时攻击，先播放动画的人可能获得先手 | 从同一攻击快照计算命中和损失，集中应用；动画顺序不改变死亡、反击或胜负 | 05 |
| 野战轮次和世界时钟各扣一次粮，或提前胜利免掉全部粮耗 | 统一在半日结算点按明确归属键扣一次，提前结束仍按该场规定结算一次半日 | 02、05、08 |
| P1不含攻城，却可能靠野战结果直接获得完整城市治理 | P1野战改变部队和道路状态；城池归属需合法政治事件；主动攻城与玩家治理仍归P2 | 05、06 |
| 任务发令势力灭亡后，自动奖励会凭空产生钱财 | 转入失效/待清算分支，按资产归属处理；可由合法继任者承接，但不自动生成缺失预算 | 04、06 |
| 老师死亡或任职调动导致必要技能永久不可学 | 基础成长有替代教师、公共教学或实践考试；专属人物事件可失效，不复活角色 | 03、06 |
| 浏览器一次写请求成功被当作存档永久安全 | 等事务完成并读回校验才显示保存成功；仍明确断电、清理、回收等风险并提供文件备份 | 08 |
| 多标签页先后保存，旧页面可能静默覆盖新进度 | 比较预期槽位代数，冲突时保留双方可导出数据，由用户选择新槽或重新读取 | 08 |
| “同一引擎”被误写成无限期跨版本确定性承诺 | 随机序列只对已验证的相同引擎构建、内容版本及动作序列作验收；升级单独迁移/复核 | 08 |
