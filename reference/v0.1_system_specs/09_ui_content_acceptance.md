# 09｜界面状态、内容交付与验收追踪

**基线：总体设计第19—20、24—26章。决策：I02、I27、I51—I52。**

## 9.1 界面不是规则的替代物

界面显示规则预览、提交命令、播放已经产生的结果；不能另写交易、奖励或伤害公式。游戏画面采用2D绘景与人物立绘，文字和数值叠层简明，不能把城市生活改成管理后台。下面是交互契约，不是已绘制的26张正式美术图。

布局基线桌面1280×720逻辑空间，侧栏可收起；宽屏增加地图空间而非无限拉伸按钮。手机横屏以单主场景＋底部行动栏＋抽屉信息为主；竖屏提供旋转说明和可访问的存档/退出，不挤压成不可玩界面。桌面常规正文18—20逻辑像素；触屏操作目标按实际显示尺度至少44像素作为设计起点，实机验证，不声称已经达某认证。

所有依赖悬停的信息有点按入口；右键取消有屏幕按钮；键盘只提供便利而不是唯一操作。字号100/125/150%重新排版，不能只放大后裁切。状态同时用图标/文字，不只用颜色；静音仍能识别战斗危险与任务截止。

|---|---|---|---|

| UI-02 剧本 | 范围、开局年份、历史/沙盒、启用内容 | 未安装剧本不伪装可选 | 确认后检查内容；引用错误给具体剧本原因 |
| UI-03 人物选择 | 处境、能力、关系、初始任务、开局差异 | 未解锁显示条件，不误导为抽卡购买 | 确认显示将创建新周目，不覆盖旧档 |
| UI-04 自建 | 姓名、年龄、属性预算、技能点、出身 | 预算未分完可继续但提示；超支禁止 | 校验名字长度、点数；失败保持已填内容 |
| UI-05 大地图 | 位置、身份、当前任务、已知消息 | 无可靠消息显示最后来源与时间 | 选中目的地仅预览，不立即走路 |

| UI-08 城市场景 | 设施、人物活动、地方特征 | 不存在设施不画假入口 | 入设施不耗时，接受服务才按规则推进 |
| UI-09 设施服务 | 费用、时间、资格、恢复/学习效果 | 缺钱、占用、技能不够分别说明 | 支付后锁提交按钮，结果只接一次 |
| UI-10 人物交流 | 对方身份、当前态度、可谈主题 | 不在、出征、拒绝接触给消息与原因 | 同一会面合并话题；送礼不收不扣物 |
| UI-11 议事 | 目标、旧主命、可请命/拒绝/延期 | 在外获豁免显示回报入口 | 一次议事一个半日；不会逐页重复扣时间 |
| UI-12 任务详情 | 目标、所缺数量、交付完成截止、资金模式 | 目标暂失效显示可延期/清算 | 接受、报告、取消各独立确认后果 |
| UI-13 市场 | 买卖、库存、总价、费用、运力、所有权 | 钱/库存/仓容不足给可成交上限 | 过期报价不自动付款；双击返回同一账单 |
| UI-14 师承修业 | 教师、条件、课程、时间/费用、替代考核 | 教师外出显示约期或其他来源 | 取消显示已完成经验和未提供费用退款 |
| UI-15 小游戏 | 规则、手动/自动、题面、评分依据 | 不擅长即时操作仍可自动/不限时 | 结果由所属行动使用；重新开窗不叠折扣 |
| UI-16 人物关系 | 属性组成、技艺进度、身份、已知关系 | 未见过的私密关系不公开 | 条件查看不改变好感；数值变化附来源 |
| UI-17 物品货物 | 私产、公物、任务预留、容器与重量 | 不可出售公物说明归属 | 转移预览原/新容量；失败不丢批次 |
| UI-18 卡片 | 类型、用途、本局已学/全局发现、线索 | 未获得显示允许知道的线索 | 解锁动画只是表现；回看不再发奖励 |
| UI-19 个人战 | 目标、范围、计划、朝向、气势、预测 | 非法格/射界/气势不足有理由 | 选中→预览→确认；结算中屏蔽重复命令 |
| UI-20 野战 | 本部/全军权限、行动序、士气、补给与目标 | 友部不属控制集可查看但不可下令 | 轮末才推进世界，援军变化有通知 |
| UI-21 战后 | 兵力损失、伤员、俘虏、物品、任务与时间 | 无奖励显示“无”而非占位卡 | 所有结果已有结算ID，确认只关闭面板 |
| UI-22 见闻记录 | 消息来源、时间、重要经历、过滤 | 无消息给正常空态 | 源已失效仍保留历史，不改写旧经历 |
| UI-23 存档 | 槽位、日期、内容版本、保存状态、导入/导出 | 无持久化权限仍能导出文件 | 写入/校验/完成分开；坏档不覆盖原档 |
| UI-24 设置帮助 | 字号、音量、速度、自动小游戏、控制说明 | 不支持的设备选项给说明 | 应用布局设置可撤回，关闭音乐不丢警告 |
| UI-25 结局回顾 | 达成目标、重要经历、继续/退休、版本边界 | 未达目标显示真实进度 | 退休二次确认；继续不重置世界 |
| UI-26 异常恢复 | 错误类别、保存/导出/重试/返回 | 环境不支持则不持续黑屏 | 区分资源下载、内容错误、存档损坏、内部规则异常 |

常见错误文本由稳定原因码和参数组成，例如InsufficientCapacity附所需/现有运力，StaleQuote附旧/新报价。技术堆栈日志放诊断导出，不替代玩家能理解的提示。

## 9.3 输入与面板生命周期

世界只允许一个当前模态交互：事件、战斗确认、交易确认或系统文件对话。打开新的模态前关闭/暂停前者，不让同一点击穿透到下层地图。Esc取消草案或关闭最上层，不默认放弃整个主命；移动端返回键遵循相同语义。

场景切换先解除旧信号订阅，再绑定新视图；结果ID已经显示也不再发动作。字号/窗口改变只重排视图，不重建WorldState。拖动地图超过8显示像素判为拖拽，不同时触发目的地确认；该阈值按输入设备可配置。

保存失败提示保留最近“已确认保存”的游戏日期，同时显示当前局有未保存进展，不用绿色图标混淆两种状态。用户主动导出为明确按钮，不能自动在每半日弹下载框。

## 9.4 内容规格与生产边界

P1保持12据点、80人物（20重点）、6预置开局＋自建、12解锁人物、3政治势力＋2商旅组织、10技能、24任务配置、18事件、48卡、3小游戏。正文已提供任务/事件/卡片的规则表；人物历史部署、正式对白、地图绘制、音画资源不是本轮已经完成的内容。

| 内容项 | 制作时必须交付 | 不可冒充完成的情况 |
|---|---|---|
| 80人物 | 唯一ID、类型、初始状态、能力、关系、角色、可达入口 | 仅80个姓名或同一头像重复 |
| 20重点人物 | 统一形象、语气、目标、有意义互动、系统关联事件 | 所有人复制同一对白 |
| 6开局 | 2在野、2文武基层、2商旅，各自任务/人脉/资金/权限差异 | 只换名字与属性 |
| 12据点 | 功能地理映射、道路、设施差异、所属与市场 | 12张不同背景却相同所有服务 |
| 24任务 | 接令、进行中、交付、部分/逾期/失败文本，目标字段齐全 | 重复模板冒充独立剧情 |
| 18事件 | 已定义分支、角色绑定、取消/退化、真实效果、三条短链 | 随机加钱弹窗冒充动态世界 |
| 48卡 | 名称、效果、获得路径、线索、图标、重复处理 | 无效占位卡或把等级图标凑数 |
| 美术 | 区域图、城市组合背景、人物一致性、兵种/武器识别、许可清单 | 内部测试图冒称正式原画 |
| 音频 | 标题/城市/旅途/战斗音乐、确认/错误/伤害/完成音效 | 依赖线上加载而离线无声 |

正式人物历史数据另做内容资料表；系统设计采用功能槽并不意味着上线可以留C01、PC01等开发编号。公开区域版必须完成映射、核验和实际可达性，不把“系统可运行”当作“内容已完成”。

美术由样板先统一角色身份、时代感、图标与场景阅读顺序，再批量生产；不在这一轮调用图像工具生成未经需求确认的几十张画面。字体和音频须有明确可分发许可，包体预算包含在内。文档包不提供字体文件。

## 9.7 跨系统验收场景

T85：从真实标题创建低武力在野人物，经短工、交通、举荐、三类主命和补给领队考核获得阶段结果，全程不编辑JSON。T86：从商旅开局通过至少两个城市的真实差价经营，开店、营业10日、完成两订单且净收益≥200。T87：P1普通开局无君主/全军指挥入口；权限夹具单独检验统帅控制集，不能混入正常存档。

T88：在交易起始已扣款、旅行途中、事件已选、个人战待下一轮、野战结算后分别保存并关闭，恢复不重付或丢既有事实。T89：整个标准主线选择自动小游戏，不因某唯一秘技或门槛永远阻断。T90：仅触摸完成出城、交易、访问、战斗、保存，没有隐含右键/悬停步骤。T91：字号150%所有关键按钮与期限可访问。T92：拖动地图和关模态不会穿透触发行动。

T93：钱0、重伤、失业的合法状态可经救助→轻工→普通工作恢复，不能死亡软锁。T94：无人干预模拟至少30个种子×720半日，检查负库存、重复任职、无故复活、死循环和不可达人物；记录各势力存亡分布，调整是否过快塌缩，不能只报平均值。

T95：所有24任务、18事件、48卡至少各有一个可达路径和必要失效路径；T96：UI-01—UI-26都覆盖正常、空/禁用、执行中、成功和失败的适用状态，不能缺页只靠截图。

T97：历史内容标出处与改编、原创支线明确身份；T98：正式资源清单无未授权或冒称正式的临时图；T99：内容预算、压缩包体与平台实测分别报告，数量齐全不等于好玩；T100：重要不可逆动作有后果预览，实际结果与预览只允许有明确标为风险的差异。

这些T编号是验收规格，不是本轮跑过的游戏测试。P2/P3专属测试仅在对应系统交付时执行；不能把文档审查计成游戏测试通过。

## 9.8 完成判据与下一道门

当前详细设计交付应包含自问自答决策、各系统规则、状态/字段/接口、参数、边界处理、内容规格、原需求追踪与自审结果。它不能代替正式历史资料、所有对白、美术、实现、试玩或平台测试。

工程开始前的执行计划应从已形成规则拆小任务和测试，不再重新做一遍同样的产品访谈。首先验证真实小闭环的Linux/Web导出与保存，随后逐系统测试，再拼P1完整生活路径。此处只说明前置依赖，不创建工期承诺、不擅自开账号或部署网站。
