# Selected character presentation checks

The source contract is `views/character_presentation.hpp`. A supplies the six original actor fields and five original public appearance fields; C decides whether the requested actor is among the currently visible selections before invoking this port. `encode_character_presentation` is the single whitelist encoder and retains saved `base_features` field order. Neither the returned view nor its encoded form carries generation seed, parent sources, appearance source category, assets or a runtime actor record.

`state_character_presentation.cpp` passed 39 cases under AddressSanitizer and UndefinedBehaviorSanitizer. It additionally checks exact field lists/order, unchanged common state, independently owned returned strings/features, clone rebinding, strict cold portrait-column types and bad order metadata. Leak detection was disabled because the executor's ptrace environment had already been verified to block LeakSanitizer; this is not a leak-check claim.

The native executable can write a finite input/expected-output vector file when given an output path. `state_character_oracle.gd` reads those same inputs and invokes the original `game/core/views/character_input.gd` on the real pinned Godot 4.7.2 engine. All 38 supported vectors matched values, numeric types, arrays and dictionary key order exactly, and their state/catalog inputs remained unchanged. The original projector, ActorIdentity and ActorAppearance source hashes are recorded in the evidence. An initial oracle runner used the reserved Godot builtin name `Projection`; that runner failed to parse and was corrected to `CharacterInput` before the terminal successful run.

Cases include saved prototype/name precedence, invalid identity before invalid appearance, valid empty authored names, missing author text, Unicode name limits and original edge-space semantics, birthday boundaries and unknown ages, missing/canonical legacy appearance, fixed/custom/generated profiles, saved feature order, private seed withholding and original malformed-profile codes. A native-only case pins inherited-profile rejection as an existing unsupported capability. No inherited identity or parent-source support was added.

The seed-length projector case follows the original GD scalar-count rule; it does not change the common world's existing admission validator. The only existing production files changed are the two cold `ActorNameDefinition` columns and their decoder. Established common validators and the sidebar name port are untouched. These are leaf-query checks, not a world install, broad identity migration, Main rendering or GUI acceptance gate.

Compile the test with matching source/header versions and the new character leaf, common codec/store/validation, and ordered-value implementation. The unit's exported vectors are consumed by the Godot runner in a small project with the unchanged original core scripts; no gameplay resource copies, world advancement or full-scale journey reruns are required.
