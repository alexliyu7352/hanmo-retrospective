# Finite common presentation source

`state_presentation.cpp` covers the two frozen `PresentationRead` methods. It needs `common_presentation.cpp`, the existing common codec/store/validation/checkpoint sources and the ordered boundary implementation; use matching current headers and archives rather than an older frozen library after `CommonCatalog` layout changes.

The behavior is sourced from `game/core/actor_identity.gd::definition/_valid_name` and `game/core/views/scene_journey_sidebar.gd::_name`. Invalid/missing identity first gives an empty definition, then the sidebar evaluates `texts.get("", "")`. A valid definition with absent author name text instead falls back to the requested runtime actor ID. Existing empty author text is a successful empty name. The selected prototype must exist even when the actor has an explicit saved name.

Saved-name limits use Unicode scalar count, not UTF-8 bytes. The pinned Godot source at [ed1daf0bf, ustring.cpp, `strip_edges`](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/core/string/ustring.cpp#L4067) removes only code points at or below 32. Thus nonbreaking and full-width spaces remain legal under the original rule. Invalid UTF-8 cannot be a Godot String and is defensively treated as an invalid saved name when a caller constructs typed records directly.

Cold catalog decoding owns only prototype-to-name-key rows and string texts. Missing `name_key` uses the original empty key. It retains inactive author prototypes too, because identity lookup consults the author catalog independently of runtime actor enumeration. Non-string name keys/texts fail the typed cold boundary. Query results own their strings and do not expose the catalog, actor records or appearance data. Visibility, `$provider`/`$player` resolution, selected options and DTO limits remain caller responsibilities.

The initial source checkpoint was held uncompiled during the unchanged P1 Bridge timing window. After its release, the focused test passed with AddressSanitizer and UndefinedBehaviorSanitizer, including a cold read of the frozen 100-actor initial state: all 100 names matched actual author texts and the common state remained unchanged. Compilation used `-Wall -Wextra -Wpedantic` and produced no warnings (the compiler-specific historical `gnu::no_dangling` attribute is suppressed with `-Wno-attributes`). `state_presentation_evidence.json` identifies the exact source files, binary, inputs and commands.

LeakSanitizer could not run under the executor's ptrace environment; its initial process exited 1 with that infrastructure error. The same binary then passed with only leak detection disabled and ASan/UBSan configured to halt on findings. This is not a leak-check claim. No world advancement or scale-trip replay was performed, and these checks do not establish Main/GUI acceptance or alter the frozen performance baseline.
