# 11｜场所、人物与情境交互设计 v0.2

**2026-10-01校准：** 本规范继续承接太阁式地点与人物交互，依据三款视频观察（未公开）补充成长、私人基业和江湖组织的现场表现；当前样板门槛见09的VIS01—VIS16。菜单、列表、图卡与独立资料页均可使用，判断标准是语境、层级、可读性与效率，不是控件类型。

**初稿日期：2026-09-09；整体校准：2026-10-01｜项目：汉末行记｜性质：持续有效的交互规范；初稿“尚未实现”仅描述当时，当前已有机制Alpha，新的视觉目标仍待实现。**

> 玩家不是在向游戏系统购买粮食、领取任务；玩家是在一座城里，与某个商人做买卖，接受某个人的托付，回到某个地方兑现承诺。

本文件取代v0.1中允许“设施入口直接调用服务”“任务页直接受领/回报”“公共市场服务不需要在场人物”的解释。保留单机2D、太阁式人物人生、跨平台与网页目标，不改变为3D开放世界，也不取消便利操作。用户已经明确场所与NPC交互的方向；具体场景组合、节奏和数据字段是本轮推荐实现基线，尚不等于用户逐项确认或已通过试玩。

## 11.2 三个方案与选择

| 方案 | 做法 | 判断 |
|---|---|---|
| A 页面套人像 | 保持全局市场/任务页，在顶部加一个掌柜头像和问候 | 不采用。人物不存在仍能正常交易，头像只是菜单装饰 |
| B 2D场所与人物驱动 | 城市总览进入场所，场所内有NPC、物件和通路；交谈后出现当前对象可提供的操作 | **采用。** 场所、人、关系与行为相连，仍可保持高效率 |
| C 全自由行走与生活模拟 | 建连续街道、室内寻路、完整NPC昼夜生活和3D/动作系统 | 本轮不采用。用户要求的是代入感与交互来源，并未要求昂贵的空间仿真 |

采用B不意味着NPC永远静止。人物可以出入场所、临时替班、正在办事、外出或主动找玩家；这些变化通过现有世界时间和事件规则表现，不要求每个人逐秒走完所有路程。

## 11.3 新的基本交互规则

**外部事务：人物所在 → 场所/子场景 → 可接触对象 → 对话/观察 → 情境选择 → 一次权威结算 → 人物和场景反馈。**

**个人事务：当前处境 → 本人或自有物件 → 自行动作 → 一次权威结算。** 自宅休息、整理行囊、查看手记、使用已有物品，不为满足“必须有NPC”而凭空插入服务人员。

必须满足六项条件：

1. 场所先存在，服务后出现。进入粮铺先看见柜台和经营者，而不是先出现货物表。
2. 可互动对象有身份与当前位置。已经离城的人不能继续隔空交易；有替班者则明确显示新的在场者。
3. 对话选项属于眼前对象。门吏可以答路和引见，不能替主官任命；仓吏可以验收，不能任意改变合同奖励。
4. 数值面板不是禁用品。商品清单是与这个商人的交易面板，任务明细是眼前这份托付，必须持续显示对象、地点与来源。
5. 结果返回世界。交粮后是验收、回话、信任变化和实际账目，不只有“任务完成＋50”。
6. 出现人物不是强迫交往。路人可以有自己的谈话、行程与烦恼；玩家可以不参与，不把每个人都做成任务入口。

全局快捷入口只保留地图、人物、行囊、手记、图鉴、系统设置与保存等信息/自管理功能。可以设“前往熟悉粮铺”，但它调用合法本地移动并落在真实柜台，不能从任何城市远程打开同一个市场。任务手记只记录已经知道的线索、承诺、期限、地址和联系人，不远程接受未知任务或凭空领奖。

## 11.4 场景组织：用必要的空间建立生活，不堆空房间

### 城市总览

城镇使用具有地理和生活辨识的2D总览或街景。可点击的建筑热点、设施图卡与紧凑位置索引是等价导航方式，可按画面采用并提供触摸入口；不强制新增自由行走。建筑入口、在场人物、路口事件和出城方向各有清楚层级，不把它们全部排列成同质化服务按钮。建筑文字是位置名，不用“购买物品”“领取奖励”代替场所身份。总览上可接触的人物有可辨认形象和短状态，如“挑担的货郎”“正在争执的两人”，而非满城统一感叹号。

### 设施内景

默认一处设施一张主要内景，必要时有一到两个有玩法差异的子区域。街景到内景采用简短过渡；不要求角色必须在每个角落自由行走。NPC位置、桌案、柜台、门和可读物件可以用热点与立绘实现。

| 场所 | 眼前应看见什么 | 主要交往与行为 |
|---|---|---|
| 粮铺/商家 | 柜台、货物、掌柜或伙计、可能的客人 | 看货、询价、议价、交割、询问路况；商家人员也可能有自身处境 |
| 官署 | 门前值守者、前厅办事人员、告示或登记处；内堂有身份门槛 | 通报来意、问差事、受领、回报；任职后参加由人物主持的议事 |
| 酒肆 | 店家、客桌、旅人、短工雇主或实际中间人 | 听闻、交谈、饮食、找活、护送线索；不是全城统一委托中心 |
| 客舍 | 掌柜/伙计、大堂、可使用的房间或床位 | 问房价、入住、打听住客、进入房间恢复；已租房可直接回房 |
| 宅邸 | 门前接待、主人、家人或门客，取决于人物资料 | 请求会面、闲谈、赠礼、举荐、拜师、切磋；不在时有消息 |
| 演武场/军营 | 值守、教习、士卒、训练中的部队 | 求教、请求参加、接受操练或带队职责；先有授权后操作实际单位 |
| 医馆/工坊 | 医者/学徒、匠师/帮工、正在处理的工作 | 诊治或委托、报价、取回；P1提供服务不等于完整职业经营 |
| 渡口 | 船家、泊船、货物、等候旅客 | 问航程、费用、通行状况、订运与登船，不按抽象按钮瞬间过河 |

“门吏、主事、仓吏”等在本文件中是便于讨论的职责称呼，不作为已经考据通过的汉末正式官号。正式剧本仍单独核对称谓。

官署不是必须拆出门房、前厅、内堂、仓库四张完整地图。第一张前厅场景可以同时呈现接待、告示和办事桌；只有通行权限、交接流程或事件需要时，才增加独立子场景。粮铺也不要求先点伙计、再点柜台、再点掌柜才能买一份粮。

## 11.5 一个完整示例：受领购粮，不再打开任务系统

以下人物、对白和事件为原创体验样例，不是已制作内容或史实记录。

### 初次来到官署

玩家在城里看见官署，点击进入门前/前厅场景。门吏正在与一位送文书的人说话，右侧有人翻看新贴的告示。玩家可询问、查看告示、离开；不会无条件获得本城所有未公开任务。

门吏对初来者说：

> “办什么事？若是问公仓雇人采买的事，去前厅找当值的陈主事。内堂今日有议事，闲人不便入内。”

这次答路只是公开指引，不因玩家点击一次问候就单扣半日、增加信任或抽取新随机事件。已有通行资格的熟客可以直接前往前厅；有人物拦阻或新事件时，捷径也必须停下。

### 查看告示与受托

告示明确写发布方、任务目的、受理位置和时限性质。查看后在手记留下“公仓采买——前厅当值主事”，不是立刻把650钱加到背包。

玩家与陈主事交谈：

> “仓里还缺十份粮。经费六百五十钱，八个半日内送回。按这份约定，办妥后余款归你，另付八十钱。”

此时才出现属于这段交涉的选择：“问清交货处”“询问经费约定”“我接下此事”“暂不应承”。任务详情作为对话中的契约摘要展开，明确数量、期限、结余、公款归属和失败责任。

接受后开始1半日受领行动：先预留组织预算但不增加个人可用资金，完成时建立生效合同并转入任务钱包；若完成前授权主体失效，则释放未付预算并说明受领未成立，不留下有钱无合同或有合同无经费的半成品。合同发令主体是组织，当值人物是经办人；私人承诺则绑定委托人本人。两者不能混同。

### 去粮铺采购

玩家离开官署，进入粮铺。掌柜在柜台后清点账目，伙计搬着粮袋。掌柜说：

> “买粮还是出货？往东的路今早来了新消息，走远路前最好打听清楚。”

点击“看看粮价”显示当前商家的交易层：对象、地点、货物、价格、数量、载重和支付来源仍然明确。原边际价格和资金归属规则继续使用，不因加入对白就换成固定收益。

掌柜知道玩家以前按约送达过一批货，才可出现“上回你守信，这次给你些便宜”的分支，并通过已有信任/折扣规则产生实际影响。陌生人默认能正常买粮，不需要先送礼刷好感才能使用基本商店。

成交后掌柜确认账目，伙计开始装货。时间、钱和货物已经由同一次规则结果处理；人物动作只是表现，不能在动画结束时再发一批粮。

### 回报与交付

合同中写明“前厅收货”，第一体验切片让当值主事同时办理验收和回报，不强迫为了十份粮跑三个房间。若后续任务明确由仓吏收货，实际货物先入仓、形成收讫凭据，再向经办人回报；这是一项预先告知的任务差异，不成为每个任务的机械仪式。

陈主事根据结果回应：按期、迟到、货不够或经费有问题各有实际评价。完成后他可能记住玩家、介绍下一位可接触人物；这不代表所有人都自动喜欢玩家。玩家可以退出这段关系继续经商，不被强行绑进唯一剧情线。

## 11.6 NPC不是功能图标：最小身份与可用性

每个可交往人物必须有稳定身份。可先显示职务/称呼，认识后再显示姓名；不要求每个路人都是历史名人，也不要求每位伙计都有大型专属剧情。

| 层次 | 必需信息 | 制作边界 |
|---|---|---|
| 重点人物 | 稳定ID、形象、身份、当前目标、关系、位置、事件与记忆 | 沿用P1的20名重点人物预算 |
| 常驻服务/普通具名人物 | 稳定ID、可识别形象、岗位、在场状态、语气、少量情境反馈、相关关系 | 可使用轻量规则，不必拥有重点人物所有AI；从原80名具名人物预算分配 |
| 临时来客/路人 | 一次事件内稳定ID、出现原因、位置、可交谈内容、离场规则 | 记入经历的再次出现者保留身份；纯背景群众不计为具名人物 |

不以“每家店都加三人”擅自扩大正式人物承诺。下一体验切片先做约7—9名真正有分工的人物，采用既有功能角色槽；正式姓名与历史映射不在本文件冒定。

人物可用性为在场可交往、正在服务、暂时不接见、离场、出征、被俘/死亡等已有状态的场景表达。人物位置仍只有一个权威来源，不另复制“界面NPC”和“世界NPC”两份互相矛盾的数据。

**服务连续性与人的存在分开处理。** 掌柜出门，已安排的伙计可以普通买卖，但无法做只有掌柜可授的引荐或大额特殊承诺；经办人调任，组织任命的接替者可接收公事，但不继承前任私人友情。没有在场授权人员时给出营业时间、等待、其他商家或留言途径，不让无形系统继续服务，也不让一次随机离岗锁死全部生计。

已经开始且被双方接受的一次交易/会面占用参与者，世界AI不能在结算中途将他派去远方。换班在稳定边界发生；新交谈重新检查在场者与权限。

## 11.7 委托的出处、传播与验收

一个完整任务需要区分：为什么有人需要这件事、谁负责任、玩家如何知道、在哪里谈妥、向谁交付，以及谁授权付款。

| 入口 | 发现方式 | 成立和回报 |
|---|---|---|
| 直接委托 | 眼前NPC主动提及或玩家询问 | 本人或获授权经办人说明条款并受理 |
| 公示任务 | 场景里的告示、文书或登记墙 | 署名与发布组织可见；按公告去受理人处，或按明确的公开悬赏规则办理 |
| 正式主命 | 有实际主持者和参会成员的议事场景 | 按任职资格领命，向上级或合法代理回报 |
| 转介消息 | 酒肆店家、熟人、路人提供线索 | 先获得消息，不自动形成已接受合同；去真实发令人处确认 |
| 送达文书 | 信使实际接触、留在住处、或合法驿递 | 文书有发信人、收信人和送达时刻；不无条件全世界即时联系 |
| 环境事件 | 进城、出门、探访或路途中遇见 | 现场人物与事情成立，拒绝或不理睬也有合理离场 |

公开告示并非一律只能“看”。若告示明确是常设公开悬赏，可在当地物件上记录应承/领取凭据，合同效力来自发布方的预先授权；付款仍在公告指定的验收人/设施完成。需要预支经费的Q04不采用无人告示直接领款：必须由授权人员受理。不是把任务墙换个样式后继续做无来源自动提款机。

P1继续使用既有任务状态机；新增发现记录位于TaskOffer而不是把所有已知线索立即塞进Active。已发现不等于已经承诺；看到别人的任务不等于有资格承接；失效、撤回和被他人受领会通过源头、告示变化或已送达消息表达。手记保留来源和最后确认时间，不伪装实时掌握世界所有变化。

## 11.8 城中事件与生活痕迹

不是每次进城都弹随机奖励，也不是只在地图旅行时才有事件。新增触发位置覆盖城市入口、设施入口、交谈结束、交易之后和正式世界时间推进之后。沿用现有18个事件预算，优先重新安排其中事件的出现方式，而不是另外承诺几十条支线。

事件分三类，只有后两类需要明确结果交互：

- **环境片段**：伙计搬货、店家与客人谈账、前厅有人等候。体现当前场所状态，不强制暂停，不给无因奖励。
- **可参与的短遭遇**：问路、争执、寻人、收到谢意、熟人打招呼。玩家可接近、旁听或离开；消息和关系变化有真实来源。
- **条件化剧情**：受托商队受阻、师傅约见、旧主命追问、人物离任。使用真实人物、任务和世界状态，重要选择有可追踪后果。

例如，进入粮铺时看见掌柜与车夫争论迟到。旁听得知道路受阻，找车夫谈可获得带时间的消息，再决定绕路或帮助。这可以成为既有E01—E03粮约链的入口；不能为了演这场戏临时把已经到达的货车重置成尚未到达。

### 触发与重复规则

候选绑定实际city/place、tick、访问序号和参与者状态。一个城市同一游戏半日首次有效到访可选一次非关键遭遇，结果缓存；在同一半日反复进出不重抽。纯浏览同一场景不抽随机、不改资源、不刷关系。普通片段不连续拦住玩家，单次访问最多一个强制阻断的非关键事件；危及人身/任务的关键事件保留优先级并提供理由。

新半日才允许按冷却重评。触发后被记入的人物与承诺必须进入存档。重复加载、跳过对白或切到后台不能再领取一次结果。原有§6.5的全局事件队列排序继续适用，场景节流是更严格的展示上限，不取消紧急事件。

### 与原18事件的落点

| 原事件 | 场景/人物承载 | 不变的前提 |
|---|---|---|
| E01—E03 粮约 | 粮铺掌柜、在途车夫、经办人的后续交涉 | Q04未清算；实际运货仍受阻；不把已到货商队重置 |
| E04—E06 师承 | 教师所在学舍/宅邸、试炼后的复访 | 教师可用、试炼事实和正式报告，离场保留证明 |
| E07—E09 任职 | 推荐者当面引荐、官署议事、独立考核后的正式回报 | 信任、已完成任务类型和领队资格，不提前赐予全军权力 |
| E10 寻人变故 | 宅邸接待者/约定接收人的消息 | 送信对象实际离开，不能把私信交给无权陌生人 |
| E11 渡运中断 | 船家与渡口停航告示 | 同一真实封路对所有人有效，等待依旧耗时 |
| E12 路遇索财 | 当前路段的遭遇人物 | 已保存的路遇抽取和队伍所在，不改为城内随机扣款 |
| E13 商铺断货 | 店员在铺内汇报，或既有合法报信途径 | 实际连续缺货，需补货而非对话后凭空恢复 |
| E14 粮价与乡里 | 粮铺价格变化、居民求助、乡里告示 | 库存持续低于阈值，救助转移真实物资 |
| E15 被俘出路 | 看守、交涉人、送达的赎回消息 | 被俘事实，保留原无钱释放途径 |
| E16 旧主不在 | 原驻地接管者、明确送达的公文 | 组织灭亡/发令主体失效，调用原公物清算 |
| E17 地方归附 | 实际负责人和使者的会谈 | 外交权限、真实保护/供给提议 |
| E18 行历回顾 | 本人翻阅行旅手记 | 真实12据点见闻和6次交往，属于自主回顾，不强塞NPC |

不得一律改成“任务页出现新红点”。上述映射仅改变发现与呈现，不改变原18事件的事实条件。

## 11.9 节奏：不把代入感误写成繁琐手续

地点与人物决定可以做什么，但重复问候与展示不是新的收费项目。

| 行为 | 时间与收益规则 |
|---|---|
| 看场景、读已知信息、展开已知货单 | 不耗时，不加关系/技能，不抽玩法随机 |
| 城内相邻公开场景切换、普通指路 | 不额外扣半日；通过正式本地移动/观察入口更新必要位置与发现，不能以UI参数伪造到场 |
| 新的一次闲谈/探听/请求引荐 | 沿用实质会面1半日，确认前说明；有新信息或关系结果 |
| 买卖、客舍入住恢复、短工 | 各自按原行动耗时，前置问候与确认并入该行动，不另加一次会面费 |
| 接受有经费的正式委托 | 本版明确为一次1半日受领，完成时授权合同和预算；期限由受领完成时刻起算 |
| 交货/回报 | 合同规定一处办理时合并为原1半日交付；明确分两处的合同预先说明时间，不临时加跑腿 |
| 等某人回来 | 选择等待才推进时间；返回按钮本身不等待 |

上述Q04原算例的本地2半日/外城6半日仍从“已受领预算”起算；本版受领动作的1半日属于前置，不悄悄从8半日合同期限中扣掉。普通窥看或取消受领草案不算承诺，不扣款、不生成任务。

第一次交易可以有简短介绍；熟客进入柜台后可直接选“照常买粮”或“看看货”，保留人物与场景但省略重复开场。允许跳过已读对白，重要的新条件仍需显式确认。小额普通交易无需关系门槛；长线关系只影响确有意义的信任、信息、条件和机会。

全局“结束半日”不作为日常每做一件事后的必点按钮。玩家确认后自动完成该行动的正常结算与反馈；长旅行、长修业和事件中断继续保留停止点。这个变化属于表现/推进控制的修订，不更改一半日只结算一次的规则。

## 11.10 数据与模块契约：不能只在UI上藏按钮

### 新增或明确的数据

| 记录 | 必要字段 | 作用 |
|---|---|---|
| PlaceDef | id、settlement_id、parent_place_id、scene_id、passages、admission_rule、npc_slots、prop_ids | 哪个地方、与何处相通、谁能进入、场景怎样组织 |
| 人物在场信息 | actor_id、place_id、role_assignment、availability、visible_activity | 从既有人物状态派生在场；岗位与本人分开，显示者必须是真实承担该岗位的人 |
| RoleAssignment | role_id、organization_id、actor_id、allowed_services、valid_from/to | 当值代理能代表谁、能办理什么，不把岗位当作永不缺席的假人 |
| PropDef/State | id、place_id、kind、owner_or_issuer、interaction_rule、linked_offer_ids、revision | 告示、案卷、柜台、床铺的来源及用途 |
| TaskOffer补充 | issuer、publisher、discovery_source、acceptance_target、report_target、funding_authority、acceptance_mode | 区分看见、接受、验收与付款；人物调动不无因抹除组织合同 |
| InteractionContext | player_actor_id、place_id、target_kind、target_id、provider_actor_id、role_id、observed_revision | 对话和动作针对谁、在哪里、由谁合法承接 |
| InteractionSession | id、context、stage、shown_node、pending_command、visited_topics、result_ref | 保存正在接触的人/物及选择；不是另一套经济规则 |
| 发现记录补充 | source_actor_or_prop、observed_tick、last_known_place | 手记中的消息与地址有来源、有时效 |

Settlement位置增加place_id作为互斥位置结构的从属字段，不另造第二份独立坐标。在道路/战斗/被俘状态下不允许残留可用于交易的店内位置。纯镜头移动和面板切换不改变人物位置；进入场所则走MoveLocal，检查通路、权限与场景事件。MoveLocal不消耗tick，但可更新位置、revision和一次性发现事实，因此它不是“纯查询”。

### 接触到行动的状态机

`SceneReady → TargetSelected → Conversation/Inspection → ActionPreview → ActionCommitted → Result → SceneReady`。

浏览草案可随时退回且无副作用；人物不存在或权限失效返回现场说明和合理替代选项，不自动换成另一人替用户签字。ActionCommitted以后按原动作状态机执行，取消与失败走原清算。没有两个重复结算系统。

### 模块调整

| 模块 | 调整 |
|---|---|
| ContentCatalog | 增加Place、NPC在场岗位、物件及来源引用校验 |
| PersonRules / WorldAI | 输出真实在场、已知关系与合法职责；NPC已接受服务时保持既有占用 |
| 新增InteractionRules | 根据场所、目标、权限与已知事实返回话题/可执行动作；只组装领域命令，不直接发钱货 |
| WorldKernel | 检查MoveLocal与交互上下文，再调用原交易、任务、恢复等规则；不能只信UI说“在商店” |
| EconomyRules / TaskRules | 接收已校验的交易代表/受领人/验收目标；仍是唯一价格、资金与任务结果来源 |
| EventRules | 绑定城市/设施入口和交往事实；处理已保存的候选、取消与节流 |
| SaveCodec | 保存place、必要的交互阶段、岗位、发现来源和事件去重；读档重验正在接触的对象 |
| Presentation | 展示场景、人物、对白、物件及情境面板；不另写一套任务或交易规则 |

错误需要区分NotAtPlace、PersonAbsent、RoleNotAuthorized、AudienceDenied、OfferWithdrawn、StaleContext、SourceUnknown。用玩家能理解的话说明“他今日不在”“内堂不接见”“这份差事已撤下”，而不是显示技术错误码。

单机NPC自主交易也需满足自身地点与授权，但不必虚构一段UI对话。玩家指令必须经交互上下文；NPC规则可直接产生已验证的同类领域命令。这是避免剧情与模拟矛盾，不是联网防作弊，不增加token签名、权限服务器或大型脚本框架。

### 最低内容校验

可受领任务必须具有真实发令主体及受理路径；要预支经费时必须存在授权经办人和来源钱包；交易代表必须绑定存在的商户库存和资金，不同值班者不能复制同一商户库存；岗位接替不能继承私人好感；全部场所至少有离开路径；角色被引用时不得无定义出现。场景变化与关系反馈通过原结果ID执行一次。

## 11.11 视觉修订：场景和人物承担画面重心

这份太阁录屏证明：完整场景、设施图卡、半身人物、对白和精简菜单可以同时存在；人物详细资料、技能列表及小游戏也可进入专用页面。真正需要纠正的是所有系统默认铺成同一种大面板，而不是禁止菜单或要求无缝世界。

默认先回答“我在哪、面前是谁、现在有什么事”。城镇状态区紧凑，设施图卡有原创建筑或器物小画；人员选择以肖像和当前处境区分。进入设施后内景、人物与局部事务构成焦点；对白和动作有稳定位置，避免每句结果增加一行就推走确认按钮。不是所有地点都挂着同一张主角立绘，也不让远处人物像在眼前一样办理业务。

交易货单、军事编组、家产承接可以展开信息密集的专门页面，但抬头明确地点、办理人、产权及事项；取消和完成回原现场与原选择。个人行囊、卡片收藏、自己掌握的知识和手记允许随时查看；查看不是任意地点可交易、拜师、征调或接发主命。

武馆、庄园、山门、军营各自有生活理由和人物活动，不能只换一张背景：武馆围绕传授/切磋；庄园围绕居民、生产、供养和家事；山门围绕门人、传承、职事和组织关系；军营围绕授权、兵员、装备和军令。人事列表可作为对照工具，默认场景应看见当前被讨论的人和物。

画面、输入与规则分工明确：身份相同的人在头像、交谈、家园和战斗中可认；角色有待机/行动及结果反馈，动作播放不结算第二遍。场景环境不能遮住核心文字，界面也不长期盖住全部场所。构图、资产拆分、动作和跨尺寸规则统一见09的9.11—9.12与表现工程规范。

## 11.12 下一次体验样板与完整扩展路线

当前机制Alpha已具备多条真实流程，下一步不重建一座孤立演示城，也不把P1的历史数量预算当作立刻批量生产任务。先在同一青川/东里世界完成以下四条代表路线，保留所有其他人生目标：

1. **生活与冲突样板：** 城镇设施图卡 → 酒肆选择雇主 → 谈妥护送 → 邀同真实车夫 → 地理行旅/路遇 → 连续个人战 → 到场送达 → 回雇主交代 → 再访反馈。同行者在人物列、地图、护卫战与交付时保持同一身份，拒绝护送仍可继续其他生活。
2. **武学成长样板：** 在武馆或师门询问 → 看清资格和代价 → 学得有图像和用途的武功/心法 → 安排修炼 → 配置与切磋 → 观察真实效果 → 向合法弟子传授。课程、所学本领、招式配置与收藏分开，不把学习简化为按钮加经验。
3. **公私经营样板：** 到庄园见管事 → 观察生产和居民岗位 → 调整分工或建设 → 任官受令 → 经明确授权借调私人部曲 → 出征/交割 → 人员归庄、劳动与守备恢复。账目能查清，但画面要让玩家看见谁离开、谁返回和哪处停工；公职不抹掉家园。
4. **长期人生样板：** 家人、门人及已知关系在场景和关系图中连贯表达 → 长期经营/成长 → 合法继任预览 → 选择后继续同一世界。前代官职、私人关系、知识和资产分开承接；不是把姓名换成下一人。

已知护送内容问题必须纳入第一样板：当前先完成送信会隐藏护送话题，接受护送时又显示泛用的已回报文案。后续应修正内容分支与结果语境，并分别验证“先送信后护送／先护送后送信”、初访／再访、进行中／可回报／已完成；不得只重走一次已知可通过顺序就宣布样板完成。

样板范围控制资产数量，不压缩流程质量。每条均检查第一次和熟访、成功和拒绝、缺席、资源不足、取消、读档恢复；操控记录与实际帧必须来自最终同一Godot工程。先完成第一条的画面与输入质量，再扩展成长和家园；最后推广到野战、围城、完整门派、山寨及水上势力。

保留原官署—粮铺采购—城中事件—回报—客舍路线作为IMM回归，不因新样板而删除。所有新表现使用已有规则与存档，必要的新机制明确立项；不再使用独立HTML规则壳或自动判胜演示替代正式游戏。设计样板图、真实运行图和完整内容交付分别标识。

## 11.13 新增验收：IMM01—IMM16

下列是设计验收要求，不是本轮已经通过的游戏测试。

| ID | 场景 | 通过标准 |
|---|---|---|
| IMM01 | 首次进入粮铺 | 进入可辨识场所，看到在场交易者；不是全屏无主体商品表 |
| IMM02 | 选择不同在场人物 | 话题、职责和权限不同，门吏不能任命、伙计不能替掌柜引荐 |

| IMM04 | 初次发现购粮委托 | 对话或有出处的告示形成已知线索，未知任务不从全局手记凭空出现 |
| IMM05 | 告示受领与资金 | 常设悬赏遵循公告授权；需预支的Q04必须经办人受理，不凭读告示加钱 |
| IMM06 | 当面交货 | 在合同地点由合法验收者处理一次货物、评价和奖励；远处任务页不能代办 |
| IMM07 | 熟人再访 | 对实际已发生的承诺、交易或共同事件作出恰当反馈，不只重复陌生问候 |
| IMM08 | 街头事件 | 当地人物/物件承载事件；可不参与；结果影响真实消息、关系或处境 |
| IMM09 | 重复进出与加载 | 同半日反复进门不重抽事件、不刷钱或关系；保存恢复保持人物与来源 |
| IMM10 | 日常操作效率 | 熟客可直接进入真实柜台并选交易；不强制看长对白或逐人通报；新条件仍确认 |
| IMM11 | 时间合并 | 问候＋买粮合计原1半日；受领完成起计期限；本地导航不重复扣半日 |
| IMM12 | 自主行为例外 | 看手记、整理物品、已租房休息不需要凭空找NPC；不借此开放远程外部服务 |
| IMM13 | UI绕过校验 | 即使直接提交命令，异地/缺人/无授权也被核心拒绝，不只隐藏按钮 |
| IMM14 | 人物替班与公私关系 | 合法代理接公事，不继承前任私人好感；原人不因此分身 |
| IMM15 | 短工和住宿 | 雇主提供真实工作与报酬，店家/房间提供住宿；场外无因“+80”或客舍回血不可用 |
| IMM16 | 体验回访 | 试玩者能说清去了哪里、见了谁、为什么替他办事、发生什么变化；不是只复述页面和收益数值 |

自动化测试检查地点、权限、资金、占用与恢复；人工试玩检查在场感、人物可辨识度、对白语境和重复操作负担。两者分别报告，不把规则正确当成代入感达标。

## 11.15 2026-10-01补充：可轻松度过的日常与有个性的小愿望

本节至11.18为获准吸收的设计与工程合同，尚不是当前Alpha的完成声明。保留有后果的战争、经营和政治事业，同时让普通生活本身有可选择的乐趣；不能只把“不打仗”表现为无事可做，也不把每次出门都改成紧急救援或每日打卡。

- 访友、小酌、观景、读书、切磋、制器等可以有场景与人物反馈；并非每项都必须发稀有物品、涨能力或接出长任务。具体文化活动及器物由内容作者作时代/地域校准，原创内容明确标记
- 人物可想学会一项小技艺、与友人相聚、完成一件习作或重访熟地。愿望必须有真实持有人、来源、对象/地点、可实现条件和结束理由；不是从全局任务池随机贴到任意NPC身上
- 个性影响选择偏好、表达、取舍及愿意付出的代价，不直接替代合法性。守信者可以顾念约定，固执者可以坚持作品，乐群者倾向访友；同一人仍受健康、钱物、岗位、承诺和他人意愿约束，不能为了演出强迫他人参加
- 小愿望沿06的`NpcPlan`及现有活动执行，不另建只为画面运转的NPC。常驻服务人员可以在空闲时参加，已有服务与职责优先，合理替班仍走正式岗位授权；重点人物、普通具名人物使用不同内容深度，不扩大既有人物数量承诺
- 未承诺前可忽略或婉拒；愿望可暂缓、自行满足、改变或自然结束。已经接受的约定才按所属承诺规则处理取消/失约，不能为拒绝普通闲谈扣全局声望，也不能反复弹出同一愿望强迫玩家接受
- 自己完成、邀人合作或求助玩家是不同路径。NPC可在真实空闲与资源条件下自行完成，玩家后来只通过本人反馈或合法消息得知；不会因玩家没点开而一直冻结，也不因远处完成立刻全地图播放庆祝

愿望定义声明对应已注册活动、触发事实、优先级/个性权重、有效窗口、重试/冷却和单人活跃数量上限；实例保存产生来源、当前阶段及计划/结果引用。进入、完成、条件变化和到期才触发必要重评，不每半日给全体人物刷新一组愿望。重复进门、送同一礼物、读档或跳过对白不能重复领同一结果。愿望与普通生活可以无硬期限，不能统一套成快到期的任务提醒。

**生活时间预算也要可预见。** 活动确认前说明真实时耗、费用、参加者及与已知约期的冲突；可选择这一段时间只修业、游历或照看住处，并按02的有限自动范围执行。已经发生的兵灾、断路、缺粮和责任仍生效；靠有界机会/通知、合理职责交接和低风险活动内容留出闲暇，不靠冻结敌军、隐瞒已到达坏消息或凭空免除生活成本。已有合法住处和物资时，例行吃用按正常账目结算，无须每日反复点击相同吃饭睡觉按钮。

## 11.16 寻人、留话与预约：减少扑空，不取消距离

| 玩家入口 | 规则合同 | 对象不在或情况变化时 |
|---|---|---|
| 查看已知去向 | 查询03的知识记录，显示最后确认地点、原事/获知时刻、来源及可信度；公开营业/接见安排与私人行踪分开 | 未知明确显示未知，过期不自动刷新为真实位置 |
| 当面问去向 | 从当前可接触的门人、同僚、店家或熟人询问；只返回对方知道且愿意透露的信息 | 对方不知道、拒绝透露或只知旧消息均是合法结果，不凭空收取“保证找到”费用 |
| 留话/留拜帖 | 由实际接待者或允许投递的物件接收，记发信人、收信人、内容类别、留置地点、接受者和投递状态 | 收下不等于本人已读，更不等于同意会面；本人返抵/信使送达等已注册条件满足后才获知 |
| 请求/接受预约 | 由本人或具有约见权限的代表答复，说明地点、开始窗口、需要完成的事项、预计占用、费用及取消规则 | 冲突、拒绝、待答复、改约、错过、履约/违约原因保留；代表不能承诺其无权安排的私事 |
| 按约前往/等候 | 形成可选的导航或等待意向，按正常路线与半日推进；约期提醒引用已接受窗口 | 不瞬移双方，不静止对方直到玩家来；等待可随时停止，离开本身不偷扣等待时间 |

普通公开指路沿11.9不另扣半日；查阅已有信息免费且不产生收益。新的一次实质探听/协商仍按会面1半日或已注册的专门活动耗时，事前显示。问候、约下一次会面和留下一条简短拜访信息可作为当前会面的记录步骤，不另计一次会面费；独立投递仅在定义明确支持零时长受理时允许，不能同时免费获得关系、秘密、答复或实质教学。邮递费用和时间由实际服务/信使承担，不能因UI写着“留话”就远程即时传送。

**状态所有者。** 交往/预约领域拥有`Appointment`和`MessageDelivery`的约定与投递状态；只引用原人物、地点、服务授权、计划、动作与结果。预约字段至少包括参与者、发起来源/受理权限、请求与答复状态、最早/最晚开始、必须完成时刻（如适用）、实际占用时长、取消/改约条款和唯一结果。留话字段至少包括发送/目标人物、保管人或物件、留置/送达tick、获知记录引用、投递方式和当前状态。对外承诺统一暴露`CommitmentRef`，知识只记录本人已获知的部分，不复制另一套人物当前位置、库存或关系。

“待答复→接受/拒绝/过期”和“已接受→履约/取消/改约/失效”的变更必须有真实来源；改约生成可追溯的新条款和答复状态，不能覆盖原条款使玩家过去看似失约。提出改约本身不取消原约，只有新条款获有效接受或原约按已定规则失效后才改变有效约定。给双方发送变更消息遵守真实送达，世界中约定已失效与玩家何时获知分别记录。人物死亡、被俘或岗位失效按所属规则清算，不能复活、瞬移或假扮本人回信。

预约不从接受起长期占用人物；开始前由计划检查其未来窗口，真正会面再取得双方主要行动占用。已接受承诺限制可接受的冲突安排，临时紧急职责若迫使失约则留下明确因果；不能让两个已接受预约在同一时段各自宣称独占同一人。

## 11.17 便利入口与规则网关合同

以下是目标接口语义，名称不是宣称当前已存在的函数。新增能力先登记作者描述和验证规则；内容若引用尚未实现能力，须明确报错，不能只靠UI按钮或通用`set_field`实现。

| 接口/状态 | 所有者与返回 | 不能做的事 |
|---|---|---|
| `known_whereabouts(observer, subject)` | 03的知识查询返回来源、时刻、可信度与可公开访问入口 | 读取真实坐标伪装成最新传闻，或浏览时更新获知时间 |
| `available_topics(actor, context)` | InteractionRules汇总该真实人物的全部有效岗位/私人话题，再投影可见性、预览入口及不可用原因 | 按人物去重后丢掉其他岗位服务，或把私人友好变成公职授权 |
| `preview_visit / preview_appointment / preview_leave_message` | 对应领域给合法来源、耗时、费用、窗口、参加者及失败原因；提交仍走统一命令网关 | 预览占用人物、送出拜帖、隐式预约或收费 |
| `preview_convenience_plan` | 应用层组合已知导航/办事步骤与02的有限时间/资源预算，引用原领域报价 | 复制规则计算器，或把计划列表当成已经成交/履约的事实 |
| `resume_activity / cancel_activity` | 行动所属领域检查稳定边界和保留/释放清单，返回实际已用、可退、剩余及阻断原因 | 关闭窗口就丢掉动作、退款或抹除承诺 |
| `explain_known_result(observer, result)` | 03的已知经历投影提供可知结果、原因与证据引用，UI组装场景反馈和手记 | 暴露未送达报告、他人秘密动机、真实隐蔽兵力或未获知的资源变化 |

熟客可在真实场所点实际柜台直接打开货单；重复交易仍使用当前商户、在场代理、市场报价和原子钱货结算。选择“按上次办理”先展示当前差异，若超出已接受价格/数量/对象/预算范围即重问；不把旧报价、已离任代表或旧授权长期缓存成永久通行证。

熟路入口、手记“去拜访”和人物列表导航只生成行动意向。已知城内捷径照常核验门禁与通路；城际快行沿02逐半日计时、付费、承受风险和处理中断。到场、换班、缺席或途经新事件后保留当前地点和人，不跳到一个无来源的全局服务页。

自动办理当前事务与委任别人办事分开：前者使用本人实际时间与占用，后者走04的`MandateInstance`及`AuthorityGrant`，由真实受任者行动与报告。自动结果用同条件正常基线，不再追加惩罚；手动小游戏的优秀奖励仍受原最多120%边界约束。便利设置不增加伤亡、损耗或隐藏关系惩罚，实际风险、资格、材料和权限也不因自动而免除。

## 11.18 手记解释、场景验收与实施边界

手记先回答“我知道什么、为什么、何时得知、接下来可去哪里做什么”。至少可以按人物、地点、承诺、活动检索已知记录，并从已知条目返回原人物/场所、合法路线或对应预览。它可以展示列表和关系图，但所有入口使用11.17的查询与命令，不成为远程任命、收款、传艺或全知寻人的控制台。

- 结果摘要分出已经发生、听说/推测和未知；重要拒绝、迟到或中断给可知原因、相关约定/费用及下一合法选项。只有“对方没有透露理由”的信息时如实显示，不解释其隐藏性格或秘密命令
- 新本领/升级提示显示来源、实际掌握变化和现在可用的动作入口；默认短反馈并收入手记。需要改变后续计划的真实选择才按02中断，普通成长不逐半日强弹
- 普通生活与已承诺事项分开呈现优先级，未承诺邀请可略过；同一已读片段和未变化状态不反复催促。关闭摘要不漏结算，重复打开不重奖，重要事件只在玩家合法获知后提示
- 展示状态可保存筛选、选中人物和阅读位置；世界真值、知识来源、预约/投递和结果去重仍归所属领域。被删除或失效的引用有可读历史说明，不能展示一个可点击但可绕过资格的旧入口

当前`241a0da`的只读核对：`WorldKernel.submit`已有版本化原子提交；`InteractionRules`已有在场/岗位/占用校验；`TravelRules/JourneyCommands`已有真实行旅与暂停；`LongRest`已有逐半日消费与取消；`SocialRules`已有有限当面往来和来源记忆。尚缺这里要求的统一愿望/预约/留话、通用计划预算与通知策略；`CultivationRules`目前在课程末一次写成长和疲劳，不能当作分段修业/退款恢复已经完成；自动赶路和休整仍有各自UI驱动。已有代码、待实现合同与实际引擎试玩须分列，本文修改不算功能测试通过。

以下情景补充IMM/VIS与02§2.15，后续以正常输入、状态差异、保存恢复和至少两份人物/活动配置举证：

1. 两位性格不同的具名NPC有不同小愿望，能独立择时或寻求合作；玩家不参加仍可继续生活，承诺后取消才产生有来源的具体后果
2. 教师不在，门人只给带日期的已知去向；玩家留拜帖后先显示待送达/待答复，经真实回复形成预约，再按实际路线抵达。教师同时受命外出时改约/失效消息不瞬间泄漏，也不制造双重占用
3. 熟客买粮、熟路前往、重复修业分别减少重复操作；地点、办理人、费用、实际日期、获得资格与风险同手动流程一致，不以一键完成跳过新条件
4. 一段低风险生活含访友/休息/修业与NPC自行活动，不被普通进度和升级弹窗反复打断；真实路遇、越界费用或已到达紧急变更仍在稳定边界停下
5. 预约待答复、已接受、改约待确认、动作暂停、消息未送达/已知、普通结果未读分别存读；无重扣、重奖、重投递、无知者提前知情或旧条款被覆盖
6. 连续真实场景能看清去过哪里、见到谁、为何没见到、留了什么、约定何时及下一入口；记录重复确认/无效往返及强制打断次数，与旧流程同任务比较，不用规则测试数替代操作成本与生活感验收
