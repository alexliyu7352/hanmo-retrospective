**基线：总体设计第7、9、16—19章；2026-10-01整体修订。原决策I32、I40—I45及P1/P2预算保留历史身份。当前Alpha已接最小NPC社会、庄园、公私联动和战争；完整治理、组织社会及内容仍按各自目标验收。**

以下原效用、规模、收入和难度公式是历史平衡候选，不替换当前已验证核心。社会、经营和事件仍用一个人物/时间/资产来源；本次补足持续生活和可见反馈，不能将功能字段或宣传片镜头当成社会模拟通过。

## 6.1 NPC行动，而不是装饰性日程

每个具名人物具备`role, personality_tags, goals, needs, knowledge, main_action_id, home, affiliation`。需要与目标取有限枚举，不先构建通用规划语言。20名重点人物增加专属事件和目标；其余60名也有真实所在地、工作和资格。

调度：人物已有行动继续执行，只有空闲、行动失败/结束或重要处境变化时选择下一行动；每半日最多一次决策。行动候选包括执行职责、休息、旅行、交易、学习、访问、等待。不可用动作在评分前排除，不通过高评分突破资源/位置限制。

初始效用`U=职责紧迫度(0—50)+个人目标收益(0—25)+关系动机(0—15)+性格契合(0—10)−时间成本(每半日2)−资源负担(0—20)−风险(0—20)`；最高分且>0才执行，否则休息/等待。同分按行动编码，必要的少量性格扰动在进入决策时取world流一次并保存，界面刷新不重选。

出征、被俘、受伤和主要任职职责具有硬限制；师傅已接受课程便不能又自动去另一城购物。NPC听到的情报与玩家一样有来源时间，不能直接读敌方未来命令。调试记录保留“被排除原因、前三候选、选中原因”，不把整段内部评分强塞给玩家。

### 经济与职业生活

NPC交易使用同一个市场接口与真实个人/授权组织钱包；缺钱可以工作，不能无限生成自己想买的装备。组织公款、日常民間工资与供给等合法来源显式标记，P1不维护全体平民实例。NPC岗位服务不要求每位摊贩都有完整历史人物AI，但必须有稳定身份、真实在场与岗位授权。公共市场资源可在后台合并核算，玩家面前必须由实际在场的商人/伙计办理；设施服务实体不得替代人的存在。

在野人物优先满足休息和生计，然后按专长访学、交游或求职；士卒/官员优先履职但保留期限内自由时段；商旅人物在有正预期净收益且足够运力时选择贸易。行商只使用其已知行情，不能总是精确追着玩家刚制造的价差瞬移。

## 6.2 区域势力决策

组织状态包含负责人、据点、主要成员、现金/粮草、编制、外交态度、守备底线、已批准行动、下一决策tick。每6半日评估一次；战争结束、负责人更替、据点归属变化时提前一次评估。常规月议事另外处理成员主命。

决策顺序：处理负责人/组织有效性 → 满足现有军队口粮 → 保持据点守备 → 恢复/招募 → 指派民政与采购 → 决定军事行动。P1每组织最多2支外出军队，不能把所有人征空。军事发起需要预计可支持至少6半日供给、出发后每控制城市守军≥100、已知可达道路和获授权将领。

出击目标评价：明确争议或防卫需求+50、预计局部优势≥1.4倍+20、道路价值+10、供给不足直接禁止。优势比较用05统一战斗参数，不凭空读取隐藏敌军；未知兵力采用已知报告和保守估算。失败后至少6半日整补，不每个tick重生一支全新军队。

P1支持真实行军、野战、护送、巡防、道路封锁、协商停战和政治归附；**不把未制作的攻城变成自动城墙伤害**。普通野战胜利改变部队、道路和谈判处境，不直接改城市归属。在旧P1预算中，归属变化通过符合条件的政治事件发生。当前已提前接入最小围城/节点作战/占领，必须依据05及现行战争事实处理；完整征服、治理与历史战役仍另行验收，不能再用旧P2标签禁止现有攻城机制。

这是对区域切片边界的明确化，不是取消完整产品的动态战争、灭国和统一目标。P1中“统一区域”只可来自实际归附结果，并且仍称区域结果。

## 6.3 世界资源更新

据点公库与民间市场分开。P1世界AI最低字段为公共现金、粮、可招募人数、守军、治安/民心；不开放玩家城郡治理界面。月度收入与补充从`production_profile`产生，记录公共生产/税收，而非按AI缺多少就补多少。

征募一次最多20人，必须从可招募池扣，每人招募费40钱；训练、装备和口粮另有真实来源。每月可招募池恢复为当期人口允许的上限，未到月末不因为重开面板恢复。P1回补上限依据据点配置；P2切换人口模型后按人口与治安计算，不并行运行两套补兵规则。

普通难度不隐藏增加AI资金或偷看玩家计划。后续高难度若增加资源，只用明示倍率，记入难度设置并可在报告中查出。

## 6.4 事件数据契约

`EventDef`至少含id、scope、priority、window_start/window_end、conditions、participant_slots、location_constraints、choices、effects、cooldown_ticks、once_policy、fallback、text_keys。scope为world/actor/task/organization之一，一次性标记以`def_id + scope_instance_id`建立，不使一次粮商失约封死以后所有角色的同类事件。

条件只允许比较数值、检查存在/状态/标签/归属、AND/OR组合；效果只允许调用已定义的资源转移、关系变化、启动任务/行动、赋予卡片、改变事件标记、设置到期修正。禁止在内容中塞可执行脚本，主要是保持可校验性和存档可信度，不建立庞大内容脚本平台。

参与者槽分`fixed_actor`和`eligible_group`。专属人物事件不可把死者自动替换成陌生人；普通职务委托可以在同职责、地点、资格条件下换合法负责人。选择结果不得创造本不存在的货物账本。

## 6.5 事件生命周期与冲突

`Dormant → Eligible → Queued → Presented → ChoiceCommitted → Resolved`；条件失效可走Cancelled或预设Fallback，后续连锁事件重新按自己的ID进入队列。

入队和展示前各检查条件。普通同一tick最多展示3个非关键事件，其余保留；紧急战斗/人身危险/任务即刻失效优先，不丢弃。排序为优先级降序、进入时间升序、事件ID升序。选择触发的新事件最早下一次稳定边界展示，禁止同一调用栈无限自触发。

事件必须有合法来源：当地人物、场景物件、已送达文书或本人回顾。场所入口及再访按11做每城市/半日缓存与单次非关键阻断限制，避免进出门重抽。事件展示期间世界时间停住，不需要现实线程锁；参与人物有当前交互占用，不能被同一条选择重复启动另一项互斥会面。选择需要1半日就创建明确行动，先显示时间与费用，不在对话文本中偷偷推进。

提交选择先重验费用与硬条件，原子执行结果并写入choice_id/settlement_id。若主体已无效，显示原因和配置好的退化内容；不能移花接木使用原来的按钮位置执行另一选项。

## 6.7 历史倾向与沙盒

历史倾向仅提高符合真实前提的已审校事件权重，不能改写既有死亡、俘虏和归属事实。自由沙盒关闭强方向性权重，保留相同日常任务、经济和人物规则。

正式史实事件额外带`source_refs, historical_assertions, adaptation_notes`。未完成出处审查的事件不能作为历史事件发布，仍可明确标为虚构支线。190年只是总体设计的剧本锚点；本详细设计不编造同一天80人的真实部署。

## 6.8 公职治理：保留完整规则与历史P2参数

玩家成为城郡负责人后开放预算与委任，不让基层开局直接操作。`CityState`增加人口、生产劳力、可征募池、治安、民心、田地/工事级、税率政策、整合剩余tick、岗位任命和公共仓储。

月初总粮产`floor(生产劳力×田地产率×季节_bp/10000)`；先满足配置的民用留粮，再按政策分公共征收和民間市场供给。**采用人口模型时替代P1对应生产补充，不重复添加**。货币税基由城市配置的民間税源×政策倍率计算，不从玩家私人钱包扣。

税政三档：宽免=基准70%收入、民心+3；常赋=100%、民心不变；加征=125%、民心−5、下月税基−3%。税基连续调整设50%—150%界限，恢复依安民与常赋而非保存加载重置。未稳定占领期收入50%、禁止征募，持续20半日。

| 委任 | 耗时 | 费用 | 前提与效果 |
|---|---:|---|---|
| 农政 | 10半日 | 公钱300 | 农政≥1，完成后田地产率+2%，同田级累计上限10% |
| 安民 | 6半日 | 公钱120、粮10 | 民心+`3+礼学级`，不超过100 |
| 巡防 | 6半日 | 公钱100、授权步卒20 | 治安+`3+兵法级`，部队和领队被占用 |
| 修缮 | 8半日 | 钱200、木10、铁2 | 筑城≥1，恢复城防100，最高为已建容量 |
| 征募 | 4半日 | 每人40 | 扣可征募池，生产劳力随出征人数下降 |
| 训练 | 4半日 | 钱150、真实口粮 | 训练+`3+对应技能级`，上限100 |

每项委任复用TaskInstance、人员占用、进度与取消清算；玩家可亲做但不额外获得免费时间。委任者离职/死亡触发改派或按已完成比例结束，不复制工程成果。

区域统辖者设各城预算上限与目标，不能跨授权动用主君直属仓库；君主确定全势力方针与任免。预算改变影响下一次执行，不能中途把已实际付出的工程费收回来又重复花。

## 6.9 外交与势力存亡

外交提议`DiplomaticOffer(id,issuer_org,target_org,envoy,terms,expires_tick,required_authority)`。条款包括停战、同盟、通行、援助、物资合作、归附；同盟的生效、义务、到期与违约按§6.16处理，不以一条态度值代替。使者必须实际到达，报价/条款在到达后复核。下属可提出建议和执行主命，未经专项授权不得代表势力缔盟；获授权使者只可在明确条款和底线内决定，超出范围须重新请示。

目标接受分=对方收益0—40＋履约可信0—30＋共同威胁0—20＋使者交涉0—10−风险0—40。分≥50接受，30—49提出一份明确反报价，<30拒绝。人物亲近仅影响接触与最多5点可信辅助，不能压倒敌对的硬条件。停战初始期限60半日，到期前发通知，违约产生组织间明确的关系与声望后果。

组织失去全部合法据点并无有效流亡存在条件时进入Defeated；依次冻结新任命/开销、处理公库接管、把军队和人物分为归附/被俘/在野、解除旧任务、迁移有效事件。私人关系保留。人物死亡只可由战斗/剧情/寿终规则产生，不随组织对象被删除而整批死亡。

## 6.10 世界与事件验收

T51：80个具名人物状态合法且不存在同人多地。T52：NPC购物扣实际钱包与库存。T53：无6半日口粮或出征会掏空守军时不发动军队。T54：三条事件链可达且每步使用真实人物/资产。T55：专属参与者死亡不自动用别的人顶替。T56：选项成本变化时要求重验，已失效选择不偷偷改意。T57：同tick连锁事件不能无限递归或丢掉紧急事件。T58：野战胜利不通过未实现或未达成的攻城条件自动占城；占领由当前真实战争目标和节点结果判定。T59：被俘10半日内有无钱出路，世界照常推进。T60：P2治理替代旧生产器，无重复税粮；占领整合期生效。T61：使者行动与签约权限都真实存在。T62：灭国不清空私产、不复活死者、不留下永久无主任务。T63：批量无人干预模拟检查资源、世界塌缩分布与卡死；这些是未来游戏测试，当前未执行。

## 6.11 v0.2人物岗位与城市事件

在场名单来自同一人物状态，不建立装饰性分身；换班在稳定边界生效，代理人只继承岗位权限不继承私交。基础生计设施安排合法替班或明确开放时段，随机离岗不能锁死全部短工/恢复。

18事件的场景映射见11.8：粮约由掌柜/车夫，师承由教师，任职链由推荐者/议事主持者，寻人由接待者，渡运由船家/停航告示，断货由店员，粮荒由居民/乡里消息，被俘由看守/交涉人，旧主失效由接管者/文书，归附由实际负责人会談，行历由本人手记承载。保留各原触发事实和18项预算，不一律改为系统弹窗。

## 6.12 NPC社会必须改变后续生活

已有有向关系、目标、需要和消息字段只是基础。社会循环为：人物因职责、利益、师承、亲近或冲突选择合法活动 → 与实际对象合作/交往/拒绝 → 产生可保存关系与经历 → 相关知情者获得消息 → 下一次行动和对玩家的反馈改变。玩家不介入时也应有可观察例子，不能只让NPC按固定路线来回走。

师父、同门、商人、管事、居民、宾客和部曲来自同一人物体系。教学占用会影响外出，缺粮会影响劳动与合作，战争征发会影响家计；转仕不清空旧交，代理人接替公事不继承私交。NPC同样遵守地点、库存、授权和已知信息，不能为演出强制瞬移、泄露全图或制造资源。

消息只向有来源与传播条件的人变化，原始事件与转述分别保留时间；事实失效后旧记录仍可作为历史，不更新成实时真相。长期恩怨、师承、继任和组织归属不能只存在会被裁剪的短命令历史。界面以人物口吻、当面回报、见闻记录和实际态度呈现，调试评分不整段暴露给玩家。

## 6.13 私人基业与公职治理共用世界

| 层面 | 所有权/权限与状态 | 半日及长期后果 |
|---|---|---|
| 村庄、庄园、坞堡 | 场地/设施、私人或公共归属、真实居民、管事、工作与守备 | 生产消耗、仓储容量、建设进度、缺人/缺粮、防御和地方关系 |
| 官署与辖区 | 获授权预算、公共仓储、属吏、征发范围和上级职责 | 税粮、民生、秩序、工程、公共军务及考评 |
| 部曲与公军 | 成员来源、装备、口粮、驻防/出征、借调与指挥权 | 唯一位置/占用、劳力下降、伤亡、回还、实际整补 |
| 宾客、幕僚与门人 | 私人关系、组织职事和正式任命分开 | 差遣、教习、谋议、供养、离去与继任后的重新认可 |

私人经营与公职可以并行，不共同占用一个互斥职业开关。公私往来使用明确交易、捐助、借调、征用及已实现的其他行为；每次说明谁授权、资产来自哪里、给谁使用、何时归还或承担何种后果。同一居民/兵员不得被重复计为两处劳力或两支军队。

委任允许玩家外出后事业继续。管事只能操作其被授权的实际资源，不能替玩家无限生成物资；负责人失效时改派、暂停或清算已有行动。调任、离职、势力灭亡和继任分别处理公权、私产与私人关系，不把家园随任职槽一并删除。

与门派、山寨、水寨相连时复用人员、库存、通行、战争和消息规则，保留各自的武学传承、分配/追捕、水路/船只等差异，不把一切机构统一成同一种产粮建筑。

## 6.14 从场所和人物观察经营变化

庄院/乡里/山门画面体现可用设施与实际人员，管理者回报生产、建设、缺粮或调动；官署/军营通过有权限的人与议事处理公事。允许名单、组织结构图和经营详单，但要保留对象与场所语境、关键操作及返回现场，不用全屏不透明管理页抹掉世界。

经营与社会验收在同一小区域联合完成：玩家离庄学艺，管事主持生产；居民关系或消息影响合作；借调部曲造成劳力/守备下降并实际到营；供给与作战改变钱粮和伤亡；归返、离职和继任后继续生活。每步既检查账目，又检查玩家能否说清参与者、地点和变化。T51—T63、Goal E/F/G、CO09—CO11与UI/VIS/IMM分别保留，当前Alpha证据不代替所有完整内容通过。

## 6.15 多辖区经营与中央、地方资源流

**2026-10-01诸侯事业补正：以下补全完整产品，属于行为与状态设计，不声明当前Alpha已实现全国治理、外交或势力战略AI。** §6.8的治理项目和历史候选参数继续保留；这里连接多个辖区、受托统治和君主决策，不追加未经试玩的平衡公式。

辖区须明确政治归属、实际控制者、现任/代理负责人、公共仓储、民生与守备、已承诺支出、在途调拨和整合状态。个人田产、商铺及宗族私产不因位于该辖区就并入公库。区域统辖是对多个已存在辖区的授权集合，不再生成一份复制的土地、人口或税收。

地方依税政与生产真实取得公共收入，先按已定政策保留民用/赈济和守备所需，再承担上缴、工程与军务责任。上级可调整后续留用额度和重点，也可依法征调，但要显示对民生、生产、守备及认可的影响。总览分别列在库、已预留、在途、待收与缺口；预计税收不是已经可花的钱粮，中央账不能隔空提取地方库存。

跨城调拨以既有运输任务和真实容器为基础：合法发令→检查来源及预留→指定承运/护卫、路线、接收者和用途→实际装运出发→沿路消耗与风险→到达验收→更新双方库存和承诺。货物装出即不再算来源可用库存，接收地只能在实际收到后使用；改运、截获、丢失、原接收地易主或负责人失效时保存货物现状并改派/返还/清算。不能点击“上缴”“支援”立即让远方满仓。

征发同一人员会影响地方生产和守备，任职不能复制劳力；当地缺粮、运输阻断和连年重税会影响其持续承载力。中央调整战略时要同时看到这些代价，允许休战恢复、缩小战线或寻求合作。公私交易、捐助、借用及归还沿用§6.13，不能将玩家私产默认为全势力亏空的无限补贴。

## 6.16 外交条约的生命周期与政治权力

外交不是一组永久好感标签。停战、同盟、通行、援助、物资合作与归附各有对手、授权发起者、实际使者、条款、时效、履行主体和失效条件。已有接受评分是候选谈判参数，不替代条款硬条件与签约权限。

共同流程为提议→派遣/接触→在有效信息和资源下复核→拒绝、反报价或接受→必要双方认可与传达→生效→履约/复核→续订、届满、解除或违约。反报价须重新决定，已过期提议不能继续提交；人员位置和消息送达与既有世界时间一致。战场即时交涉只覆盖有权谈的当地事项，不能默认为全势力同盟。

- **同盟：** 写清共同防务或进攻义务、可请求的支援、各自独立决策的边界、持续条件及退出方式。援军仍需可用人员、兵粮和行军时间；无法履约、拒绝履约与蓄意违约分别产生后果。普通同盟不转移政治主权，不能直接计入统一
- **停战/通行：** 明确适用势力、地域、行为限制与终止条件；已在途的军队按撤出/通行条款处理，不因签约瞬间回营。届满提前通知，续约不是自动永久有效
- **援助/物资合作：** 将承诺转成实际输送、支援任务或设施使用权。物资交付和盟友态度分别记录，签字本身不生钱粮
- **归附：** 写清保留何种地方权限、接受谁的共同政治与军事号令、承担何种资源/军务义务以及原军队/官员去向。名义友好、口头臣服或普通联盟不自动构成有效从属关系

违反条款影响实际对手、受影响者及有消息来源的相关势力，不让全图NPC瞬时获得同一态度。首领死亡、继位或失城时复核条约的连续性条款与履约主体，不默认全部永久有效，也不默认全部清空。归附方脱离或不再接受共同权力时须改变实际政治状态并触发相关争议/应对，不能只改一条外交颜色。

汉末政治权威由具体剧本的官职授予、上级/朝廷文书、地方认可、人员承诺及实际控制构成。正式名称、被承认的职权和事实统治分别表达；可通过合乎剧本的征辟、举荐、授职、调停与政治协商取得机会，不能将日本官位次序改成中文就称为汉末制度。朝廷/上级相关内容依剧本存在条件运行，不保证其永远存在或一纸文书必使敌方投降。

## 6.17 多线战役、占领治理与下一轮战略

势力首领/获授权统辖者在已知局势下选择战略目标，明确目标地区、作战目的、各路统帅、所辖部队、集结/供给来源、协同职责及改变/停止行动的条件。地方负责人可以按授权处理防御或求援，不能为了方便无限跨辖区征兵。两条战线若争用同一将领、部队或粮仓，必须先解决分配冲突；同一资源不能因存在两份计划而重复可用。

各路从真实据点集结出发，使用既有行军、野战、围城与补给规则。玩家可亲自指挥一线，远方将领按合法已知信息和明确目标选择行动；报告有时间与来源，中央下达的新指示也须按定义送达。情报不完备时显示不确定性，不能让NPC读取玩家未来计划或让玩家成为全图实时指挥者。

粮道被切断、援军迟到、目标易主或战损扩大时，前线可在授权内固守、改道、解围、撤回或申请增援；超出权限的改攻/媾和需请示。取消旧计划会处理在途军队、运输、俘虏与已预留物资，而不是回滚既往事实。失去唯一返营点时寻找可接受的友好接收地、交涉安置或保留合理的滞留/撤离处境，不用永久占用锁死人生。

占领后的治理循环为：确认军事目标与当前控制→清点公共资产和守备→安排有效临时接管→决定原属吏/降将、俘虏及人员去留→任命可到任的负责人→恢复粮食、治安和设施→完成整合后纳入正常辖区责任。破门、短暂驻军和实际整合是不同状态；§6.8占领期约束继续生效。私人产业、人员关系和未受征调的财物不能全数没收。

本轮战果改变下一轮议事的边境、资源、人员与外交。战争可以因达成有限目标、议和、失败或承载不足结束，统一事业不要求无休止地打一串互不影响的预设关卡。失城要撤销旧公共支配权、处理难民/人员安置与任务接管，仍保留其真实损失、私人事业和后续恢复选择。

## 6.18 势力存续、继位与自主政治竞争

势力的首领、实际据点、认可关系、任命链、公产、军队、条约和已批准计划构成同一政治状态。首领失效时按04§4.13决定代理/继位或权力争议；已有被授权事务按其连续性规则执行，只有需要重新确认的部分暂停。不能因删除一个首领人物便删除整个组织，也不能把其私产继承人无条件设为所有官军的新主人。

失去据点后，只有剧本定义的流亡存续条件实际满足才可继续作为政治竞争方，例如仍有可行动领导及真实追随力量、合法庇护和可维持的供给/承诺。条件失效时进入§6.9的灭亡清算，不在地图外保留永远无法接触、无限生成军队的幽灵敌国；普通逃亡人物本身也不必永远阻止统一。归附、流亡、在野、被俘与死亡分别处理。

NPC势力使用同样的任命、预算、运输、外交和战争入口，周期评估民生/守备、恢复能力、已知威胁与机会。失败后可以求和、重新用人、调整辖区、收缩或依附，不能只按作者固定命令无限出征；成功扩张也要承担接管与整合成本。玩家不参加战争时仍可观察到这些结果和由合法消息得知的原因。

验收除§6.10外，需联合检查无玩家介入的任免/经营/战争循环、两线资源冲突、失城后存续与灭亡、条约连续性及政治继位。设计完成不等于这些场景已经通过；LORD01—LORD12记录在现有战争验收文件，07§7.16给出贯通路线。

## 6.19 时令与地方社交的内容模板

聚会、宴饮访学和乡里活动作为现有事件与会面的内容配置，补足日常关系生活，不另建节日引擎。先选择少量具备来源与场景的样本，使用02的游戏化历法及本章事件时间窗；“每月30日、每年360日”不因引用节气或历史节日便冒称精确汉历。具体文化名称、礼俗、器物和参与方式须核对时代、地域与出处；未审校的内容只能保持明确的原创活动身份，不能以“中国传统”概括替代核验。

每项配置除§6.4字段外，还须在内容说明中明确：

- 主办者、实际场所、参与者资格及邀请/得知来源；有名单不等于人物已经到场，旅行、出征和既有课程仍占用本人
- 开始/结束窗口、预计路程、参与所需时间、费用/物资的承担者与合法来源；预览免费，实质交往按行动协议结算，不用每句对白重复扣时
- 应邀、到访、参与、拒绝、迟到、取消及离开的处理；未承诺时拒绝不自动失信，已接受具体职责后未履约按实际承诺处理
- 会面话题、可知信息和可能变化的关系边；共同活动不保证所有人互相亲近，更不等于全地区声望或善恶统一加分
- 主办者离开/死亡、场所封闭、时窗已过、物资不足和关键参与者缺席时的取消、延期或合资格替代；专属人物事件不得用陌生人顶替

例如一场地方讲学后的宴饮，可以由真实主人提供场所与物资，来访者选择听讲、提出游戏中已有论据、与在场人物交谈或离开。后续引荐、传授机会或争议只依据实际互动与立场，不要求背诵诗史，也不保证参加便获得卡片或永久属性。关系后果只作用于实际参与者及之后合法获知的人；消息标注原事与传达时间，不让远方敌对势力无因同步改变态度。

活动从人物邀请、已送达文书或现场消息进入，结束后可回访相应人物观察反馈；不得只在手记里新增领奖按钮。保存恢复、重复访问与同一时窗的重新打开遵守§6.5及11§11.8，不重复消耗或发奖。界面和场景仍随09的视觉样板验收，不排到游戏完成后的装饰阶段。

## 6.20 地方危机的多职业共同内容链

用有明确地区、时段与发生依据的灾害或供给危机检验世界联系。候选内容链为“地方生产或交通受扰→可用供给、库存与价格变化→居民及事业出现需求→各方介入或不介入→恢复、延迟或恶化”。这是一条内容样本，不新增完整天气、灾害或人口模拟器；配置须复用已经接入的EventDef、行动及资源操作，未接入的因果环节标明缺口，不能靠叙事直接宣称已经结算。例如临时产出修正若尚无对应实现，后续需先补最小规则与测试，再用于内容；不能将整条链声称为当前已可纯配置完成。

优先复用E01—E03粮约、E11渡运中断、E14粮价与乡里及已有治理、交易、运输和医案规则。发生条件须读取真实道路、生产/供给和库存状态；只损失已有物资或在规定时段调整合法产出，影响期满不返还已经损失的货物。价格由市场和有期限的事件修正形成，同一原因不能重复扣库存或叠加同一份影响。不能为引出任务把已到货车队退回受阻状态。

| 人生处境 | 可选介入 | 真实成本与结果 |
|---|---|---|
| 普通居民/在野人物、私人基业经营者 | 改变谋生安排、保留或转让个人储备、帮助乡里、申请已有救助、暂不介入 | 使用本人可支配的钱粮、劳力和时间；基本生计与恢复路径仍保留，家产不自动充公 |
| 商人 | 改道采购、承接运输、出售或捐助物资、暂停高风险订单 | 货物、运力、路费和合同真实占用；有利润、延期、货损或亏损的可能，不保证“救灾必赚钱” |

### 世界事实与人物认识分开

真实目击可以使人敬畏、怀疑、求证、招揽或争夺资源，评价仍依利益、性格、证据和承诺。远方势力需要使者、信件、来访者等合法来源才获知，转述可能不完整；不得把神兽相助等同全世界效忠、实际授官或政治统一。玩家误信传闻所做的选择仍留下实际旅费、工时和承诺，不在揭晓真相后自动返还全部代价。

### 局部环境效果的定义和生命周期

能改变地点/道路/设施的法效必须逐项说明：唯一效果实例、来源行动及施用者、真实目标ID、开始条件、作用对象与尺度、明确变化、持续时间或解除条件、叠加/替换组、作用上限、失效与到期行为、在途占用处理及结算标记。效果未知、目标不存在、范围不明或缺少到期处理的配置不能发布；需要新规则时先实现并验证，再允许内容引用。

法效采用“核查目标/资格/费用→原子提交消耗与状态→世界规则统一读取→到期/解除时移除该来源影响并重算当前结果”的生命周期。恢复不能把地点回滚为施效前整张旧快照，否则会抹掉期间合法发生的修路、占领或其他变化。相同来源重复提交不重叠；不同来源是否叠加按明确组规则处理，不采用隐含无限乘算。

照幽、辟雾等探察/环境作用只揭示或改变对应地点真实存在的对象，不读取未接触地区、未来命令或全地图未知状态。发现秘密入口不自动获得进入产权；让道路暂时可用也不取消敌方封锁、已知战争和过境授权。地方效果可间接影响运输与后续报价，但价格仍由实际库存和有效市场规则形成，不能同时凭叙事再加一份货物或利润。

| `CommitmentRef`与所属领域`ContractRecord` | 引用含`domain_id, contract_id`；所属合同含承诺双方、事项、权源、条款、期限、状态、唯一结算及适用的资源/预留引用 | 任务、交往、组织等所属领域拥有合同；资源领域拥有实际预留与清算，持续事务与AI不复制履约状态 |

`required_amount`可以是粮石、运输批次、工程工作量等已登记单位；“开放道路”这类不可分成果用明确目标与完成事实，不能硬换成万能进度百分比。普通合同、疾病救助、军需等使用相同身份与引用机制，但由各领域定义自己的验收条件。

同一人物的位置与占用归人物/行动系统，钱与货归现有钱包/库存系统，部队归军事系统，工程成果归治理/经营系统。`CommitmentRef`不能建立一份独立可花的钱粮；当前只接受action_id预留的库存接口必须明确扩展为受检的预留主体引用或兼容适配，再接入长期承诺，不能把新ID硬塞进旧字段宣称支持。

### 6.24.2 创建、去重与派生接口

- `open_or_update_affair(origin_ref, episode_key, cause_fact_ids)`：源领域在阈值越界、真实事故或已批准行动发生后请求创建。`episode_key`由该领域按对象、原因与发生轮次产生；同一键只得一份活跃事务，不按玩家职业、是否在场或是否接受任务另开世界
- `upsert_need(affair_id, semantic_key, requirements, expected_revision)`：需求键至少区分受益对象、真实目标、地点和需求类型。供粮与护送是有关联的不同需求；同一批粮的两个宣传入口不是两份供粮缺口
- `query_opportunities(actor_id, known_scope)`：按已知消息、所在地、资格与权限返回可见机会。职业只改变入口、方法、收益资格和表现，不修改事务事实；没有玩家承接也不阻止NPC处理或局势恶化
- `claim_need(need_id, amount, assignee_ref, expected_revision)`：复验仍需数量、现有份额、承接能力与权限。候选失败不留占额；两个承接者不能分别承诺同一份独占成果
- `apply_contribution(need_id, claim_id, domain_receipt_id, expected_revision)`：只消费领域真实成果回执。回执包含来源命令/行动、实际受益对象、完成时间和数量；同一回执对同一需求至多消费一次
- `release_claim(claim_id, reason)`与`close_need(need_id, reason)`：退回尚未履行的责任，触发明确资源清算。关闭不代表删除历史，也不自动将已经付款/交付的部分倒退为未发生

还需运输的粮、已经预留的粮和已经交付的粮必须分开。剩余真实缺口为`max(0, required_amount - fulfilled_amount)`；未占用可承接份额还应扣除合法活跃claim的剩余责任，不能把“已承诺”算成“已救济”。需求改变时先重验既有份额，超额部分按公开的期限/承接顺序规则缩减或另行议价，不悄悄改写已经接受的费用与承诺。

任务负责记录责任与报酬，需求负责验证其目标是否满足。各职业的奖励可来自不同合法预算，但不能复用同一贡献回执重复拿同一笔奖励。跨多需求复用一个事实必须由登记的贡献规则明确允许：例如护送安全抵达事实可证明护送完成，粮食交付回执可证明供粮完成；两者不创造两批粮。默认不允许凭一个含糊“成功”标记清空所有相关需求。

危机消退、暂缓、失败和再次发生不同：消退保留终态；暂缓保留未结需求及复查时间；失败可留下伤亡/损失；以后新的粮荒使用新episode并引用旧因果。不得重开旧任务奖励，也不得仅凭文字相似自动合并不同据点的危机。

事务基本阶段为Open/Active/Suspended及Resolved/Failed/Cancelled终态，领域可声明合法细分；Need为Open/PartiallyFulfilled/Fulfilled或Expired/Cancelled，claim为Accepted/InProgress/Settled或Released/Expired。每次迁移必须有领域条件、时间与原因引用；仅把phase改成终态不构成资产清算。具体状态名是待实现合同，不自动映射为现有任务状态。

数量口径约束：`required_amount`始终表示本episode累计应满足目标，`fulfilled`为累计已验收贡献。初需100、已交50后，剩余为50，不能把required重写成当前缺口50后再减fulfilled50。若源域按实时库存重算，须转换回累计目标或另以`current_shortfall`直接记录可验证缺口，不再扣历史贡献；该量仍为源域派生值，不另建库存。消费、新医案等新需求须明确扩目标或新episode，撤销/退款回执的贡献冲减按源领域合同处理，不能仅删任务便抹掉真实交付。

## 6.25 有限NPC目标、感知与计划合同

### 6.25.1 决策状态与输入

每个可行动的运行人物通过统一身份/原型接口取得行为定义，不只遍历静态作者人物。NPC自治模块拥有`NpcGoal`与`NpcPlan`，NpcPlan是工程架构Plan的NPC实例，与02的PlanIntent/PlanStep共用意图/行动边界；组织决策模块拥有`OrganizationIntent`。两者都不能直接拥有钱包、库存、位置或战斗结果。

- `NpcGoal(id, actor_id, kind, source_ref, priority, target_refs, desired_result, deadline_tick, status)`：有限枚举的生计、履职、恢复、学习、求职、交往、履约等目标；新目标机制必须增加受信能力，不能用任意字符串脚本解释
- `NpcPlan(id, goal_id, template_id, step_index, phase, current_action_id, dependency_refs, observed_revisions, commitment_refs, mandate_ref, last_decision_tick, next_decision_tick, retry_reason, retry_count)`：使用有限模板的行动步骤，如问讯→采购→装载→行旅→交付。每步都可失败；不能一次计划就假定末尾事实已经发生
- `DecisionContext(actor_id, tick, known_reports, own_state, authorized_resources, visible_opportunities, commitments)`：只提供本人已知、亲历、公开或按权限可知的数据；不能把整个世界快照传入评分器后仅要求作者“不要偷看”
- `ActionProposal(plan_id, step_index, actor_id, command_kind, params, authority_ref, cause_refs)`：交给正式命令网关预览、检查与提交；成功返回行动/结算引用，失败返回稳定原因码和下一检查条件。计划更新与行动启动一起提交，防止行动成功却仍从旧步骤重跑

角色已有主行动时继续执行。结束、失败、本人确实获知的重要变化或到期复查才触发选择；同人每半日最多一次有效决策。候选先排除不合法动作，再按6.1的有限效用评分。采用少量性格扰动时，仅在正式决策候选事务内从规定随机流取值，随机状态与采用计划、消耗唤醒/推进游标同成同败；事务外的候选预筛选和评分查询不消费随机。计划未失效时不因每次微小价差而切换，不每半日从头遍历全部职业与地图。

### 6.25.2 事实、消息与知情边界

`DomainFact`是工程架构Fact及03经历所引用的原领域事实的统一信封，不另建平行事实表。最小信封为`id, kind, schema_version, domain_id, tick, transaction_id, subject_refs, cause_fact_ids, affair_ids, payload`。事实由产生结果的领域写入；其类型与payload有Schema和受信处理器。结算事实与真实快照共同作为验证依据，不要求把所有字段更新都改成事件溯源。

`ObservedReport(id, receiver_ref, fact_ref, source_ref, channel, observed_tick, received_tick, valid_until_tick, visibility_scope, reliability_kind)`由感知/消息领域记录，属于03同一Knowledge/Memory认知模型的消息证据，不建第二份记忆账本。渠道只支持已登记的亲历、当面转述、公告、真实使者/信件等；传递距离与耗时由渠道规则规定。战报允许过时和有限估计；亲历事实不能因过期被抹掉，但其作为当前敌情/价格的可信度会降低。

“客观真值变了”“人物得知了”“向玩家展示了”是三个不同步骤。客观归属可立即使旧权限失效，消息仍可能尚未送达；不知情NPC到场遇拒时再获得能观察到的失败原因。正式校验可拒绝非法动作，却不能通过隐藏目标的详尽失败原因给AI提供侦察捷径。一次未能执行未知敌方动作，不自动透露其兵力、未来命令或精确物资。

事实的消费者是模块清单中声明的有向接口，不是任意订阅后可写任意状态的总线。必须声明输入类型、拥有状态、输出类型、幂等键与阶段；不允许同步循环触发。社会转述沿用现有“半日内不连续多跳”原则，新得消息最早在下一允许传播边界再次传递。UI、音效和通知可以漏看，但不能因此漏执行世界后果。

### 6.25.3 承诺、冲突与局部性

计划中“打算采购”只是意图，不持有资源；到实际承诺步骤才通过所属领域预留有限资源与人员。合同提议、接受、改约、履行、解除、违约和失效沿03/04及工程架构的统一承诺语义查询，不复制清算。资源占用可投影为Held、PartiallyConsumed、Consumed、Released或Expired，它们只解释资源域原有预留/消费状态，不另存第二状态机。未兑现的Held部分才构成占用。期限、取消费用、已消耗部分和归还去向必须明确，不允许多年计划永久锁死商店、教师或守军。

计划读取03的`commitment_constraints(actor)`及04的Mandate权源；已接受的时窗、许可和守约限制参与候选排除。授权内fallback可按预先约定选择，超预算、超辖区、改换目标或其他需本人决定事项进入`AwaitingDecision`并发送报告；报告实际送达才改变授令者的已知信息。等待期间保留合法安全动作与到期清算，不自动越权，也不冻结全世界。

同一人不能同时授课、赴约、行军；同一部队不能兼作两支军队；同一批货不能同时承诺两个买家。互斥由现有领域资源所有者裁决，AI评分不是最终裁决。当前步骤与必要下一步以外的未来资源通常只估算；确需长期合同必须有显式期限与代价。

竞争提案按已声明的硬优先级、承诺期限/申请tick和稳定ID顺序裁决，并保留失败原因；不因玩家身份暗插队。固定扫描顺序不能造成永久饥饿，反复争用应记录等待时间并按已声明规则影响同优先级仲裁。局部AI只评估相关人物、已知道路和候选设施；组织只在自己的权限和已知局势内决策，不需要全国每个NPC互相评分。

## 6.26 稳定边界、失效清算与持久化

### 6.26.1 目标阶段顺序

以下是新能力接入后的目标依赖，不能直接替换现有WorldStep顺序并假称结果不变。A1注册迁移先保持既有行为与RNG；新增阶段及行为须以独立规则版本、固定seed和兼容回归启用。

1. 读取tick开始的稳定状态，确定本次已在进行的行动、到期承诺与必需结算集合；新产生的计划不能补走本半日进度
2. 按显式依赖推进既有补给、生产、行旅、战斗与行动。紧急死亡/俘虏/归属/权限变化在其依赖动作继续前完成对应领域校验；不能等到通知页才生效
3. 结算有效完成、到达和交付，写领域回执；按02的截止边界处理到期，推进需求/持续事务并清算失效引用。只消费本阶段允许的事实集合，不在同一调用栈无限生成任务链
4. 交付本次实际到达的消息并建立亲历/已知证据，形成权威重评/到期状态、机会与通知；需要多跳的传播进入下一边界。事实消费、已送达知识、权威唤醒及公平游标与领域结果处于同一候选事务。不同阶段对本tick新事实是否可见的规则必须登记，不依赖字典顺序
5. 完成全候选世界不变量校验后一次提交。事实、资源、tick、RNG、权威队列与未交付通知同成同败；UI不接收半成品。自动推进按完整提交后的可见信息检查是否需要停止
6. 基于已提交知识与权限，对到期或确实获知重要变化的组织/人物纯计算有限候选。采用配置中的组织评估节拍；重大变化合并一次，不把十条同类战报变成十次决策。此阶段只刷新可重建投影，不在事务外移动权威游标、消耗唤醒或修改计划
7. 下一步沿正式命令网关进行后续独立候选提交，采用计划、消费唤醒/调整公平游标、行动启动及资源占用一起提交；等待/失败重规划也须事务化。新行动最早下一半日取得进度。不得反复免费尝试直到抽中好结果；重评不由UI通知回调驱动，关闭界面后仍处理持久排队的合法工作

严格到期、补给和危险结果不得因每tick展示/AI工作预算而丢失。性能预算可推迟低优先级重新考虑和非关键展示，必须保存待处理原因、期限与公平顺序；不能用“远处不模拟”跳过应发生的消耗或偷偷冻结战局。

### 6.26.2 失效与取消

统一失效通知为`Invalidation(subject_ref, reason_code, effective_tick, cause_fact_id, replacement_policy)`，由拥有主体的领域发出并经明确消费者处理。`replacement_policy`只能是定义中已经声明的固定参与者失败、合法同岗替换、等待、改派或清算；不能运行时随便换人保证剧情成功。

| 变化 | 必须处理 |
|---|---|
| 目标已被NPC满足或危机自然消退 | 关闭剩余机会，重验在途承诺；已付出工作依合同结算，可退货/改用途须重新取得合法接收者，不能将车上真实货物直接删除 |
| 委托人死亡、离职或组织灭亡 | 先失效授权，再决定合法继任者是否承接；无承接则清算公共资产与已做成果，私产/私人关系保留，不留下永久占用 |
| 路断、价格变动、物资不足 | 保留实际当前位置与已消费资源；进入Blocked并记录复查条件/next_decision_tick，按模板绕行、议价或终止；不能重启任务刷预算 |
| 人物受伤、被俘或死亡 | 由行动/军事/人物领域终止或暂停对应工作，释放可释放的承诺；尸体、损失和在途物资依真实领域规则处理，不重新生成同一参与者 |
| 玩家拒绝或离开 | 仅关闭本人当前邀请/展示；持续事务和其他参与者继续。退出责任另走cancel与清算，不把“关闭窗口”当成已履约或全世界取消 |

`cancel`对已发生的部分不做时光倒流；已消费粮食不返还，已完成路段不瞬移回原地，已支付且不可退的费用保留事实。解除承诺、关闭claim、行动释放、唯一结算与计划终态在同一提交边界保持一致；重复cancel、重复回执、重复消息都幂等。

### 6.26.3 保存与恢复

存档必须包括事务/需求/份额/计划/承诺/消息队列、阶段与revision、下一决策/复查tick、RNG状态、已消费回执与唯一结算键；不能读档后重新随机目标、重新补满公库或从头重播计划。依赖索引可从这些权威对象确定重建，不能靠重放历史奖励建立索引。

恢复先验证所有引用、单人单地与占用、实际预留和承诺对应、需求完成量与回执对应、终态结算唯一、消息时序和权限。事件展示与计划等待状态可续接，但正文不保存待执行脚本。旧档迁移只增加明确默认空状态或可证明的兼容引用，不推测旧局以前发生过的危机、历史消息或NPC目标。

关闭对象保留用于因果、结算与续档的最小终态；仍被任务、消息或回执引用的事实不得清除。可裁剪的仅是非权威调试轨迹/重复展示缓存，裁剪后不得重新发奖、丢失曾知情来源或改变计划结果。长期存档验收同时检查活动对象和已关闭历史增长。

## 6.27 世界节奏、扩张代价与普通生活留白

### 6.27.1 节奏来自世界规则

世界变化有行动、日常、区域议事、月度治理等不同节拍，使用同一时钟。6.1人物决策与6.2组织评估不等于每tick必然开战或触发私人灾难。是否行动取决于真实需要、利益、资格、所知情报与可承受代价；没有正收益候选时允许工作、修复、休息或等待。

每次扩张的`ExpansionAssessment`至少记录`authority_ref, known_target_report_ids, committed_army_refs, retained_defense, supply_horizon_ticks, transport_capacity, mobilization_cost, recurring_upkeep, projected_integration_load, available_governors, earliest_departure_tick, refusal_reasons`。该评估是只读查询，军令正式提交仍重验；其估算范围与误差来源可诊断，不能直接读取隐藏敌情。

- 出征前依选定规则配置检查守备底线、供给时长、合法将领及外出军队数量上限，6.2的6半日等数值作为历史候选测试配置保留；完整远征再校验道路、运输、途中消耗和返程/补给方案。不能把“起步有粮”当成整场战争无限供给
- 动员、训练、恢复、行军、守备和治理消耗同一人员、装备、劳力与公共预算。外派人才减少本地可用服务，征募与生产劳力的关系在相应人口模型中记账
- 扩张获得的资源沿真实归属和接管流程入账；先付接管、修复、驻军、安民与管理成本，不能占一城立即满额税收再无限连锁征兵。采用6.8历史参数的配置须兑现未稳定占领20半日、收入50%且禁止征募；其他配置明确给出同类代价，均在新一轮推进检查实际粮饷/人手不足
- 失败后的配置整补期与伤员/装备恢复都保留，6.2的6半日作为历史候选；时间到并不凭空补齐军队。和平、停战、外交协作也经过真实意愿、使者与履约成本，不能仅作为强制拖慢统一的按钮
- 生产/税收采用明确来源和节拍。人口治理替代旧生产器时只能运行一个权威生产器；显式难度倍率入报告，不允许按AI快失败或玩家太弱临时送钱粮

这些成本限制无成本滚雪球，**不保证永远多国并存，也不设保护玩家的统一进度上限**。一个准备充分的强势力可以壮大甚至统一；是否过早形成单一解由多seed长期分布和可玩性检验决定，再调整公开世界参数与行为策略，不能每局暗中扶植弱国或复活已灭组织。

### 6.27.2 普通生活与事件展示

“留白”是有可用的谋生、学习、交往、经营和休息机会，局部变化可以观察和应对，不是让玩家生活期间其他地区停止。危机可能造成真实服务关闭、改价、断路、征调或迁徙；通知要指出已经知道的原因与可采取的行动，不把所有战事都强迫变成玩家必接任务。

事件紧急性来自实际危险/到期与当事人关联，不能因为“玩家最近太闲”就制造灾祸。与当前位置、责任、关系和已知消息无关的远方变化可作为延后见闻，而非连续弹窗。6.5的每tick普通展示上限只限制界面，不限制NPC、供给或战局本身；紧急队列保留且不被普通消息挤掉。

6.5“事件展示期间世界时间停住”指统一回合/命令边界中等待用户输入，不按现实秒数后台推进。它不授予任何事件冻结其他实体多个游戏半日的权力。玩家选择等待、工作、学习、长休或履约而经过的每个世界tick，相关地区和NPC均照常结算；长行动可因已经到达的有效危险/期限提醒在稳定边界暂停续走，但不能撤回本tick他人已经发生的结果。

普通工作保留明确工期、费用、产出与是否可中断。非关键邀请可以稍后处理或拒绝；任务期限制定要基于实际路程、办理时间和已知风险，不设大量必然撞期的短倒计时制造忙碌。战区不会因玩家选择当商人自动变安全，但安全地区可以有持续日常，不把全国人口都强制投入唯一主线。

## 6.28 同一危机的跨职业样例

例：东城粮食跌破配置阈值并持续达到门槛，运输甲又被实际断桥阻住。经济域建立粮荒episode与供粮需求，行旅/治理域记录断桥及通行限制；两者通过因果事实相连，不能假定所有粮荒都由断桥引起。

| 参与身份 | 可做的实际工作 | 共用状态与结果 |
|---|---|---|
| 商旅 | 根据已知需求报价、取得合法供货份额、采购并运输 | 使用真实钱包、批次与目的地；到货才减少供粮缺口，报价/接单不恢复库存 |
| 护卫 | 承接同一运输甲的护送或侦察可用绕路 | 引用该运输/道路与风险事实，不能为护卫再生成一辆相同粮车；护送完成不冒充粮食已交付 |
| 地方官 | 动用权限内预算，安排真实人手修桥、调配公粮或批准采购 | 修桥与采购各有需求与投入；不能写一句赈济完成就同时加粮、修桥、恢复全部民心 |
| 将领 | 依法调兵保障道路或调整前线用粮 | 真实部队离营、口粮与守备下限有效；军用粮转民用须有合法权限和一次转移回执 |
| 医者 | 在确有病伤人口且医疗能力已实现时承接救助 | 医疗需求引用真实受益对象/群体与物资；不能仅因玩家选择医者就额外生成伤员，也不能用供粮回执代替治疗 |

某NPC先完成供粮后，所有入口查询同一新revision：未承接者看到需求已满足；在途者按先前合同处理剩余交付/转售/退回；已完成者得到应有报酬但不重复奖励。桥尚未修好就仍然不能通行，粮荒也可能因别路到粮先缓解。拒绝参与的玩家仍会见到价格、道路、人物去向或后来的消息变化；切换职业、离城、存读档都不新开一场危机。

样例只证明可组合的因果合同；其中尚未实现的医疗、治理与需求机制必须在作者编译时报告缺失能力，不能把完整样例文本当成正式版本已可玩。

## 6.29 跨系统验收与接入顺序

下列DW是本章局部合同用例，与09的DYN验收关联，不新增另一套总体验收编号；全部为待执行，不复用旧测试数量宣称通过；其结果要绑定规则版本、内容包、seed、平台和命令序列。除单元断言外，至少两套不同人物/地点/组织配置完成实际闭环。

| ID | 必须证明 |
|---|---|
| DW01 共享原因 | 同一粮荒从至少三种职业入口及NPC触达时，只有一份episode和真实库存；切换身份/地点或读档不复制；另一次合法复发有新ID且关联历史 |
| DW02 分工与竞争 | 供粮、护送、修路各自消费正确回执；两个承接者抢同一份额只有合法份额提交成功，重试不超额；供粮完成不凭空修路 |
| DW03 世界自行推进 | 玩家不接、拒绝、离开及从事普通长期活动时，NPC仍能解决、改派或失败；任务UI全部关闭不改变同命令序列的世界结果 |
| DW04 局部知识 | 未收到战报/行情的NPC不据该信息重规划；传递实际耗时且无同tick无限多跳；真实权限变化立即生效，拒绝理由不泄漏隐藏兵力 |
| DW05 同一资源 | 教师授课与出征互斥；钱包/粮批/车/部队不会双重承诺；意图不扣款，Held有真实预留，部分履行后取消只释放剩余部分 |
| DW06 生命周期 | 依次覆盖死亡、俘虏、委托人离职、灭国、断路、涨价、需求已满足和期限到期；无伪造替代者、永久占用、无主任务或退还已消耗资源 |
| DW07 确定恢复 | 在计划待启动、Held、在途、Blocked、贡献已提交、事件待展示等边界保存重开，结果/RNG/下一决策tick一致，回执、通知消费与报酬不重复 |
| DW08 调度有界 | 同人每tick至多一次决策，稳定排序不受文件枚举影响；竞争不永久饥饿；同tick同步派生超限报错并回滚整个候选，只有显式声明未来tick的事项才延期；低优先级AI预算可公平延期，紧急结果不因普通展示/预算限额丢失 |
| DW09 扩张代价 | 无足够补给/守备/合法将领不可出征；占领整合、返程、动员与实际生产来源均生效；玩家与NPC使用同一成本，难度倍率可追溯 |
| DW10 长期分布 | 多seed无人干预记录资源收支、首次战争/灭国/统一时间分布、据点换主频率、未结需求年龄、无进展计划/承诺与存档增长；提前声明观察期与异常阈值，不仅挑一局展示 |
| DW11 普通生活 | 在事先定义的安全、边境、战区配置分别跑谋生/学习/交往/长休；记录可完成比例、强制中断原因、通知密度和可用职业入口。普通生活有实际产出，远方世界同期推进；不以战区永不受影响为通过条件 |
| DW12 作者及兼容 | 第二份危机/计划配置仅使用已登记能力即可形成真实闭环；未知需求单位、非法回执映射、因果环、缺参与者及动态人物行为缺失明确报错；旧档不凭空补史 |

接入次序：先修正现有事件trigger/失效策略的能力声明并固化旧流程，再在A1合同中预留事实信封、来源绑定、合法承诺与阶段依赖；以既有供货/护送/军需选一个最小共享事务切片完成DW01—08，再启用有限目标计划与区域势力评估，最后扩展人口治理、医疗等新领域。每步保留现有可玩路径，不先制作全国完整AI，也不等所有职业完成才第一次验证“同一世界”。
