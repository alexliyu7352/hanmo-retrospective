# 02｜世界时间、地图与行动详细设计

> **v0.2场所/NPC交互修订：** 本文件与新增`11_places_people_interaction.md`共同阅读。外部事务必须通过合法场所中的人物或有明确来源的物件办理；原数值与未涉及机制沿用v0.1。本文是修订后的设计，不是已经实现的新游戏；旧版游戏/文档核验不代表新增交互已通过。

**基线：总体设计 v0.1 第4—5、16、21章。决策：I03—I10、I32。适用：P1起。**

本文件定义规则，不是已经运行的程序。文中钱、日、容量均为游戏单位；所有数值标为首轮平衡参数，不是历史度量。

## 2.1 全局不变量

| 编号 | 必须始终成立 |
|---|---|
| INV01 | 一个人物只有一个合法位置和一个占用其本人的主要行动。组织任职与行动占用分开。 |
| INV02 | 同一个世界半日只结算一次；界面帧、动画、浏览器可见性不驱动世界时间。 |
| INV03 | 数量与金额为整数且不为负；同一份货物不能同时被两个任务预留。 |
| INV04 | 规则结果先形成，表现层只播放；跳过动画不改变任何结果。 |
| INV05 | 查询和预览不改变世界、随机流、关系或任务进度。 |
| INV06 | 行动、交易、任务结算各有实例ID；重复提交旧实例不重复执行。 |
| INV07 | 跨模块判断使用稳定ID和明确时刻，不用显示名称、真实时钟或节点路径。 |
| INV08 | 读档恢复已提交事实，不再次执行进入场景时的奖励脚本。 |

## 2.2 时间表示与截止口径

`tick`为从剧本起点开始的非负整数；0代表开局日上半日。`day_index = tick div 2`；每月30日，每年360日。时间标签是游戏化历法，不声称对应精确汉历。日期换算只在显示层进行，逻辑不解析中文日期。

任务以**交付行动完成时刻**判定及时性：`delivery_finish_tick <= deadline_tick`为按期。在`t=10`开始一个耗时1半日的交付，于11完成；截止11则按期，截止10则不能称按期。接令和路线预览同时提示“预计交付完成时刻”，不只显示到城时间。

截止检查位于本半日所有正常完成效果之后。于截止边界完成的交付先完成，再检查未完成的任务。任务是否允许逾期部分交付由任务配置决定。过期不自动消失，清算规则见04。

时间可免费查看，不能免费刷收益。相同会面中的问候、打听和请求组成一个会面行动；额外开始一次实质交往才再耗时。免费取消未确认的草案，不产生关系或经验。

## 2.3 权威状态与行动状态机

`WorldState`保存`tick, revision, next_instance_id, actors, locations, routes, organizations, markets, tasks, events, battles, long_actions, places, role_assignments, interactions, discoveries, rng, history`。`revision`在每次逻辑提交后加1，和时间不是同一概念；零时长的事件选择也能改变revision。

`ActionDraft → Validated → Committed → Running → Completed`。

可选支路：`Draft/Validated → Cancelled`（无代价）；`Running → Suspended → Running`；`Running/Suspended → Aborted`（保留已经实际消耗的资源和时间）；`Running → Failed`（目标失效等结果）。Completed、Aborted、Failed都是终态，不允许同ID重新启动。

| ActionInstance字段 | 类型与规则 |
|---|---|
| id / actor_id / kind | 稳定字符串；kind来自发行版提供的受控注册表，未注册种类明确拒绝，不由MOD执行任意代码 |
| created_tick / start_tick / expected_finish_tick | 非负整数；预计时刻不是不可变化的承诺 |
| participants / occupied_actor_ids | 参与者条款与当前实际占用分开；运行时占用实际参与者，暂停按行动类型释放或保留。交易占用在场办理者，不锁全城商人；人物本人仍可使用岗位限定的机构库存 |
| status / remaining_ticks | 上述状态；剩余时间不得为负 |
| start_effects_applied | 布尔，防止恢复时重复扣预付款 |
| reserved_resources | 资源ID、数量、owner与用途；只记录真实预留 |
| progress / pause_reason | 按行动类型定义；不使用任意脚本对象 |
| result_id / completion_applied | 结果引用与终态结算标记 |
| validated_revision | 防止过时预览提交；不作为联网防作弊机制 |
| interaction_context | 场所、人物或物件目标、办理代表与岗位授权；外部事务必须校验，个人自主行为按其类型校验 |

`validate`返回可执行性、原因码、显示费用、耗时和涉及实体版本。`commit`重验；失败必须零副作用。已经接受的行动写入实例并占用人物，只有该动作定义的起始效果立即发生。行动服务是写入入口，UI不能直接加钱或移动人物。

### 起始效果和完成效果的统一口径

短交易在确认后立即交换钱货，再推进半日，交易单据记录确认时刻；买卖行为不会因随后出现的道路消息被撤销。交付任务的数量在开始时预留，**完成时**转交并判定期限。修业在开始时缴费，逐半日获得学习效果；取消后不退已完成部分。旅行逐半日付费与推进，不预扣整段行程。

这些差异写在行动配置，不由各页面自行决定。每个逻辑提交使用临时状态副本；不变量检查通过后替换当前权威状态。P1小世界先使用普通状态副本与局部结果对象，不先建事件溯源数据库。程序异常时丢弃未提交副本，保留最近稳定世界，不能默默吞错误继续算。

### 稳定边界

允许保存：行动已接受且起始效果明确写入后、一个半日完成后、一个事件选择完成后、战斗等待下一轮输入时。保存包含正在进行的行动；加载不能把Committed再当成新动作。结算函数内部和移动动画中途不是保存边界。

## 2.4 一个半日的固定顺序

进入时读取起始快照`S(t)`并生成本轮消费、行动与占用清单。`advance_one_tick`不可重入；本次只能推进`t → t+1`。

| 阶段 | 操作 | 冲突规则 |
|---|---|---|
| T1 | 检查现有行动可继续性；确定本半日参与者、行程和军队口粮 | 只准备，不向UI展示半成品 |
| T2 | 按行动ID顺序推进旅行、工作、学习、NPC已有行动；收集完成效果 | 不启动本半日尚未开始的新长行动 |
| T3 | 应用本轮战术结算、到达、交货、治疗与任务客观进度 | 同一物资冲突先预留者有效；无预留的竞用按行动ID |
| T4 | 消耗本半日事先确定的旅行费用、口粮，更新疲劳、伤病计数 | 一个费用键只能出现一次；军需规则见05 |
| T5 | 令时间到`t+1`；跨日时做市场生产消费、店铺营业和恢复；跨月时做薪给与常规议事 | 已终止组织不付款；单个结算记录明确日期键 |
| T6 | 完成有效任务的奖励清算；再检查逾期、主体灭亡、合同失效 | 截止边界完成优先于逾期 |
| T7 | 汇总NPC与势力的到期唤醒、条件变化和计划失效 | 先记录待决/脏集合，不在半成品世界直接启动新行动 |
| T8 | 处理合法送达的消息、事件候选和通知，写经历、验证不变量、提交稳定快照 | 提交后计划才经命令网关启动，新行动最早下一半日取得进度；重大选择不在半日中途递归打开 |

上述阶段在同一候选世界内完成并整体校验后提交，不把T2—T6或消息阶段的中间状态单独发布；提交后新计划命令另作原子事务，详见2.14。遇到需要玩家选择的道路事件，先停在对应真实路段边界，完成本半日其他结算，再展示选择。选择引发的新行动从下一半日开始。日结算或月结算不会因为一次旅行跨了多日而只执行一次。

部队战每完成一轮调用一次上述流程；个人战包含在触发它的行动半日内，轮数不另加世界时间。没有任何战斗动画直接调用时钟。

## 2.5 行动表与取消处理

| 行动 | 时间 | 起始效果 | 完成效果 | 中断 |
|---|---:|---|---|---|
| 实质会面 | 1 | 占用双方；收礼物时转移礼物 | 关系、消息、请求结果 | 普通会面不被半日内新事件打断 |
| 场所内/城内通行 | 0额外 | 检查通路与入场资格 | 更新place_id与必要发现；不刷关系/奖励 | 新阻断事件与门禁可停止熟访捷径 |
| 经费委托受领 | 1 | 占用经办人、预留预算 | 合同生效、拨付任务钱包，期限从此时起算 | 主体失效释放预留，不生成半成品合同 |
| 一批交易 | 1 | 一次钱货交换；生成账单 | 技能经验；结束市场占用 | 不撤销已成交账单 |
| 任务交付 | 1 | 预留交付资源、记录报告地点 | 转交、质量、期限、奖励 | 发令主体消失转合法清算 |
| 短工 | 1 | 无押金 | 个人收入80钱、疲劳+8 | 受伤严重也有低强度版本，收入40 |
| 普通休息 | 1 | 支付已展示费用 | 体力+35、疲劳−30 | 可在半日后停止 |
| 修业 | 2—6 | 支付本课程费用 | 每半日经验，最后检查卡片资格 | 未开始半日退款；已提供教学不退 |
| 城际旅行 | 路线计算 | 首段路线、运力和同伴合法性校验 | 每半日行程和费用；最终到达 | 可于边界转向或等待 |
| 野战一轮 | 1 | 冻结参战单位与供给清单 | 本轮损失、任务、世界推进 | 轮内不随意退出；可保存于轮间 |
| 个人战 | 0额外 | 从原行动接管局部交互 | 胜负返回原行动 | 依战斗目标撤离，不重复收费 |

“短工80”不是所有NPC无限被动收入，只有占用人物劳动半日的实际服务；世界经济中记作民间服务收入来源。主要用于恢复基本行动能力，不用复杂市民资产数据库来证明每个铜钱流向。

## 2.6 路网数据与行程

据点定义`id, type, facility_ids, owner_org, map_xy, market_id, garrison_id`。路段定义`id, from, to, base_steps, modes, risk_bp, capacity_limit, blocked_reason, known_at`。全部逻辑路径使用节点和有向边，双向路显式提供反向通行条件。

P1逻辑拓扑采用以下12节点与18条双向连线，**这是功能测试拓扑，不是已审校的190年历史地理名单**。C01—C08为城市，V01/V02为乡里，F01为渡口，M01为营寨。正式地名、人物快照是内容制作交付，不在系统设计中编造历史事实。

| 边 | 标准步行半日数 | 用途 |
|---|---:|---|
| C01—C02 | 2 | 常用商道 |
| C02—C03 | 2 | 城际主路 |
| C03—C04 | 3 | 长途路段 |
| C01—V01 | 1 | 新手恢复地点 |
| V01—C03 | 4 | 主路受阻的替代路径 |
| C02—M01 | 1 | 官军任务 |
| M01—C04 | 3 | 较短但高风险路径 |
| C04—F01 | 2 | 水陆衔接 |
| F01—C05 | 2 | 渡运费用节点 |
| C05—C06 | 2 | 交易循环 |
| C06—C07 | 3 | 区域远行 |
| C07—C08 | 2 | 城际主路 |
| C08—C05 | 4 | 第二商旅环 |
| C06—V02 | 1 | 地方支线 |
| V02—C08 | 3 | 备用道路 |
| C03—C05 | 6 | 不经过渡口的陆路 |
| C04—C07 | 6 | 战争改道 |
| C01—C08 | 8 | 跨区域长路 |

路线用Dijkstra求“当前已知的最短时耗”；另提供低风险候选，计算权重`time + floor(risk_bp/500)`，仅作选择建议，不伪装真实概率最优。相同权重按路段ID字典序固定。允许玩家手选途经点。

旅行进度使用整数`progress_points`。道路长度`base_steps×100`；步行每半日100点、轻装骑乘150点、车队100点；雨天乘80%，运输熟练按第03章增益，最终至少1点。没有“半个tick到达并多做一件事”，到达在边界发生，溢出进度不跨下一条边。距离与速度修正是平衡参数。

同伴共享队伍位置，队伍速度取最慢的成员/运输方式；轻骑不能一边跑得快一边让步行货车瞬移跟随。载重按真实携带及任务货物计算。超载时禁止启程，提供分批、租车、存仓；途中运力损失则暂停，允许存放、托运或明确放弃货物。

每半日基本行旅费：个人8钱，车队附加4钱，护卫每人6钱。道路额外费用只在进入指定边时收一次，路段实例记录。费用只能使用合同允许的钱包。余额不足时不负债穿越；在边界触发“滞留”：就地求助送回最近已过据点，耗2半日、货物最多损失非任务个人货物10%，无个人货物则无货损。返回不瞬移免费重置，可在该据点做短工。

风险在进入每个路段时抽一次`event`随机流，保存`encounter_resolved`；停留与读档不重抽同一段。普通/危险道路基线300/1200基点；护卫与最新情报最多减少500基点，最低100基点。风险是遭遇概率，不直接等于死亡概率。选择绕行使用真实替代路线，无替代路才等待或返回。

人物位置采用互斥联合类型：`Settlement(id, place_id)`、`OnRoute(edge_id, progress, origin)`、`Battle(id)`、`Captive(holder, settlement)`、`Dead(last_place)`。不同时存两个可独立修改的“当前位置”。地图标记由此派生。

## 2.7 人物消息与访问

玩家知识条目保存`subject_id, last_known_place, observed_tick, source, confidence`。已知消息不会每次开图更新为真实世界。亲自见到、可靠报告、旅人传闻分别标为确认/报告/传闻；过期仍展示日期，不直接删除。

宅邸访问预览免费告诉玩家公开可知的可用性：在家、受命在外、未知。实际打听消耗1半日，获得合法消息并可能建立联系。人物被占用时不能双重开始师承；可约下一个可用时段，超过约期显示原因，不无声消失。

## 2.8 规则契约与错误

| 契约 | 输入 | 输出 | 主要错误 |
|---|---|---|---|
| 预览行动 | actor_id、kind、参数、当前revision | 可行性、时间、成本、原因 | 未知主体、不可达、权限不足 |
| 提交行动 | draft、预览版本、request_id | ActionInstance、起始结果 | 版本过时、人物占用、资源不足 |
| 推进半日 | 当前WorldState、驱动原因 | 新状态、结果、通知 | 重入、内部不变量失败 |
| 暂停/取消 | action_id、具体选择 | 已消耗与释放资源 | 不可取消阶段、实例已结束 |
| 查看路线 | 起终点、模式、知识 | 路线候选及消息时间 | 无已知可达路线 |

开发时具名类、函数和方法都要写明职责、输入输出和重要副作用；不能以“函数名很清楚”替代维护说明。这里只规定可观察契约，不为凑详细程度编造数百个内部函数。

## 2.9 本模块验收

T01：阅读20个面板，tick、revision、随机状态不变。T02：连续旅行5半日，恰结算5次时钟，跨日消费次数正确。T03：截止11、交付完成11，成功；完成12按逾期规则。T04：路上返回不清零原耗时和费用。T05：加载Committed交易不再扣款。T06：同一人物已在行军，不能同时拜师。T07：道路遇险读档不重抽。T08：野战一轮恰为1半日，个人战10轮不额外变成5天。T09：NPC新任务最早下一半日有进度。T10：12节点全连通且任一主商道路段受阻仍有可解释的替代/等待路线。

## 2.10 v0.2交互与时钟衔接

按照11，查询面板仍为纯查询；MoveLocal是可改变位置/revision的零时长命令，不能混为一谈。一般指路和交易问候并入具体行动，不每句扣半日。短工、买卖、交付由当前场景合法对象提供；已租房、自宅和野外等自主行动按本人的处境校验。确认短行动后自动结算其正常半日与反馈，不再要求每次额外点击“推进半日”；长行动和真实中断保留停止点。原子结算与保存边界不变。

## 2.11 2026-10-01补充：有限自动推进与生活时间预算

本节至2.15是承接既有架构的目标合同，尚未实现或验收。目的是减少重复确认，让玩家有时间访友、修业和生活；不改为离线挂机，不冻结远方世界，也不为了制造紧迫感不断生成必须处理的新危机。NPC计划和调度归06，人物已知经历归03，委任权力与预算归04；本章只定义它们共用的时间与行动边界。

**三个不同的“自动”必须分开。** 跳过对白/动画只改变表现；自动办理调用已获允许的正常领域命令；自动推进连续调用同一个世界半日。三者都不直接设定完成日期、人物位置或最终收益。小游戏自动使用03§3.6的人物正常基线，不再乘额外效率或奖励惩罚；同人物同条件的手动成长收益仍最多为正常值120%。基础生计、正常成长和已具备资格的职业路径不能因选择自动而失去入口。

| 合同 | 必需内容 | 边界 |
|---|---|---|
| 自动执行范围 | 实际行动/计划ID、人物、允许的动作种类、目标、办理来源及允许的参数范围 | “继续本次课程”不等于自动接受新课程、出征、替换教师或替玩家作关系决定 |
| 时间预算 | 开始tick、最多追加半日数或最晚停止tick、当前已用半日、已知承诺的最晚可行动点 | 开始前按预计完成时间提示冲突；实际时间预算到达即停，不能把预算当作暂停世界的保障 |
| 资源预算 | 原有钱包/库存及产权、累计支出上限、最低保留量、允许的已报价费用变化 | 不建立自动化专用的第二份钱粮；临时提高价格或改用公款超出边界时停止重问 |
| 停止条件 | 完成、玩家停止、需要决定、实际阻断、预算用尽、有效窗口关闭 | “遇普通升级就弹窗”不是默认停止条件；清单不允许屏蔽无法合法继续的阻断 |
| 可恢复进度 | 当前步骤、所属动作、上次稳定tick、剩余预算、停止原因和待决通知引用 | 读档先恢复事实并停住驱动；继续前再验人物、地点、资格和费用 |

应用层统一协调自动推进，UI提供开始/停止与显示；不继续为赶路、休整、修业各复制一套截止和消息判断。每次调度最多提交一个可验证的稳定半日，再检查停止条件，允许渲染、保存与输入处理；帧率仅影响提交请求的速度，不能改变每半日结果或导致迟来回调多走一步。正常阅读、查看手记和作选择不会自行经过游戏时间；打开决策或保存入口先停止后续自动请求，正在提交的事务必须在稳定边界完成。

城内熟访可把一串已知公开通路合为一个导航意向，仍逐段检查通路、门禁、在场和新阻断；进入场所是正式MoveLocal。城际“熟路快行”只压缩表现与重复确认，使用真实行程、速度、同行者、载重、逐半日费用和同一遭遇随机状态；不得省路、瞬移、免遭遇或把未知路线当成已知。到达后不自动越过新的会面、受领或交易确认。

## 2.12 长行动的分段履约、暂停、取消与恢复

沿用2.3的生命周期，由注册的行动模块给出`prepare/start/step/finish/cancel/resume`，应用层只协调，UI不写入进度。每种长行动必须声明其合法稳定边界、可中断性、占用释放规则、资源预留、逐段效果和终结效果；不把旅行、学习、制造和战斗强行套成同一种退款逻辑。

- 准备/预览不占用、不扣费、不消耗随机；开始时冻结已接受条款及实际预留，记录起始效果唯一键
- `step`以行动ID与分段序号/结算tick去重，只结算实际完成的一段；累计进度、钱粮、疲劳、经验和产物的领域记录是权威，不从动画播放次数推算
- 暂停后保留已完成部分和原行动身份；暂停是否继续占用由类型声明。修业可释放师徒以便各自行动，恢复必须重新取得双方占用；在途停步仍受真实道路位置与行旅约束，不能因此同时在店内办理事务
- 暂停记录不等于永久预约：释放教师后，他可接受其他合法安排；恢复时失去资格、地点、教师可用性或有效窗口，应明确等待、改约或结束，不悄悄换教师或强拉回来
- 取消释放仍由本行动持有的预留，不返还已经走过的日期、吃掉的粮食、已提供的教学或已消耗材料；终态不得以同一ID重启。不可中断的战术轮先结束本轮，不能通过关闭面板取消已结算伤亡
- 修业逐半日提供学习与对应疲劳，完成时只补尚未执行的终结检查/卡片资格。未提供部分按已接受条款退款；该部分款项在同一钱包账本中保留退款预留，不让收款人先花掉后再凭空退款。取消、退款与成长均有唯一结算记录
- 完成时已经存在的硬阻断优先阻止不合法效果；若阻断是在本半日世界结算中形成，仍保留本轮真实经过的世界时间及其他合法结算。开始前预览就失败的命令则零副作用，不为失败查询扣半日

课程应分清“已听完若干半日”和“最终取得资格”；中途结束可以保留前者，不凭空完成后者。已预先确定的题面、自动成绩及分段表现记录随行动保存；暂停、重开面板、换自动模式不能重抽题或重复领加成。对既有末尾一次结算的存档，必须由明确规则版本迁移解释旧行动，不能读档时按新分段规则补发历史经验或重复退款。

## 2.13 意向队列、预约与承诺的时间约束

`PlanIntent/PlanStep`表示准备做什么，`ActionInstance`表示已获准开始并实际履行的动作；两者不等同。约见、任务和委任的承诺分别由所属域保存，计划只保存`CommitmentRef`，不复制第二份截止或成功状态。承诺既可限制新动作，也可由合法动作成立，并非每个意向都会生成承诺。

1. 计划保存有序步骤、对象/来源、最早开始、所需已知前提、预期耗时和允许失败处理；尚未启动的步骤不锁人、不扣钱、不占库存。需要正式预约或物资保留时，必须调用对应域的接受/预留命令
2. 每步启动都走正常预览和提交，检查当前revision、真实到场、参与者占用、权限及剩余预算。先前“可行”的预测不是保证；不自动降低目标、挪用资产或接受新风险来维持连播
3. 取消未开始的意向无代价；已有动作、预留或承诺要各自清算。删除UI列表不能取消已接受托付；取消本次自动驱动也不等于毁约或终止正在进行的行动
4. 窗口分别声明允许开始和必须完成的时刻。若要求完成，必须用预计交付/课程完成时刻检查；到门口或发出拜帖不算已经履约。未接受的邀请到期只标错过，不能当作玩家失约
5. 新计划只在启动、已排定唤醒点、相关事实变化或当前步骤结束时重评。调度器使用到期队列和受影响人物/地点集合，不要求每半日扫描全地图、全部历史或重新给所有NPC制定人生计划；第一轮注册化先保持已有推进结果，再独立验证此调度优化

动作开始、暂停和恢复只改变本动作声明的占用；仍坚持一人同一时刻最多一个主要行动。预约可以限制可接受的未来安排，但不从预约成立起把人物锁死到会面当天。重复或冲突预约在接受时明确拒绝/改约，不能靠实际到场后随机淘汰一项。

## 2.14 消息到达、升级反馈与同tick中断顺序

世界事实成立、某人获知事实、UI显示通知是三个时刻。领域结果经03的`KnowledgeClaim/MemoryEntry`及已有消息来源规则形成玩家可知投影；`Notice`只引用该投影与结果，不负责发奖、改变关系或再次结算任务。远方未送达的消息不能抢先中断玩家，也不能通过手记、升级提示或“事务摘要”泄漏；本地实际危险和已发生的合法性阻断仍可要求停止，即使玩家尚不知道全部原因。

| 通知层级 | 默认处理 | 例子 |
|---|---|---|
| 必须决定/无法继续 | 完成本轮合法结算后停在稳定边界，下一半日前交还控制 | 实际路遇与战斗决策、费用/授权越界、人员失效、已送达且将影响当前承诺的紧急变更 |
| 重要但无需立即决定 | 短提示与可回看的手记条目，按已选择策略在活动结束时汇总 | 学会新本领、达成卡片资格、已知预约变更但尚有充分余量 |
| 日常结果 | 合并同源摘要，不逐条强弹 | 每半日修业进度、一般收成、普通商旅见闻、无新条件的熟客反馈 |

“升级”本身不要求暂停成长。若升级带来尚须玩家作出且会改变后续计划的不可逆分支，才按必须决定处理；未配置的新招可先保留待配置，不能因没关弹窗再次发奖。玩家可以更改显示偏好，但不能用关闭通知绕过强制战斗输入、越权或资源不足。

同一`t→t+1`内采用显式阶段依赖，迁移以现有固定seed结果为基准：先检查本轮实际参与者及阻断，再推进已开始动作并结算有效完成/到达/交付；同一截止tick的有效完成优先于未完成事项的到期清算。随后处理合法到达的消息、计划失效与机会更新，完整提交稳定世界；再由持久脏集合/到期集合形成计划提案，通过正常网关开始后续动作，并决定是否继续自动。新开启的动作最早在下一半日取得进度；新获知的消息不能在同一半日沿任意多人链无限传播。同行动完成和同tick外部变化有冲突时，由声明的阶段和稳定ID决定，不能由UI回调或模块扫描顺序决定。

已知预约的提醒可由其既有窗口产生，无须等待新的外部消息；提醒须留出当前合法路线及办理耗时，并注明估计与未知条件。世界中新发生而尚未送达的变更，不得冒充早已知情的期限提醒。通知确认只处理展示/待决输入；重复显示和读档不能让已经到期的承诺复活，也不能把到期事实再次处罚一遍。

## 2.15 持久化与可验证情景

保存当前意向及游标、动作阶段、逐段结算键、剩余预算、所属域的承诺/预约引用、预留和清算记录、已知消息及去重键。读取先核对动作模块版本、内容引用和占用，恢复最近稳定事实；默认不因打开存档就恢复自动执行，不根据现实离线时长补推进。可重建的到期索引由权威记录确定性重建；如保存索引，只作为可丢弃缓存，不得改变顺序或丢失到期项。

以下新增情景补充T01—T10与ARCH08/09/12，均须待程序实现后以同seed手动/自动、保存重启及第二配置举证：

- 连续赶路5半日，与逐次确认路线的日期、费用、位置、同行者和遭遇结果一致；第三半日真实封路即停，不直接到终点，迟来回调不再推进
- 六半日课程在第二半日暂停，双方可正常释放/重新取得占用；取消只退未提供部分，已有成长不消失也不重复；教师离岗后恢复给出改约，不生成替身
- 当前动作恰在截止11完成则成功；同tick尚未满足者按合同清算；只在11抵达、12才完成交付不能被自动队列算作按期
- 远方变更在tick10成立、tick13才送达：10至12手记和自动停止均不泄漏，13展示可知原因并在必要时停止；已知约期的预先提醒仍可在此前出现
- 连续修业发生普通升级时得到可回看反馈而不逐条拦截；需选分支、缺粮或待战斗命令时暂停，关闭普通通知不能越过这些边界
- 保存于已缴费、已完成一段、已暂停、已到期、待确认通知各边界；恢复不重扣、不补发、不重抽、无占用遗留；删去计划步骤不能抹掉已经接受的承诺
- 自动使用正常基线，与同人物同条件手动优秀成长比不超过1.2；允许整条非战争生活/职业链使用自动，仍保留真实时间、材料、学习和任职资格
