# 青川与松门 1.2.0

正式后继包 `hanmo.local_society@1.2.0`，由 `content/packs/selections/local-society-1.2.0.json` 选择。1.1原目录和三个旧情景原记录保持；本代新增正常标题可选的“北驿当值 · 自愿军籍与返乡”。显式启用 `population_military_v1`，只有该新情景配置人口军籍来源。所有美术沿1.1原Git资源和原SHA复用，无新生成或替代图。

## 正常操作路线

程禾从青川庭院出发，持有县务组织职务的实际训练、动员和释放权限。先在“查看地方近况”安排一名自愿家户成员受训，经过四个真实半日成为受训预备人口。训练许可仅负责训练；独立的 `consent.city_service` 才声明本群体同意到青川接收营服役，最多同时四人。

青川接收营就在家户原所在地 `place.courtyard`，同属 `org.city`。原独立训练营和其四名固定士卒保持原来源，不能借其名册接收异地人口。到“军务与部曲”向现任县务经办人接受“青川输粮部将”任命，再到“预备与军籍”登记。本次实际登记一人、劳力一人，占一个半日；源单位开局没有士卒，采用 `population_source_id`，没有 `initial_soldiers:0` 或另一份虚构兵力。

受领“北驿送粮”，沿原编组页选择“青川志愿输粮部”。建议装28粮、40军钱；每名士卒一份训练矛同样从真实营库配给，编组另需一个半日。按军令出发，经过实际道路一半日抵达同组织北驿，交付四粮。请求返营，沿真实返程回青川；粮秣页办理原 `army_return`，再在官职页回报军令。这个供给军令不安排虚假战斗或脚本战损，若实际发生军事战斗仍只用原引擎和真实伤亡分类。

归营以后人口仍是现役。再到“预备与军籍”显式办理健康人员退籍，一个半日后回到原受训群体，家庭、训练资格和军籍来源史保留。只恢复可分配劳力，不自动重建原农田劳动分配。伤员、被俘、离队不能通过此按钮洗成健康预备人口。

## 明确的开发参数

以下均为 provisional，供正常出勤返程演示，并非最终平衡承诺：

- 军籍来源容量四人；登记初始训练20、疲劳0、士气70。四半日群体训练只证明资格，不被换算成军队训练数值。
- 家户工资每四半日按到期人数计算：受训/预备每人1钱、现役2钱、伤员2钱、被俘1钱、离队1钱。五份独立的原 `RecurringObligation` 都由 `wallet.city_service_wages` 实际支付给原 `wallet.city_households`，不创建士卒个人钱包。
- 工资公账初有400钱；接收营公库240军钱、160粮、8矛；北驿公库120军钱、80粮、2矛。北驿已有一名独立静态士卒及真实守备人物，均不算本次青川家户来源人口。
- 原青川县务工资账在本情景初有240钱、县公账600钱、民间粮仓120粮，均是显式情景初态。运行中不加款或补粮。
- 军令期限40半日，两条实际道路各一半日，无额外随机遇险。军令交付的四粮不免除行军与驻军现有口粮。
- 预备与离队沿宏观口粮义务；现役、伤员、被俘通过 `military_source_id` 绑定原军籍当前营地、军团或实际羁押方。军事绑定的静态payer/obligation为空，不能把原城市仓冒充外地军粮来源。

已产生工资欠额不会因登记、退籍或状态变化被删除。军事补给在前、宏观经济在后、登记退籍完工再后，身份变化只影响下一合法供给边界。
